# P23.13 designer proposal — Ink & Instrument

**Independent proposal · 2026-09-16 · superseded as design target.**

Current candidate: [Architectural Drawing + Local Instrument](./P23.13-final-design-specification-Designer-D.md), based on the owner-supplied synthesis. The linked atlas has been updated to that candidate; the prose below preserves the earlier independent proposal.

Companion: [interactive specimen atlas](./P23.13-ink-and-instrument-atlas-Designer-D.html).
The atlas is a design study using illustrative geometry, not compiler output or a functional
editor. This document governs where a specimen is simplified. Numeric thresholds below are
proposed starting values, not measured usability results.

Inputs: [brief](./P23.13-designer-brief.md), [design context](./P23-design-context.md),
[P23.12 contract](./P23.12-final-design-contract.md), and

## 1. Position

A museum creator should see rooms and openings before seeing controls. Use a continuous,
graphite-filled architectural band, ample uncolored room space, and restrained labels.
When someone edits, disclose a small drafting instrument around the affected geometry:
one active handle, one winning snap, and the dimensions relevant to that operation.

The distinctive choice is **a dark cut silhouette that survives selection**. Blue lives
outside the mass, so even an active plan remains legible architecture. Normal and near walls
use the same graphite mass; zoom never washes walls into a different apparent material.
Non-bounding walls remain solid physical walls, with a lighter body and a small paired
interior role mark. That mark reports room behavior, not material or structure.

The main alternatives considered were white wall bodies with heavy outlines and a fully
dark drafting surface. White bodies make close parallel outlines compete with window
symbols and object edges. A dark surface would require a second complete optical palette
without improving this slice's core task. Choose one paper system across all shell themes.

Adopt all three research challenges: separate physical band from drafting ink; automatic
semantic zoom; optional exact entry during drafting. Exact entry is a proposed interaction
extension requiring child-plan ratification, not a claim that the current app supports it.

## 3. Architecture, joints and openings

### Walls and role

Band edges must come from compiled geometry. Drafting ink can have a 1 px floor; physical
width cannot. At projected thickness below 2 px, retain exact band and add a centered 1 px
silhouette ink line. This is a readability mark, excluded from measurements, snapping and
hit truth. Two separate walls never merge semantically because their ink touches.

At valid L/T/X junctions, show compiled connected mass without redundant internal profiles
where the compiler supplies an unambiguous continuous outline. Never erase a discrepancy by
inventing a union, bevel, bridge or extension in SVG. If today's compiler exposes a seam,
retain it and record it for P23.15. The atlas's clean schematic joints are the desired visual
reading, not evidence that difficult mixed-thickness or tangent cases are solved.

Mixed thickness keeps actual shoulders; mixed height adds no invented overhead or cut-plane
classification. Free ends are closed square caps. Curves use exactly the same band/profile
and the shared evaluator, with no local curve approximation policy. Shared walls draw once.

Non-bounding walls have the same continuous dark outline and a lighter solid body. At normal
and near zoom add **two short longitudinal ink dashes inside the body**, centered in a safe
unoccupied span, 3 px long with 2 px separation. These are a single role mark, never a dashed
wall contour. Hide the mark when thickness <6 px or available uninterrupted span <20 px.
At far zoom the gray body is the cue; on hover/focus/selection append `Does not define room
boundary` to target context. Never label these “interior,” “nonstructural,” or “temporary.”

### Door and Window geometry

Let `w` be the hosted width and `t` the physical wall thickness. The void always occupies
exactly that authored interval, with jambs on its ends. Frame strokes follow the compiler's
opening presentation frame; curved hosts do not get straightened by the SVG consumer.

| Regime | Door | Window |
|---|---|---|
| Normal / near | Void + two jambs + one short threshold stroke centered along the host, length `min(0.35w, 8px)` | Void + two jambs + two parallel frame strokes at ±0.18t from the band center |
| Far, width ≥8 px | Same short threshold stroke; jambs simplified to 1 px | One continuous center frame stroke across the true interval |
| Width <8 px | Keep actual gap; 4 px open-notch cue displaced 5 px outside host | Keep actual gap; 4 px double-line cue displaced 5 px outside host |

Subpixel-opening cues are symbolic and must never widen the physical cut. Space cues along
the same stable host side; if they collide, suppress lower-priority cues, retain the actual
cut and reveal the selected kind in target context. At extreme overview, individual adjacent
openings cannot honestly all remain distinguishable; selection and zoom recover detail.

Two frame lines are the limit: no mullions, panes, sash, handles or glazing layers. Door has
no hinge, leaf, swing arc or side inference. The short threshold is a neutral type cue, not
a sill specification. Door recognition without swing is a usability hypothesis: test it with
creators rather than claiming the novel glyph is an established standard.

Rectangular, rounded and pointed profiles have the same resting Plan symbol because their
elevation silhouette cannot be inferred from the top view. Selected context says `Rounded
arch` or `Pointed arch` when authored. No invented arc on the floor. Min-width hosts and
near-end/near-junction/near-neighbor openings use true cuts; fit feedback is discussed in §7.

## 4. Rooms, labels and density

Normal full stack: name / reference / derived area. Example: `Gallery` / `R-7K3M` / `24.5 m²`.
Use the existing identity resolver and area source, not renderer-created names or area math.
Display area to one decimal; positive values rounding to zero read `<0.1 m²`. Display rounding
never changes precision or dimensional input. Name equal to reference is shown only once.

Names can occupy two lines, maximum 160 px. Area and references are never wrapped or shrunk.
Full identity means complete authored name and complete reference; area is supplementary.
Long selected names wrap in the selection readout, with bounded scroll for pathological
length, rather than forcing every room label to expand.

Proposed bounded placement: use up to five interior candidates provided by the presentation
model (preferred safe center, then four locally offset safe points). Reject any candidate
whose text bounds, plus 8 px, cross the Room boundary or core geometry; reserve 12 px around
handles and 24 px around active annotation. This is label placement, never Room inference.
Use canonical identity as a stable tie-breaker, never document order or reference text.

Preserve the accepted candidate during a gesture and small pan/zoom. Reconsider only on
geometry changes, an actual collision, or LOD transition. No optimization every pointermove.
A label may shift at most 12 px from its preferred anchor before suppressing a tier. Never
animate labels across rooms. Reappearance requires 8 px extra clearance and 150 ms after
zoom/gesture settles. Accessibility reduced-motion requires no animated placement at all.

Drop order: area → reference → whole resting label. For duplicate names, protect name +
reference as a pair: drop area, then suppress the entire pair if it cannot fit. Never leave
two ambiguous identical names with hidden references. No warning or forced renaming.

| Face condition | Rest | Selected / active |
|---|---|---|
| Large / medium | Full stack if safe | Same stack; faint fill plus boundary overlay |
| Small | Name, or duplicate name+reference pair | Full identity in local free space if possible |
| Tiny / no safe interior | No resting label | Full identity in fixed canvas selection readout |
| Dense adjacent rooms | Stable drop order; no leaders | Selected room wins; neighbors suppress |

Selected Room uses 5% blue interior tint plus 1.5 px boundary overlay outside the wall mass.
No wall handles appear solely because a Room is selected. Hovering a participating wall adds
its neutral contour and context `Bounds Gallery · …`; it does not select another entity.
The fixed canvas readout is a non-mutating fallback, inset 12 px from the viewport safe corner,
maximum 280 px or available viewport width. It is not a second Inspector or rename field.
It may overlap passive context, never active handles or core geometry; reserve a safe inset
for it if the viewport has no free drawing space. Narrow views reflow it above the drawing.

Collision priority: active control/selected identity → invalid marker + reason → winner snap
and precision → Room identity → Layout object context → passive Scene. If first two compete,
keep the active control at geometry and move the reason to the fixed readout. Dimensions may
move outward or enter the readout; no unresolvable pile of text. Compiler diagnostics keep
a 6 px marker at source; colliding reasons consolidate in one readout with count and existing
Inspector destination. Never hide invalid geometry itself.

## 5. Semantic zoom

Global scale `s` is CSS pixels per world meter, independent of device pixel ratio. Initial
classification: far `<24`, normal `24–79.99`, near `≥80`. Hysteresis: far→normal at 28,
normal→far at 20; normal→near at 88, near→normal at 72. On jumps, resolve directly to the
appropriate regime. During an edit, hold the active target's control set until completion.
Entity-specific projected-size rules still govern tiny features at any global scale.

| Entity | Far | Normal | Near |
|---|---|---|---|
| Wall | Exact band + silhouette ink floor | Band + profile + role cue where fit | Same; active baseline only |
| Door / Window | Simplified cue (§3) | Full neutral symbols | Same; selected controls |
| Room | Name only where safe; duplicate pair or none | Full stack with tier suppression | Same fixed text size |
| Junction | No passive nodes | Selected wall endpoints; active tool winner | Same contextual rule; no node cloud |
| Curve points | Selected only; cull passive controls below 6 px/m | Selected bend points; polygon only on focus/drag | Same; extra space is not permission for clutter |
| Dimensions | Active only or fixed readout | Selected/active set | Same; no permanent chains |
| Layout objects | Simplified footprint, 1 px minimum ink | Full geometric footprint | Selected allowed handles |
| Scene context | 15% secondary ink | 30% secondary ink | 30%, no extra detail |
| Grid | Major only if spacing ≥16 px | Major plus minor when minor spacing ≥12 px | 0.25 m minor when spacing ≥12 px |

Below 6 px/m no resting Room labels or Junction/curve control cloud. A selected/focused
control remains available through the fixed readout and keyboard navigation; focusing it
reveals its screen-size marker even at overview. Geometry never disappears because its
label or handle does. Grid visibility and snap step are independent; never silently change
0.25 m snapping when grid detail drops. Ruler intervals use readable 1/2/5 progressions with
labels at least 48 px apart; scale bar stays segmented, axes remain X/Z and meters.

## 6. State and control grammar

| State | Wall / Opening | Room / Layout object | Handles / feedback |
|---|---|---|---|
| Rest | Ink geometry, neutral symbol | Unfilled Room; light object footprint | None |
| Hover | Offset neutral hairline, no blue | Neutral contour; no fill | No new handles; target context on dwell/focus |
| Focus | Dark double ring with paper moat | Same ring around boundary or target | Focused handle ring survives every other state |
| Selected | Separated blue perimeter; retain ink | Room faint fill+boundary; object blue outline | Only owner-allowed controls |
| Direct edit | Proposed real band + ghost baseline | Proposed footprint/boundary | Active handle filled; local dimensions |
| Snap | Single shape at winner; short source accent | Same rule | Optional one guide + relation label |
| Valid draft | Real band at 70% opacity; solid profile | True candidate footprint | Blue endpoint and relevant dimensions |
| Invalid draft | Real proposal at 35%; broken 4/3 perimeter | Same broken contour | Octagonal stop mark with × + local reason |

Non-color identity: hover = single neutral contour; selection = separated double silhouette
with actionable handles; focus = enclosing double ring; valid draft = continuous proposal
with active endpoint; invalid = broken contour + ×; snap = relation-specific glyph + word.
Direct edit includes a faint baseline and dimension witnesses, distinguishing it from rest.

Precedence is **compositional**, not “top state replaces all”: geometry → role/symbol →
selection → proposal → source/guide → handles → winner/invalid marker → focus ring → text.
Invalid suppresses a success-colored snap assertion but can retain an explanatory source.
A selected wall under snap stays selected; only the winning marker claims the relation.

Hit precedence: captured gesture first; then focused/active control; then controls belonging
to the one selected entity; then Opening, Junction (when exposed), Wall, Layout object,
Room interior. Co-located selected Opening edge beats its host endpoint; selected curved Wall
control beats unrelated Opening hit; an unselected control is not a competing target.
Allow keyboard traversal of overlapping controls without spatially moving their geometry.
This ranking is a requirement to reconcile with the existing canonical hit system, not a
second SVG hit resolver. Arrange owner resolves Arrange hits; passive Scene never enters
Layout hit priority. Cross-owner emphasis uses neutral context only, never Layout handles.

| Control | Visible mark | Reveal / target |
|---|---|---|
| Junction / Wall endpoint | Filled 7 px diamond | Selected wall endpoints, selected Junction, or Wall-tool winner |
| Curve bend point | Hollow 8 px circle | Selected curve; active point fills blue |
| Opening width edge | 7 px square straddling jamb | Selected or editing Opening |
| Opening slide | Short paired grip across symbol center | Selected Opening; body drag remains same operation |
| Object resize | 7 px corner square | Only where owner already supports resize |
| Object rotation | 14 px ring with short radial tick | Only where owner supports rotation |

Pointer hit targets at least 24×24 px; coarse-pointer target 44×44 where space allows.
Overlap resolves by selected owner and focus, not increasing visible mark sizes indefinitely.
Selected curve shows bend circles only. Focus/drag adds a 1 px broken control polygon and
its true reference centerline. Baseline geometry appears only during edit at 20% ink; original
Opening is ghosted during slide to show displacement. No free Bézier tangent handles invented.

Bend discoverability: when a selected wall is hovered, target context says `Bend: ⌘-drag` on
macOS / `Bend: Alt-drag` elsewhere, plus `Add bend point here` as the existing menu path.
Do not add a floating mutation toolbar or a new straight/curved conversion button.

Keyboard requirement: canvas is one tab stop. Enter on a selected entity enters its control
group; arrow keys traverse controls in canonical endpoint/arc order; Enter activates a
numeric edit; Escape exits edit, then group. Tab leaves to the next existing surface.
A focused Junction opens X/Z, curve point X/Z, opening edge width, slide grip offset,
object corner its already-supported size and rotation its already-supported yaw. Use the
same canonical commands as Inspector/pointer. Merely moving focus never changes selection
or history. Readout announces name/reference, control role, current value and units.
P23.14 must reconcile shell focus handoff; this is a proposed Plan-local interaction contract.

## 7. Precision, previews and refusals

Dimensions are **working information**, never authored annotations. Use 0.75 px witnesses,
4 px slanted ticks and horizontal 11 px mono text on a small paper knockout. Offset from the
band by 18 px; reserve a second lane at 34 px when necessary. Choose the side with more
space once at gesture start; freeze it until end. Short spans push text outward, then to
readout; never scale text smaller. Display meters and degrees explicitly; actual precision
comes from the canonical value, not its formatted string.

| Context | Automatic while editing | Selected, idle |
|---|---|---|
| Straight Wall draw / endpoint reshape | Length, angle; adjacent affected span if essential | Length only; angle through focused precision |
| Curved Wall bend | Arc length + active point X/Z on focus | Arc length (label explicitly `arc`) |
| Rigid Wall move | ΔX / ΔZ; baseline | Length; no global coordinate field |
| Junction move | ΔX / ΔZ; X/Z when numeric editing | Coordinates on focused handle |
| Opening insert / slide | Width + canonical-start offset; nearest end/neighbor clearance | Width; offset on focus |
| Opening resize | Width + changing clearance | Width |
| Rect Room | Width + depth; candidate enclosure | Room area, no permanent dimension chain |
| Poly Room | Current segment length/angle; closure cue | Room stack |
| Layout object transform | Supported size/delta/yaw only | No automatic complete bounding box |

**Adopt optional type-to-enter** for straight Wall draw length/angle, rectangle width/depth,
Opening insertion width/offset and Opening slide/resize offset/width. Focused direct-edit
controls may edit existing numeric fields through the same canonical planner. No new curve
radius/tangent constraints. Passive measurements such as clearance and area are never inputs.

During active creation the first digit, minus or decimal starts entry in the primary value
(length, width or offset). Composition events and keys in other text fields never intercept.
Tab cycles the finite applicable field set; click on its underlined value is the pointer
alternative; keyboard-focused control + Enter is the discoverable alternative. Idle dimensions
remain passive unless explicitly focused. No global shortcut hijack while simply viewing.

Entry replaces the displayed value with a small input at the same location. Lengths default
to meters; `m`/`cm` suffixes accepted, angles degrees; no expressions or command language.
Explicit values outrank a conflicting snap: remove its winner marker and report `Exact value`.
In an active pointer drag, typing freezes the proposal, transfers to numeric editing, and
consumes the eventual pointer-up without committing; Enter submits once. For click-based
drawing Enter submits the current segment/insertion once; Wall tool continues from that end.
Escape in a field restores the pre-entry candidate; second Escape cancels the gesture. Tool
change cancels the whole proposal. Blur never silently commits. Invalid values stay editable
with a reason; no history or allocation. Numeric entry must pass the same release validation.

| Gesture | Preview composition / completion |
|---|---|
| Wall draw | Real band, compiled cap/join if available, active endpoint, length/angle, one snap. Candidate closure gives faint Room fill only when canonical candidate actually yields a face; otherwise say `Close at junction`, never promise a Room. |
| Rectangle / polygon | All candidate physical walls, last segment precision, derived face cue when valid. No invented fixed example dimensions. |
| Opening insert | Neutral host contour, true ghost cut, neutral Door/Window symbol, width/offset; candidate rejection where fit is already known. Host remains architecturally visible outside the cut. |
| Opening slide / resize | Original faint symbol; moving actual cut and jambs; width/offset/clearance witnesses; source highlight on blocked neighbor/end. |
| Junction / endpoint drag | All affected wall bands and openings; active diamond; deltas, optionally coordinates; no Room-owned vertices. |
| Rigid Wall move | Candidate band plus connected changes as canonically derived, original faint baseline, ΔX/ΔZ. |
| Subdivide / bend insert | Existing resolved click position gets one node preview. No visual reallocation of references; selection follows the existing command result. |
| Bend drag / removal / Curved toggle | Final candidate band primary; selected bend circles secondary; guides during manipulation. Inspector remains the toggle/remove command surface. |
| Object presets | Column-like or slab-like creation ghost may explain the preset. On commit it becomes the ordinary geometry footprint. |

Known invalid preconditions may be shown before commit; do not claim full validation before
the existing release validator runs. On release re-derive, then show the actual accepted or
refused candidate. A changed winner is updated, never left reporting stale pointermove truth.
A refused proposal remains broken with a reason for 1.2 s or until next deliberate action;
original geometry remains intact. Escape clears it immediately. Announce the refusal once
through the existing status channel. Cancel and successful commit clear all transient draft
scaffolding immediately; normal selected controls may remain after commit.

| Refusal class | Local language / source emphasis |
|---|---|
| Opening does not fit / overlap | `Opening does not fit here` / `Overlaps another opening`; mark nearest limiting jamb or host end |
| Unsupported topology / degree | `This junction cannot accept this connection`; mark canonical affected junction |
| Curve not render-safe | `This bend cannot be built`; mark refused curve/control; never claim a guessed radius limit |
| Degenerate geometry / invalid length | `Wall is too short` only if validator gives that reason; otherwise use its precise supplied reason |
| Unresolved host / click distance | `Choose a position on a wall`; omit unavailable command; no fictional candidate |
| Release differs from preview | Accepted: show release truth; refused: `Position cannot be used` plus validator's reason |
| Existing compiler diagnostic | Persistent 6 px diagnostic marker and Inspector issue; never style accepted baseline as an active valid draft |

Copy is illustrative: use canonical reason data, and never turn a generic rejection into an
invented diagnosis. No automatic repair or detached substitute geometry.

Snap glyphs: endpoint = square; midpoint = triangle; intersection = × inside circle;
perpendicular/orthogonal = right angle; Opening edge = bracket; grid = small cross.
Each gets a short relation label, a 2 px source accent if useful, and at most one guide.
These describe eligible canonical snap winners only. A missing snap family is not added by
this proposal; omit its glyph until the owner can actually honor that relation. Marker shape
may resemble a handle, but the handle is stationary and actionable while the winner has a
relation label and no independent hit target.

## 8. Objects, chrome and empty states

Generic cylinder and sphere show their compiled circular footprint; box shows its compiled
outline. Do not add a column cross, concrete hatch, level arrow, plinth name or structural cut
fill. Selected allowed handles use §6. No room ownership is inferred from spatial overlap.

Passive Scene uses no fill, thin outline, and 30% secondary ink at normal/near; 15% far;
10% during Wall/Opening authoring. Never hide architecture beneath it. No resting labels in
Layout. Cross-owner Navigator emphasis may temporarily raise its outline to 60% and show
one name in passive context; it remains non-hittable for Layout. Arrange uses its own owner
selection vocabulary and commands; this proposal supplies only footprint hierarchy there.

Keep existing rulers, scale, axis key and Grid toggle positions. Empty drawing reads:
**Start your plan**
“Draw connected walls with **Wall**, or start with **Rect Room** or **Poly Room**.”
Below: “Scroll to zoom · Middle-drag to pan.” Use exact toolbar labels. A small neutral
open-corner sketch is illustrative, not selectable; no fake `10.0 m × 8.0 m` promise.
One committed wall removes the first-run message. A sparse plan does not nag the creator to
close a Room. Broken imported geometry uses diagnostics, never the empty-state illustration.

## 9. Icons and accessibility

Icons are 20×20 with 1.5 px optical strokes and ≥2 px gaps; visible labels stay authoritative.
Atlas includes: Select pointer; thick-band Wall; band-shaped Bend; enclosed Rect/Poly Room
with two short label strokes; neutral Door gap/jambs/threshold; Window gap/two parallel lines;
Junction node and add-node plus; Column preset cut-circle; Platform/Plinth preset slab;
generic box/cylinder/sphere geometry; Snap magnet/target; Grid lattice. Preset icons may
explain creation, but are never reused to classify committed generic objects. Bend icon
belongs only beside existing commands, not a newly inserted toolbar tool.

The atlas provides a grayscale toggle and all seven shell surrounds: navy-blue,
salon-espresso, electric-plum, acid-moss, porcelain-atelier, synth-sunset,
velvet-kodachrome. Paper and semantic palette stay constant. The surrounding swatches are
illustrative; final integration must use actual shell tokens. At minimum review the darkest,
lightest and most saturated shell, then check all seven without changing Plan semantics.

Focus remains a dark ring separated by paper on poché, tint, selected edge and handles.
Invalid retains broken geometry, stop shape, × and language under grayscale or red/green
loss. Snap uses shape/text rather than green. Do not rely on opacity alone for interactive
states. Hover is supplementary; all context is available through selection/focus. Screen
reader summaries include control role, identity, value, snap relation and refusal once per
meaningful change, not each pointermove. Preserve native input editing keys and IME.

Validation targets for child plan: small actionable text 4.5:1, essential control outlines
3:1 against adjacent surfaces, keyboard path to every displayed actionable handle and
editable dimension, 200% text zoom, and coarse-pointer targeting. These are design acceptance
targets, not an accessibility certification. Decorative grid/passive context are exceptions
only because the task remains fully operable without them. P23.14 must raise status-hint
legibility and reconcile shell focus return; neither issue is solved by this artifact.
