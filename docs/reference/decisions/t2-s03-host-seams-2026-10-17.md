# T2.P01.S03 host-seam exception — 2026-10-17

**Owner decision.** Narrowly extends batch B's shared-file protocol so `T2.P01.S03` may add the three
additive host seams its editing surface needs. It reopens no authorization, changes no product scope
and grants no capability, gate or acceptance state.

**Context.** Batch B's protocol gave host core, route and shell modules to **T1 alone**, written when
both slices were expected to contribute only through S07's AM-5 points. Implementation proved that
three plan requirements had no seam at all: a press could not be offered to an adapter before the
route acquired `stage-pointer`; an instrument's candidate could not invalidate the surface's overlay
read; and closing a contributed task from the shell fired no adapter callback. Without those hooks
T2 could only offer typed entry, which the plan does not accept as its editing surface.

## What this authorizes

`T2.P01.S03` may edit the shared Stage host **only** for these additive interfaces:

1. **Pointer delegation** — `StagePointerIntent` and an optional binding
   `pointerIntent(intent, context): boolean`, consulted by the route before it acquires
   `stage-pointer` and only while a contributed task owns the surface.
2. **Surface invalidation** — `StageFacade.notifySurfaceChange()`, so an adapter that changes preview
   state can ask the shell to re-read `overlay()` without a document change.
3. **Task-close callback** — an optional binding `taskClosed()`, fired for Esc, task replacement and
   install-close through the existing `notifyTaskClosed()` path.

And the route call sites that pass the pointer phases (`down`/`move`/`up`/`cancel`, with `shift`) and
reuse the **single accepted viewport rect** for CSS coordinates.

Plus the contributed-task mirror recorded in the addendum below.

## Addendum 2026-10-18 — the route's contributed-task mirror

**Owner-approved narrow addition.** Acceptance review found that after an accepted install the
facade closes the contributed task, and a domain adapter may reopen its own persistent task, so the
host can no longer rely on its own invocation to know which task the instrument home should show. The
owner approved restoring that behaviour with one additive function in the spatial route,
`syncContributedTask()`, called wherever the route re-reads the facade's task (the adapter-registration
listener and the acceptance-change listener).

It is inside this exception because it adds no authority: it reads `session.taskLifecycle()`,
`stage.tasks()` and `instrumentForTask()` — all already public — and writes only the route's own
`contributedTaskId` mirror. `instrumentForTask()` carries the facade-side owner check, so probing the
contributed entries re-identifies the one live task and yields exactly the content the home renders.
A parked (inactive) task keeps whatever mirror it had. It creates no second selection, task, gesture
or acceptance authority, and no adapter can reach it.

This is the complete set of host edits the exception authorizes: the three interfaces above, their
route call sites, and this mirror. Everything under "What it does not authorize" still stands.

## What it does not authorize

- A second selection authority, navigation gesture, acceptance coordinator, history, or renderer
  state store. The pointer claim is offered to the open task's binding and refused when another lease
  is held.
- A second editor host, a second F4 writer, Layout/Scene source mutation from a route, or any change
  to `apps/api/**`, migrations or the Save protocol.
- Rendering `graphics()`, a new overlay system, or a 3D candidate mesh. The candidate is presented
  through the existing overlay surface under **this** exception; the later
  [renderer exception](./t2-s03-renderer-exception-2026-10-17.md) separately authorizes the minimum
  ghost mesh and the drawn-geometry support test.
- Any capability, gate, acceptance, readiness, merge or closeout record.

## Boundaries carried forward

- T1 remains the only writer of the Save mount, the Card-name contribution and the Layout proposal
  lease. T2 must not alter those behaviours.
- Both slices now modify `stage/stage-facade.ts` and the spatial route. The merge protocol's
  "second merger resolves" rule applies; the combined tree was verified before either merge
  (check 0, fast 1894/1894, arch 163/163), so the additions compose.
- A press is refused, never stolen, when another gesture owns the lease; a delayed pointer-up after a
  replacement epoch must be inert.
- Mesh-versus-floor evidence and browser journeys remain acceptance obligations, not something this
  exception satisfies; the renderer exception above supplies only the minimum seam for the former.
