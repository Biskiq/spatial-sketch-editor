## Strong convergence

All four independently land around same core architecture:

| Area          | Real convergence                                                                                                        |

| Rest state    | Calm architectural drawing, not topology/debug mesh                                                                     |
| Interaction   | Editing scaffold appear only when user show intent                                                                      |
| Rooms         | Mostly negative space; restrained identity                                                                              |
| Openings      | True cuts in Wall; Door/Window visually distinct without invented swing                                                 |
| Selection     | Accent should explain interaction, not replace architectural geometry                                                   |
| Snapping      | One winning relation, not cloud of candidates                                                                           |
| Dimensions    | Temporary working information, not permanent annotation system                                                          |
| Precision     | Type-to-enter belongs locally in drafting gesture                                                                       |
| Invalid state | Candidate must clearly differ from committed geometry                                                                   |
| Ownership     | LayoutObjects subordinate to architecture; Scene passive                                                                |
| Presets       | Creation icon may communicate Column/Platform/Plinth intent, but committed generic geometry must not gain fake BIM role |
| Theme         | Plan drawing semantics should not change with shell theme                                                               |

This convergence meaningful. Four proposals reach same basic product truth from different visual treatments.

### Agreement caused mostly by brief/locked architecture

Some agreement less interesting because brief already force it:

* no Door swing/handing;
* no renderer-owned topology;
* canonical identities;
* one geometry/compiler truth;
* generic committed objects;
* no P23.14 shell overhaul;
* no visitor contamination;
* Scene/Layout ownership separation.

Those still correct. But they should not count as four independent votes.

## Suspicious shared assumptions

Here me think all four inherit ideas without challenging enough.

First: **three semantic-zoom modes**. Everyone reaches Far / Normal / Near. Useful mental model, but actual product should not behave as three CSS themes. Different objects cross readability boundaries at different projected sizes.

Second: **Room label always fundamentally belongs inside Room**. Mostly yes, but tiny/dense Rooms eventually prove this assumption false. Selection identity sometimes needs a secondary readout.

Third: **passive Scene = dashed line**. This may be useful, but dash already has architectural meaning for hidden/overhead geometry. Should be conscious product convention, not automatic choice.

Fourth: **architectural credibility comes from adding recognizable drafting marks.** Dangerous. More marks do not mean more architectural. Often opposite.

Fifth: **icons are miniature drawings of canvas objects.** Good starting grammar, but premium tool icons need optical design, not literal miniaturization.

# 4. Reject list

These should die before final contract.

1. **Invented physical opening construction.** No fixed 50 mm jamb, 40 mm glazing spacing, invented sill, frame profile, Door leaf, swing, or arch-on-floor. Symbolic marks must stay symbolic.

2. **Renderer-side join repair.** No little SVG cover patches, fake unions, bridge fills, invented bevels, or cosmetic topology corrections. If canonical compiled geometry has seam, expose truth and fix geometry owner.

3. **Wall-height step lines in Plan just because heights differ.** Elevation fact does not automatically create plan-cut mark.

4. **Blue replacing architectural Wall ink.** Selection should surround drawing, not become drawing.

5. **Hover-revealed actionable handle clouds.** Causes target instability and destroys resting calm.

6. **Exclusive eight-state machine.** Focus + selection + drag + snap + validity can coexist.

7. **Static entity-only hit ranking.** Intent and selected ownership matter more than class hierarchy.

8. **Near zoom means “show everything.”** More screen space does not justify Scene labels, every alcove label, every control, or permanent dimension chains.

9. **Three global LOD thresholds as full visibility policy.** Too crude.

10. **Selected Room suddenly using centroid.** Never abandon safe placement precisely when identity matters most.

11. **Fake `10 × 8 m` empty-state room.** It teaches arbitrary dimension as though meaningful.

12. **Empty state remaining until first Room exists.** First meaningful Wall means user already started.

13. **Passive Scene technical labels appearing merely because zoom is near.**

14. **Permanent dense red hatch for normal invalid dragging.** Too visually aggressive for common transient refusal.

15. **Literal tiny visible handle = hit target.** Visual mark and acquisition target must be separate.

16. **Using document order for annotation placement tie-breaking.** Use stable canonical identity.

17. **Renderer inventing curve-control meaning from point position/index.**

18. **Chord distance labeled Wall length on curves.** Curves show canonical arc length or no length.

19. **Isometric Platform/Plinth glyphs mixed casually into flat drafting icon system.**

20. **Dark Plan shipped as an incomplete sibling.** A half-good second palette lowers product quality rather than raises it.

# 5. Shared blind spots

This is where strongest final direction should go beyond all four.

## A. Semantic zoom should become a **salience system**, not three modes

Far / Normal / Near useful for documentation.

Product should instead answer per visual feature:

**Does this mark still communicate something at its current projected size?**

Examples:

* Wall physical band stays exact.
* Screen silhouette appears below useful band thickness.
* Window second line disappears before lines merge.
* Opening cue changes once authored width too narrow.
* Minor grid appears only when spacing readable.
* Room area drops before reference.
* Handle only appears if actionable and owned.
* Scene context decreases while authoring.

Global zoom regimes can choose broad policy. **Projected-size gates choose actual marks.**

This produces much smoother, more professional zooming.

## B. Need an explicit **visual attention budget**

All proposals solve collision mostly label by label.

Dense Plan needs higher-level rule:

**active task owns visual budget.**

When editing Opening, nearby architecture stays fully legible, but unrelated Room metadata and Scene context may quiet locally.

When editing Room identity, selected Room wins annotation space.

When snapping, only winning relation may claim guide/text.

This should happen **locally**, not by dimming whole canvas.

Think “instrument zone” around active work.

That gives far more calm than merely adding suppression priorities.

## C. Room label placement needs free-space reasoning, not anchor tweaking

Best system beyond all four:

1. canonical Room polygon;
2. subtract annotation obstacles / protected geometry regions;
3. find a few large safe free-space candidates;
4. choose stable candidate nearest semantic center;
5. keep it sticky through small pan/zoom;
6. drop information tiers before moving far;
7. fixed selected readout only when no honest local placement exists.

That solves concave Rooms, alcoves, objects, openings, long names, duplicates and active dimensions as one system.

## D. Wall representation needs an **ink budget at dense topology**

Nobody fully addresses what happen when many wall contours, opening jambs and joins collapse into same few pixels.

At overview, exact outer profiles cannot all survive.

Need rule:

**physical truth remains geometry; visual ink may simplify without claiming extra topology.**

This means selected screen silhouette / contour reduction can happen when multiple edges become subpixel, while hit/snap still use full compiled truth.

Not just “minimum stroke width.”

## E. Door/Window should be treated as **type recognition problem**

All four invent some Door symbol.

None actually prove creators recognize neutral Door without swing.

The correct next design question is not “which one looks most architectural?”

It is:

**Which smallest truthful cue gives reliable Door-vs-Window recognition across 8px, 20px and 100px widths?**

That needs recognition study, not taste debate.

## F. Iconography needs independent optical design

All four mostly derive icons literally from Plan marks.

Correct grammar, incomplete craft.

Final icon family should share:

* optical stroke weight;
* fill balance;
* corner vocabulary;
* negative-space size;
* action affordance;
* 20×20 silhouette distinctness.

Toolbar icon not need be geometrically exact mini-plan.

It need be instantly discriminable.

## G. “Architectural” should not become cosplay

Museum Editor not AutoCAD.

Borrow:

* cut hierarchy;
* poché;
* working dimensions;
* openings;
* line-weight discipline.

Do not borrow simply because “architectural plans do it”:

* hidden-line conventions without need;
* permanent annotation clutter;
* material hatch;
* arbitrary wall construction symbols;
* BIM roles product does not own.

That distinction should be explicit final principle.

# 6. Coherent synthesis

Me would call unified direction:

## **Architectural Drawing + Local Instrument**

Not combination of four aesthetics. One rule set.

### Resting Plan

Use one neutral light paper surface across shell themes. Slightly cool/off-white, not strong sepia.

Architecture dominates.

Boundary Walls use solid graphite poché plus crisp dark outer profile. Non-room-bounding Walls retain equally credible physical contour but lighter body. Do **not** add a permanent interior role dash; the owner-ratified treatment is lighter body plus contextual role disclosure.

Room interiors stay unfilled.

LayoutObjects use thin solid neutral contour plus faint fill.

Passive Scene uses a very-light continuous outline, no resting labels and no Layout hit authority.

No topology nodes. No dimensions. No guides. No handles.

### Wall geometry

Renderer consumes canonical compiled Wall geometry.

No renderer union tricks.

True world thickness always preserved.

Screen ink independent from world thickness.

When a band becomes too thin to read, add screen-space silhouette aid without changing hit/snap/measurement truth.

Curves use same geometry evaluator and same visual grammar as straight Walls.

No height-derived line unless cut-plane model actually produces one.

### Door / Window

Opening remains exact authored void.

Jamb edges simply terminate Wall cut.

Door gets one short **dashed symbolic type cue perpendicular to the host**, centered in the opening. It is a screen-space identity mark, not a threshold, leaf, hinge or swing indicator.

Window gets maximum two symbolic parallel frame marks when projected space supports them; collapse to one mark when it does not.

Very small openings retain true cut and may receive displaced symbolic cues.

Profile like rounded/pointed stays textual selection context only.

No swing or hinge semantics are authored in P23.13. Future Door mechanics may add truthful hinge/swing/open-state data for 3D animation and contextual Plan editing without changing the resting identity cue.

### Rooms

Resting hierarchy:

**Authored Name**
**Reference**
**Derived Area**

But tiers are conditional.

At overview, Name wins.

If duplicate names exist, Name + Reference become indivisible identity pair.

Area drops first.

Do not force uppercase.

Labels use screen-space safe-free-space placement and remain sticky.

No centroid override.

Selected Room receives subtle 5% wash plus Room-side boundary overlay.

If full identity cannot honestly fit locally, use one bounded temporary canvas readout.

### Semantic zoom

Use broad overview / reading / edit regimes only as policy.

Inside them, every feature obeys projected-size thresholds.

No “Near shows everything.”

Freeze active target control vocabulary through gesture even if zoom crosses threshold.

Use hysteresis around visibility transitions.

Initial optical studies can start near roughly `24 px/m` reading boundary and `80 px/m` precision boundary, but **those numbers stay tuning values until fixture testing**.

### Hover / selection / focus

Hover:

neutral offset contour only. No new handles.

Selection:

blue outer contour separated by thin paper moat. Original dark architectural edge survives.

Focus:

high-contrast dark focus ring/paper separation around actual focused target/control, layered over selection.

These layers coexist.

### Handles

Shape by DOF:

* topology endpoint/Junction → diamond;
* curve bend → hollow circle;
* Opening width → square at jamb;
* Opening slide → paired center grip;
* object resize → corner square;
* supported rotation → ring + radial tick.

Marks small.

Invisible pointer target ≥24px. Coarse pointer target toward 44px.

Handles only for selected owner or active-tool eligible target. No hover cloud.

### Snaps and guides

Show **one honored relation**.

Relation encoded by shape + short text.

At most:

* winner marker;
* source accent;
* one guide;
* relation label.

No candidate constellation.

Explicit typed value beats conflicting snap.

### Invalid state

Committed geometry never becomes “red invalid geometry.”

Keep original intact.

Proposal becomes quieter plus broken refusal contour.

Add stop/X marker and precise validator reason.

No full hatch by default.

Committed diagnostics remain separate persistent language.

### Dimensions

Working information only.

Use witness lines + ticks + paper knockout.

Lane chosen when gesture starts, then frozen.

Short spans push value outward rather than shrinking text.

Selected idle object gets only most useful primary measure.

Active edit gets relevant changing measures.

Curves use canonical arc length, explicitly identified.

### Exact entry

Adopt type-to-enter.

This is not optional decorative feature. It raises Plan from casual drag editor toward serious drafting tool.

Use one transient numeric editor attached to current working dimension.

Typing freezes pointer proposal.

Pointer-up during numeric entry does not commit.

Tab cycles applicable values.

Enter submits one canonical operation.

Escape restores candidate; second Escape cancels gesture.

Blur never commits.

Explicit value uses same planner/validator as pointer interaction.

No expression language or CAD command prompt.

Exact entry is available during gestures and from explicitly focused selected primary dimensions.

### Creation previews

Preview should look like actual committed geometry, not abstract blue line.

Wall draw shows true candidate band, active endpoint, dimension, one snap.

Room closure wash only appears after canonical candidate says a valid face results.

Opening preview shows actual cut and symbol.

Direct manipulation shows proposed final geometry plus faint original baseline.

Refusal keeps original geometry untouched.

### Objects / Scene

Authored LayoutObjects do **not disappear merely because view is far**. Simplify them when projected tiny, but preserve authored composition where meaningful.

Scene stays passive.

No default Scene labels in Layout at any zoom.

Cross-owner emphasis may temporarily raise one Scene object's prominence without giving it Layout ownership.

### Surface

P23.13 uses **one light Plan surface**: cool off-white `#F5F7F8` across shell themes.

Not because dark impossible.

Because a dark Plan is another complete drawing system with different poché, grid, selection, focus and context behavior.

If product later wants dark drafting, design it deliberately as sibling surface.

Do not let shell theme recolor Plan.

### Iconography

Build one optical 20×20 drafting family.

Canvas grammar inspires icon, but icon optimized for discrimination.

Door icon uses the same dashed perpendicular identity cue; Window remains parallel-line based.

Column/Platform/Plinth creation presets may communicate archetype.

Committed geometry still generic.

Do not reuse creation preset icon as evidence of durable semantic classification.

Recognition, density, accessibility and threshold tests remain QA/tuning work, but these six are no longer open product decisions.

# 8. Ratified direction

This is the direction carried into the final P23.13 specification:

1. **Plan rests as architectural drawing. Editing appears as local instrument.**
2. **Compiled geometry owns truth. Renderer never visually repairs topology.**
3. **World-space physical band and screen-space drafting ink are separate systems.**
4. **Boundary Wall = graphite mass; non-bounding Wall = lighter mass with same credible physical contour.**
5. **No invented height, jamb, frame, swing, handing, material or BIM semantics.**
6. **Door/Window marks are symbolic type cues around true authored cuts: Door = dashed perpendicular cue; Window = parallel frame strokes.**
7. **Room interior remains negative space; Name is primary, Reference disambiguates, Area is first to suppress.**
8. **Duplicate Room names preserve Name + Reference as one identity pair.**
9. **Room labels use stable free-space placement, not centroid placement.**
10. **Semantic zoom = broad regime + per-feature projected-size gates + hysteresis.**
11. **Near zoom reveals precision, not clutter.**
12. **Hover never exposes handle cloud.**
13. **Selection surrounds architecture; it does not recolor away architecture.**
14. **Focus, selection, proposal, snap and validity compose rather than replace each other.**
15. **Hit authority follows captured gesture and selected owner before generic entity ranking.**
16. **Controls use distinct DOF shapes and larger invisible acquisition targets.**
17. **One winning snap only; at most one guide and one relation label.**
18. **Rejected proposal never mutates visual truth of committed geometry.**
19. **Working dimensions are temporary, spatially attached and stable during gesture.**
20. **Adopt type-to-enter with full pointer/commit/cancel lifecycle.**
21. **Creation preview predicts real committed geometry. Closure cue never promises Room before validation.**
22. **LayoutObjects stay authored and readable; passive Scene stays context-only and unlabeled at rest.**
23. **One canonical light Plan surface across shell themes for P23.13.**
24. **Icons form one optically designed drafting family, not collection of miniature diagrams.**
25. **Architectural precedent is vocabulary, not authority. Museum Editor should borrow only conventions that improve truthful authoring.**

That gives P23.13 one identity rather than four merged proposals: **quiet, truthful architectural drawing at rest; precise, local, composable instrument when editing.**

Owner ratification is complete. The final design specification now governs implementation-ready planning.
