# REGISTER — direction and interaction specification

**Proposal, unratified · 2026-09-22.** Established constraints are identified explicitly. Everything described as REGISTER behavior is a proposed P26 capability, including the mockup. Deferred means outside the proposed initial product increment, not quietly unsupported forever. This is not a schema or implementation plan.

## 1. The product idea

A creator should be able to stand a drawing up, make an exact change, and lay it down again without losing the object or their place. REGISTER treats orthographic editing as **a visit from Plan**. A section has a location in the building; an elevation belongs to a wall; Ceiling Focus looks upward from an explicit datum. None needs a drawing document or workspace browser.

The working rhythm is **locate → focus → shape → check → return**. Central Paper holds the active instrument. A quiet registration map in the Navigator preserves its relation to the plan. One object remains selected across the visit. Return to Plan restores the previous pan/zoom and active target; it does not undo work. A direct precision action may replace the current instrument, with one visible Back action and a persistent Return to Plan. No permanent tab stack.

This preserves PLATE's hierarchy: Project → Scene → Plan → Section/Elevation/Focus → tool → target. Camera never acquires these tools or a second motion system. The 3D tab remains a durable view: selecting it exits the instrument and restores the remembered 3D observer. “Resume section” is then a contextual return action, not a new peer tab or camera node.

**Why this direction:** a physically legible relationship to the plan makes temporary instruments trustworthy. A modal full-screen CAD view would give more paper but discard the user's location; a simultaneous split editor would sacrifice precision and introduce competing active surfaces. The map is read-only during editing and uses the same derivation; “Edit cut in Plan” is an explicit temporary return, not a second editor.

## 2. Entry, section volume and return

**Entry.** In Scene/Plan/Layout the Section tool lives in the existing Tool Tray. Click a start, click an end, then click the side to look toward. A directional arrow follows the third click; before committing the definition, both Enter and a small tray action “Open section” are available. Each click has a keyboard equivalent: tab between X/Z input pairs in the Inspector while the placement tool owns it, Enter accepts a point, Left/Right flips look side, Escape backs one placement step or cancels. No architecture history entry.

The line endpoints establish span; the cut itself extends only over that span. Default depth is **5.00 m**, a proposed predictable room-scale starting point, never unlimited. S2 uses 4.50 m: the cut is at x=4, North's east wall is x=8, and the East gallery begins x=9. A 0.5 m allowance beyond the east wall includes its thickness and stops before East. The placement preview displays the exact included footprint and excluded count. Default vertical crop is off. Fit has independent horizontal and vertical margins, minimum 32 screen px, without changing the plane or depth.

**Active host.** Plan/3D stay in the 34 px View Bar. Immediately below, a 34 px contextual Instrument strip says “← Return to Plan · Section A · Looking east”; a second 34 px row owns Depth, Cut only, Crop and Edit cut. This is one contextual host with disclosure for less-used facts, not another global toolbar. Inspector continues to describe the selected architectural entity. Section parameters never masquerade as an entity or displace an excluded selection.

**Range manipulation.** “Edit cut in Plan” restores Plan with this section's endpoints, direction arrow, depth edge and translucent finite range selected as view controls. Drag endpoints changes span; drag depth edge changes depth; click arrow flips direction about the same line. Temporary readouts become numeric editors via keyboard focus. The contextual host exposes “Resume section.” When not editing range, the map and Plan only show a quiet cut line and arrow. Discarding the instrument removes them. One recent definition is remembered for the session; pinning, naming collections and cross-session saved instruments are deferred.

**Cut only** is an explicit toggle alongside depth, preserving the last finite depth when toggled off. It suppresses projected streams while retaining intersected architecture and its semantic opening marks. It is not represented as a numeric zero or a broken field.

**Crop** opens two absolute-Y fields in the contextual host and activates top/bottom brackets on Paper. Lateral crop is the existing span, not an extra range. Pan/zoom never changes membership. Escape cancels the current range gesture; “Reset crop” removes the vertical bounds. A cropped selected feature has a reason even if part of its parent remains visible.

**Return.** Escape first cancels a proposal, then dismisses a transient field/popover, then returns from the instrument when no operation is active. The visible Return action always works, cancelling an uncommitted draft. It preserves selection, committed edits and the Plan viewport. If the remembered target was deleted it returns without that target; Undo can restore it. Changing domain cancels the draft, closes the instrument and retains appropriate canonical domain memory.

## 3. What the section says and what it lets you do

Cut material has a 2 px graphite silhouette and flat neutral poche. Near projected edges are 1 px full secondary ink; farther included edges are 1 px lighter ink with explicit “Projected” identification on hover/selection. Hidden edges are dashed, off by default. Symbols (opening identity mark, directional arrow) are semantic overlays, never extra geometry. There is no continuous distance fog: three discrete stream treatments remain stable while zooming. Outside membership has **no pixels, hits or snaps**, except a deliberate temporary Reveal state routed through that same membership computation.

S2 looks east. With north to screen-left, the section crosses North (6 m), the shared wall at the door void, and South (5 m). Poche exists at the exterior cuts and the shared lintel above head Y=2.25, **never inside the doorway**. Door head and sill are truthful vertical edits. Width runs perpendicular to this cut; there is no width handle here. The projected east window can be named and selected but redirects to its host elevation for precise editing; no ambiguous depth/host drag. The curved partition is projected where within range, at top Y=2.55. Room names sit quietly below the floor; rooms are not filled volumes.

Selecting cut material resolves its Wall id. Clicking the semantic doorway contour resolves the Opening id, even though there is no solid in the void. At coincident picks, repeat-click cycles a compact ordered candidate list (opening, wall, ceiling/platform as appropriate), showing kind and reference; it never invents a grouped “section object.” Scene artwork is fine passive context with “Scene object · edit in Arrange”; architectural pointer picking ignores it. The registration map indicates orientation and scope, not a competing selection.

## 4. Wall Elevation: precision tied to a source

The contextual action **Open elevation** is exposed in the Inspector for a Wall or Opening (the latter opens its host). A selected Room exposes **Interior elevations**, a transient boundary-wall chooser containing little oriented silhouettes and wall references. Shared walls occur in each room's chooser as the same id with a different interior side. Double-click is not required and does not replace existing selection behavior.

The instrument definition follows wall identity, chosen side and canonical extent on every rebuild. Initial span is the wall's full length; background depth is **0.30 m behind the chosen face**, with the host retained by the constrained-section policy. The contextual strip owns North/South face switching; changing face reverses screen direction but not canonical offset, ids or profile stations. Selection remains O-DOOR. A small start-end direction mark explains which side of the image corresponds to canonical start.

**Opening handles.** Left/right square grips change width while holding the opposite jamb; a center mark changes host offset. Bottom grip changes sill with head held fixed; top grip changes head with sill fixed. This makes head and sill actual architectural constraints, and computes height from their difference. Inspector exposes width, offset, sill and head as writers; height is a readout to avoid two numeric definitions of the same fact. Selecting “Move opening vertically” explicitly translates sill and head together, preserving height. Rounded/pointed profiles gain a spring-line grip for rise; rise changes keep head fixed. Rectangle has no rise grip. A dimension pill invokes the same edit session as the corresponding Inspector field, not a third durable numeric widget.

S1 door starts width 1.00, sill 0, head 2.10 above floor. The sequence may raise head to 2.30, then sill to 0.10 (height becomes 2.20); it never silently preserves a different constraint. World-Y readouts are 2.45 and 0.25. Window starts sill 1.10/head 2.30, width 1.80, current semicircular rise 0.90. Proposed rise 0.45 makes a shallower rounded arch, requiring a shared authored profile extension. No fake “already adjustable” claim.

**Wall profile.** Inspector owns Constant/Slope/Gable choice. Constant has one whole-top grip. Slope exposes two eave grips. Gable adds one ridge grip with station and height; ridge defaults to midpoint. Section only exposes a defining profile point if its station is actually represented; otherwise it redirects to the wall elevation. A section through a non-defining station may offer “Raise whole profile,” explicitly translating all heights together, never secretly adding a point. There is no arbitrary vertex insertion.

Gable ridge must remain strictly between endpoints and above both eaves; an eave collision remains a dashed refused proposal: “Ridge must sit between the eaves. Move it inward or choose Slope.” Changing form is an explicit, previewed conversion, not automatic collapse. Fit compares the complete opening top boundary against the wall top throughout its width, including thickness/junction requirements, not just the opening center. Failure names the obstructing interval.

**Curves.** No misleading flattened elevation. For a curved wall, elevation opens a tangent view at the selected opening center or, without an opening, the wall midpoint by canonical arc length. A station rail in the contextual host locates that tangent, and the map shows the tangent on the curve. This remains an ordinary planar constrained section; its image is foreshortened, and the rail reports the station it actually derived by canonical arc length rather than a fixed number. Vertical grips are valid at that station. Opening width/offset and profile station are exact Inspector arc-length fields; a station diamond moves along the map only after returning to Plan. For visual width work, “Locate jambs in Plan” returns to existing curve drafting. This is an intentional truthful representation, not a claim that unrolling arbitrary curved walls already exists. When a bend moves in Plan, Resume derives the tangent anew; it follows the opening's canonical location if one anchored the instrument. If a selected station falls beyond a shortened wall, the instrument asks for a new station and does not silently move it. A future developed-wall instrument would need a distinct metric mapping; it is deferred, not a second geometry compiler.

**Source loss and wrong orientation.** Delete the host from Navigator: normal canonical deletion validation runs; if accepted, Paper becomes “W-SHARED was deleted · Return to Plan,” and the contextual host says the instrument is empty. No stale face, active handles or ghost edit, and no second deletion-specific control: the Project Head’s global Undo restores the id and the dependent view (see §9). Select the east wall/window while shared-wall elevation is active: Inspector names the new canonical selection, Paper highlights its edge if represented, and says “Edge-on here · Open W-EAST elevation.” Depth alone cannot repair orientation; precision redirect replaces the instrument and preserves the return chain.

## 5. Ceilings are independent pieces of architecture

### Ownership and creation

**Established:** Layout-owned independent CeilingRegion is the selected P26 architecture; room ownership, Levels, roof assemblies and freeform meshes are excluded. **Proposed here:** a creator authors an overhead surface with footprint, underside profile and thickness, plus an explicit relationship to existing closure. The primary numeric surface is the **underside**, the surface a person sees; thickness extends vertically upward. This bounded extrusion rule is proposed, not an assumed roof-normal thickness system.

Scene/Plan/Layout → Ceiling tool offers **Use room outline** or **Draw region**. Use room outline copies a snapshot of a room boundary into a draft. Clicking adjacent rooms while this creation tool is active unions the seed footprint with a preview across shared walls; these are tool operands, not a new general-purpose multiselection. “2 rooms · one region” is explicit. Disconnected selections produce separate regions with separate ids in one accepted creation transaction, with the count shown before commit. A Room never becomes a transform parent or a live constraint. Later Room changes leave the authored footprint where it was; the relation is “overlaps now,” not “owned by.”

Draw region supports room-free polygons, partial rooms and concave footprints. Existing curved boundaries may seed a curve-preserving footprint; samples are compiled from canonical curves, not persisted as dense edge soup. Self-intersection, an unclosed loop or zero area cannot commit. Backspace removes the last point; Escape cancels. For curved boundary topology beyond the supported footprint validator, the first increment must explain the unsupported shape rather than flatten it invisibly. A later increment can add explicit holes/disconnected contour editing without introducing arbitrary mesh modeling.

Before commit the draft shows Flat/Shed/Gable, underside Y, thickness, and **Closure / Suspended**. The first room-seeded suggestion is Closure, matching the action “make this the ceiling”; room-free drawing asks for the relationship explicitly and proposes Suspended. Suggestions are visible and changeable. Profile defaults and all seed operations are previews until one Create transaction. At differing room heights, a seed never guesses a blended surface: it initially suggests the higher generated underside and lists both replaced surfaces; the author chooses the profile before accepting.

### Existing derived closure is visible, and remains honest

Untouched rooms retain today's derived planes: S1 North Y=4.35, South Y=3.35. The gap above the shared wall to North's overhead is 1.00 m. No automatically invented vertical infill conceals it. In Ceiling Focus, this reads “Generated from boundary walls” and selection resolves the Room (read-only overhead properties + Create ceiling action), not a new ceiling id. In Section its edge has a small generated marker on hover/selection.

A **Closure** region replaces generated room ceiling **only over its own footprint**, clipped to each overlapping room for that suppression. The authored region itself may extend beyond rooms. Remaining uncovered strips retain the room's generated closure. That fallback stays at the maximum boundary-wall top (including proposed profile maxima), so a wall-profile change can still move it. The selected room's Inspector explains this dependency. No roof or guaranteed weather-tight enclosure is implied. Generated fragments cannot be dragged; Create ceiling uses their footprint to make authored truth.

A **Suspended** region leaves generated closure in place above it. It can float under a higher authored Closure too. In Plan, footprint edges distinguish selected ceiling from wall lines without filling whole rooms. Ceiling Focus shows the first overhead, with higher overlapping surfaces shown only as dashed context or in an overlap chooser. Section shows the actual air gap and both solids. 3D renders both as physical surfaces; temporary editor see-through is explicitly presentation-only.

For a partial closure stopping 1 m short of North's east wall, the remaining strip retains generated overhead at Y=4.35. The surface step is exposed, including any open vertical slot between different elevations. “1 m strip · generated overhead” appears in the overlap readout. The creator can extend the footprint, create another region, or intentionally keep it. Automatic fascia/infill is excluded because it would invent a roof/enclosure rule.

### Spanning, several regions and overlap

S5 spanning story: one Shed Closure spans North and South, full 8 × 11 m footprint, high southern edge Y=4.55, low northern edge Y=3.55, thickness 0.15. In a shed the high edge is what the brief calls the southern ridge; it is not a two-plane gable ridge. One id C-SPAN, one continuous slope across the shared wall. At the shared wall the underside is about Y=4.095; the wall top is Y=3.35, so a ~0.745 m gap remains. That gap is shown, not silently repaired. The northern exterior wall crosses the low ceiling; wall/ceiling embedding is displayed as a junction condition requiring inspection, not mistaken for a generated side wall.

Comparison: North only has C-FLAT and C-GABLE; South has no authored ceiling and retains Y=3.35 generated overhead. North's eastern 1 m strip retains Y=4.35 generated overhead. The two regions overlap horizontally by 0.50 m. Footprint overlap **by itself is legal**: two separated vertical solids stack, with clearance dimensions and an overlap chooser. “First above cut” is a viewing policy, never deletion of upper geometry.

If two authored ceiling solids intersect, REGISTER proposes a **joint decision** inside the candidate preview: “These surfaces intersect. Raise/lower one, reshape a footprint, or Trim one to the other.” It does not reject the concept of overlap or move geometry automatically. The author chooses which region retains material in the intersection. **Trim C-GABLE against C-FLAT** subtracts only intersecting solid from C-GABLE, preserves both authored footprints and ids, and records a directional authored relationship whose evaluated cut faces belong to C-GABLE. The overlap remains visible in Plan as original-footprint context; the compiled physical boundary is solid, not a phantom selectable face. The selected region's Inspector distinguishes authored extent from trimmed material. Exact coplanar duplicate faces require the same explicit choice; touching faces may meet with no joint operation. A region wholly removed by a trim is refused (“No material remains”), with edit/cancel actions.

This is the ambitious architecture seam: a bounded ceiling-to-ceiling joint operation on the canonical solids, **not** general Boolean tools or a cell complex. Acyclic directional dependencies are required; attempting B→A when A→B already exists produces “This joint would depend on itself,” with neither change committed. Moving/deleting the retaining region previews affected joints; accepted deletion releases those trims in the same transaction. If that creates invalid crossings, resolve them before accepting. Unresolved solid intersections are drafts, not silently accepted geometry; legitimate separated overlap is never blocked.

Walls may penetrate a ceiling volume without cutting holes in their own architecture. The canonical compiler must account for hidden interior contact faces consistently for rendering/derivation and attribute exposed faces to their sources; ceiling-wall penetration is distinct from ceiling-ceiling joint policy. A “Contact / wall passes through / gap” readout informs the author. It does not certify structural support. Persistent wall-to-ceiling attachment is deferred. Instead, set wall slope/gable eaves/ridge in elevation and snap to ceiling intersections. Snaps copy values once; changing the ceiling later never moves the wall secretly. Shapes outside the bounded wall-top vocabulary receive an explicit limitation.

### Ceiling profiles and Focus

Plan owns footprint and horizontal profile direction. Select Shed → draw a low-to-high axis on its footprint; select Gable → place/orient a ridge line inside the footprint. These are parametric references, not structural beams. Inspector owns their exact direction/station values. A ridge outside the footprint, invalid domain or non-positive thickness is refused. For a concave footprint the profile is evaluated over the whole region; disconnected ridge intersections are surface facts, not extra ridges to edit.

Section perpendicular to the slope/ridge exposes low edge, high edge or ridge heights, with underside/thickness clearly distinguished. An oblique section exposes truthful intersection height and whole-surface lift only, with “Open profile section” for defining eave/ridge edits. That action creates the same Section instrument aligned to the region's profile direction. Plan shows the profile arrow; it does not show every height dimension at rest.

Ceiling Focus is included in the first useful P26 product release. Select any authored ceiling → Focus ceiling; a room → Inspect overhead; or Ceiling tool → Focus overhead. It reuses Plan scope, explicit reflected kind, upward camera, reflected in-plane mirror, readable unmirrored text, and renderer-only ±2 mm offset with sign opposite Plan. The default cut is **1.60 m above current floor**, i.e. **world Y=1.75** in every canonical scenario. The contextual host displays both. On opening, this suggested value is resolved to an absolute cut; later floor changes do not silently follow it. “Reset to floor +1.60” is explicit. Looking up has a finite 5.00 m depth too, ending at Y=6.75 by default, and reason-coded exclusions.

The reflection is intentionally visible: matching asymmetric orientation diagrams show Plan east on the right and Focus east on the left; north stays up, E/W orientation labels and O-WINDOW text remain upright. This is the screen result of the upward-camera convention combined with the explicit in-plane mirror policy, not a freehand CSS flip of the entire UI. Pointer/snap mapping must invert the same transform as rendering. A handedness fixture with a door off-center and an east-window label is required in later reconciliation; a symmetric rectangle is not sufficient evidence.

Focus can select, cycle overlapping regions, lift the entire underside through an explicit numeric grip, edit thickness, and open the profile section. The numeric lift does not pretend that height is a horizontal screen displacement. Horizontal footprint changes always invoke **Edit footprint in Plan**, retaining selection and return intent. No reflected horizontal drag quietly reverses Plan's authority. A horizontal cut above a low suspended region excludes it as “below cut,” preserving selection and offering Reveal with the necessary temporary cut change.

## 6. Selection, Reveal and two kinds of reversal

The implementation coordinates several canonical domain slots; REGISTER adds no instrument-local object selection. Compact refs and optional names stay consistent in Navigator, Paper, Inspector and status. C-prefixed ceiling references are a proposed family extension. Cut fragments, opening contours, trimmed faces and mirrored projections all resolve their source. Search works over the canonical project even when the result is outside membership.

An excluded selection stays selected. Inspector header/body still show its entity and values. A view-status line says **“O-WINDOW · outside depth 2.00 m · Reveal”**; no fake handles are painted at the canvas edge. Partial exclusion is feature-specific: if crop minimum Y=1.00 removes the door sill Y=0.15 but not its head, the opening stays drawn and the sill field says “Sill below crop · Reveal.” Reasons may stack (outside depth and crop); list all limiting reasons.

**Reveal** is a temporary, source-specific inspection exception. It stores the previous instrument definition, extends the necessary finite range/crop just far enough for that source, and restricts the newly admitted space to that source (and minimal host context needed to understand its opening). Every other source retains baseline membership. This is evaluated by the single membership stage: drawing, hits, snaps and dimensions receive the same effective result. The revealed source uses a dashed perimeter/“Revealed” badge while remaining at its true projected coordinates. There is never an x-ray ghost that can be clicked but cannot snap. Background/fill occlusion policy follows the same explicit exception. Behind-view or no-meaningful-projection cases offer an appropriately derived elevation/flip preview instead of pretending depth alone fixes them.

Only one Reveal lease is active; revealing another source replaces it after restoring the baseline definition. “Restore view” closes the lease without touching the selected entity or architectural history. Return to Plan closes it too. Revealing O-N4 in S4 leaves column 4's other entities excluded: not an expansion to the entire wing. A host wall included for the opening is identified as passive host context, not an invitation to edit its excluded neighbors.

An excluded object's exact Inspector edit is allowed when canonical validation can decide it; its outside-view warning remains. After revealing the east window, the user may change sill in Inspector, or follow Open elevation for a truthful visual edit. The lease remembers the baseline Section when returning from that focused elevation.

**Undo** always addresses the existing chronological architecture/Scene history. One accepted handle drag, numeric session, profile conversion, ceiling creation or explicit joint decision is one Layout entry. Selection is restored through the canonical snapshot path. Range changes, entering/returning, Reveal and Restore view write zero Layout entries. Undo of a window sill leaves the current Reveal state unchanged; Restore view leaves the edited sill unchanged. The atlas provides separate buttons and readouts to demonstrate this distinction.

Temporary dimensions live outside the selected silhouette, 16 px from the nearest free side with 12 px lane spacing. They never sit inside the door void. If lanes collide, retain the active value, then its primary constraint, then move remaining dimensions to Inspector. Hover is a non-editable value and no handles; selection shows eligible grips, active drag adds the one accepted snap/guide. Zoom sheds dimensions, secondary edges, labels, then handles; silhouette survives. Keyboard selection can restore a selected target's accessible handles regardless of hover availability.

Typing a number while a grip is focused opens its temporary field; Tab cycles only that operation's defining values (sill → head; eaves → ridge station → ridge height), Enter validates/commits, Escape restores baseline. Inspector focus opens the same operation; while it owns a draft, Paper shows the draft but its competing grips are inactive. Blur to a different field inside the operation does not commit; leaving the operation commits only a valid draft, otherwise retains the error and offers Cancel. No global Undo is intercepted by a value scrub. Arrow increments use a metric step independent of validity-grid quirks; exact legal typed values must not be marked invalid merely because they are off the increment lattice (existing TD-2). Numeric controls must reconcile after external Undo, including unfocused displays (existing carried debt).

Invalid drag paints the candidate dashed in refusal ink and retains committed geometry beneath it; text names the reason. Pointer release on invalid cancels that candidate, with zero history. Invalid typed values remain in the focused field for correction; no auto-clamp and no geometry mutation. Snap shows only one eligible source and rejects excluded/passive references. No-op gestures write nothing.

3D exposes one coarse handle set on the selected architectural source through the existing host. Wall lift offsets all profile heights; ceiling lift offsets the entire underside; column top changes height with base fixed; platform top translates base/top together at fixed thickness. Exact Inspector controls and precision redirects remain available. No 3D arch-rise/jamb/profile-station gizmo. No new navigation evaluator. Editor see-through never changes visitor geometry.

S8 column is explicitly architecture: 0.40 × 0.40 footprint, base Y=0.15/top Y=3.35, height 3.20. Platform top Y=0.60 (rise 0.45), thickness 0.20, base Y=0.40; the air gap below is visible and legal, not snapped to the floor. It remains independently selectable where touching a wall. Artwork and its plinth are Scene context. Existing preset objects require explicit conversion/semantic adoption preserving identity where possible; no automatic migration by mesh shape.

Same-property batch editing is **not required by this direction's first release**. General marquee/room stretching is absent. A future bounded same-head or same-height command may extend canonical selection sets with all-or-nothing validation; it is not needed to make the current design complete.

## 8. Density, empty states and recovery

S4 uses a 3 × 4, 24 × 15 m wing with shared walls, alternating 3.0/4.2 m wall heights, roughly two doors/one window per room and one curved wall. A north–south cut at x=9 looks east with depth 6, spanning all rows. Column 2 is cut; column 3 projected; column 1 is behind; column 4 beyond depth: six included, six excluded. Registration map and source readouts agree. Repeated “Gallery” names retain R-N1/R-N2/R-M2/R-S2 refs; selecting a shared Wall displays its W-reference and both room relationships, not a room-local duplicate. Navigator filters may show all or in-view occurrences, with selected exclusion pinned even if filtered. “In view” is navigation filtering, not a second membership calculation.

When width tightens, drop contextual secondary readouts, collapse range fields under “Range,” then collapse low-frequency utilities. Return, kind, selected identity, active tool and Plan/3D remain. This is a P26 proposal for its own host, **not a ratification of PLATE's unresolved squeezed View Bar seam**. At short heights panels scroll; the return host stays pinned. Accessible named SVG grips, keyboard alternatives, 44 px coarse-pointer targets, non-hue stream/state cues and reduced motion are product requirements, not asserted verified by a static mockup.

## 10. Desired capability and progressive delivery

These are product horizons, **not child slices, schemas, schedule or implementation approval**.

**First useful release:** complete Plan → Section/Elevation/Focus → 3D/return loop; finite range/crop and Reveal; coherent identity/history; Constant/Slope/Gable wall tops; precise opening sill/head/width with truthful curve handling; independent Flat/Shed/Gable ceiling regions, room-free/spanning/partial footprints, Closure versus Suspended, separated overlaps, visible fallback closure; architectural column/platform vertical editing. Ceiling Focus belongs here because partial/stacked overhead needs an intelligible inspection surface.

**Full direction:** explicit ceiling joint trimming, curve-preserving footprint editing beyond simple seeds, refined overlap traversal, and bounded complex-region edits. These may arrive after the initial geometric vocabulary, but the authoring model and identity must reserve them. Before trimmed joints exist, an intersecting candidate says “This joint is not supported yet; separate the surfaces or edit the footprint.” That is a temporary delivery limitation, not a rule that ceilings cannot overlap. UI must not advertise Trim until it exists. Separated overlap, spanning and room-free regions are not deferred merely for ease.

**Deferred outside this direction:** persistent wall attachment, developed/unrolled curve view, general architectural multiselect/transforms, Levels, roof assemblies/fascia/drainage, arbitrary mesh profiles, sheet/documentation systems, staging/P24 and visitor interaction/P25. Optional pinned instrument records are later session/product work; no derived primitives ever persist.

## 11. Architectural consequences and questions to resolve

1. **Canonical authored vocabulary:** extend Layout validation/codec/migration for wall profiles, independently controlled arch rise, ceiling regions/closure relationship, and meaningful architectural vertical extents. Decide exact representations later. Current scalar/semicircular values must preserve appearance on read. Do not put any of these facts in Scene or room render metadata.
2. **Shared compiled solids:** current compiler/junction-aware mesh seams are real, but no generic orthographic solid derivation is established. Expose one renderer-neutral physical representation with source/host identity to shared cut/project/hidden derivation. Curves and openings compile once; Plan, 3D and visitor consume the same results. No consumer may secretly repair top/ceiling joins.
3. **Coverage/joints:** independently derive generated-ceiling suppression by Closure coverage; evaluate bounded acyclic trims without destructive identity merge; define contact tolerances, coplanar ownership, disconnected remnants and conservative failure. This is the largest unresolved geometry feasibility question. Validate concave curved multi-room footprints and partial masks before declaring overlap solved. Research compatibility is not a proof.
4. **Datum policy:** underside absolute Y and explicit floor-relative readouts; wall tops keep floor-relative authored meaning; a floor edit changes wall bases/tops but does not silently translate independently authored ceiling Y. Existing opening sill follows host base. Ceiling Focus absolute cut remains fixed until reset. This asymmetry must be ratified and tested deliberately.
5. **Membership and view mapping:** one baseline plus explicit source-specific Reveal lease, one reason result consumed by rendering/hit/snap/dimensions. Curved tangent metric mapping and reflected handedness need shared projection/inverse mapping, not ad-hoc screen calculations. Per-feature crop reasons refine source membership, never create alternate selection ids.
6. **Editor session:** contextual definition/return state, canonical selection exposure, numeric edit lease, cancellation and validation through existing history. Preserve Svelte runes and existing Threlte canvas/host boundaries. Ceiling refs extend the canonical ledger; generated closure targets Room only.
7. **Visitor isolation:** only authored model/compiled physical geometry belongs in visitor-safe packages. Instrument definitions, preview guides, Reveal exceptions, history and authoring controls remain editor-only. Public visitor and frozen museum receive no instrument imports. No camera node, path evaluator or motion interpolation is added.
8. **Responsiveness:** new work must use P23B's measured eventual constraints; no budget is invented here. The preview interaction needs stale-result protection and shared invalidation, not a private fast compiler.

Unresolved engineering questions: robustness of trimmed sloping solids and curve-preserving coverage; occlusion behavior for selective Reveal without implying false spatial adjacency; exact profile compatibility for non-semicircular rounded and pointed arches; identity migration for existing layout presets. These are explicit seams, not missing UX choices. Their later resolution can change progressive delivery; it should not silently replace the product vision with room-bound ceilings.
