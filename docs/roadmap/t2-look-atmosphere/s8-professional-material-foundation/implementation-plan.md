# T2.S8 · Professional material foundation

**Proposal for review.** Base `5d5f9858` includes the unified renderer cutover. The first deliverable is an opaque, metallic–roughness Finish that a creator can import, adjust, share, inspect under known light, save, and reuse in another project. A creator picking Walnut from the catalogue can still paint it in one action. The professional path earns its place when someone supplies their own wood grain, packed maps and physical tile dimensions and can reproduce the result on a second machine. ## What changes from the umbrella

Manual assignment still precedes recognition. Move packed-channel selection and gloss conversion into that first manual capability. Deferring them would hard-code “one file equals one property” into import, caching and delivery. Give new assets a neutral PBR base so a creator's plaster cannot accidentally inherit walnut roughness or a brass tint. Keep opacity, emission and fixture models out of the first family. A channel called *Shading* cannot stand for ambient occlusion, height and a baked lighting pass. Each requires a different evaluator. Earlier S8 control sketches are design inputs to the single UX phase.

**Portable identity.** A definition addresses each creator image by its byte digest inside the recipe. The project resource stores the recipe once plus the local bindings from those digests to verified texture resource IDs. Hash canonical recipe bytes, including the family/version, input digests, factors and transforms. Exclude display names, project IDs, transport URLs and derived thumbnails. Use a project resource ID derived from the recipe digest and a matching exact `resource:material` dependency-lock entry. Two recipe revisions can coexist. Verify the revision from the recipe and the local pins when admitting it. Catalogue IDs retain their frozen semantics and static byte paths.

**Reuse.** A private library item has its own logical identity, display metadata, immutable recipe revision and retained image pins. Saving a project Finish to the library resolves overrides into a self-contained definition, including the current literal value of a project palette follower. The transfer result reports this capture. The original keeps following its palette. Inserting vendors verified bytes, binds destination-local texture IDs, deduplicates the recipe by revision and creates a named project Finish. Removal of a library item or its source project cannot break an inserted Finish. Capture built-in inputs by their frozen catalogue IDs and digests. A later update requires an explicit rebind with impact review. This costs storage but lets a visitor play entirely from release-owned inputs. Extend the private, owner-scoped library pattern already used by My Objects. [Library precedent](../../../reference/components/assets.md#my-objects-form-library-scope)

**Resolution.** Resolve base → instance overrides → project palette → effective PBR inputs → S6 Treatment → descriptor and bindings for the target geometry. Only the final lowering knows Three/TSL. Strip appearance maps for Flat colour and Clay per S6. Preserve structure/alpha for imported materials under Treatment and the dedicated Artwork path. Whole-model Finish replacement remains explicit and clearing it restores the source materials. Project-backed instances qualify as project Finishes even when every parameter is inherited. The three-key pristine rule applies only to the existing catalogue case. [Scene contract](../../../reference/components/scene-content.md#material-and-light-semantic-gaps)

**Existing assignment encodings.** Primitives and Forms currently require a catalogue `materialId` even when they carry an instance. For a resource-backed instance use a frozen neutral catalogue ID in that fallback field. Drawing still requires the exact resource. A broken reference fails closure. Models keep the optional instance pointer and surfaces use the existing curated-or-instance reference. Test the My Objects form-only transfer's catalogue fallback and disclose when transferring a Form this way excludes its project Finish. The independent material library transfer preserves the complete recipe.

## First material family

Use `pbr-metallic-roughness/v1`, opaque, with a single surface response on both backends. The following are proposal semantics. Preserve the six built-in definitions' established multipliers. For a newly created neutral recipe use white tint, roughness 0.5, metalness 0 and no maps. When importing a complete set, propose unit factors on supplied roughness and metalness signals so those maps keep their full range. Manual assignment shows the effective multiplier and preserves an explicitly authored factor, including zero.

| Input | Binding, evaluation and neutral behavior |
| --- | --- |
| Base colour | RGB decoded from sRGB to linear, multiplied by the linear value of the literal or resolved palette colour. A missing map contributes white. Alpha has no coverage effect in this family. |
| Roughness and metallic | Each selects R, G, B or A as raw normalized data. Optional scalar inversion precedes multiplication by its own [0,1] factor. Gloss is `1 − sample` for an explicitly selected gloss signal. With no map, use the scalar. |
| Occlusion | Raw scalar with strength [0,1], default 1. Modulate indirect light by `1 + strength × (sample − 1)`. A missing map contributes 1. A baked beauty image and a shadow pass have different meanings. |
| Normal | Raw tangent-space RGB. Decode the signed vector, apply strength to X/Y and a single Y sign for OpenGL (+Y) or DirectX (−Y), then normalize. Strength is greater than zero and at most 10. Disable to use the geometric normal. Height, object-space normals and displacement require other evaluators. |

**Worked set.** A brushed-metal base colour, an `_ORM` PNG and an `_NormalDX` PNG need three ready images. Bind R/G/B of the ORM image to occlusion/roughness/metallic and set the normal's Y convention explicitly. For a texel (0.2, 0.75, 1.0), AO at half strength contributes 0.6 to indirect light, roughness at factor 0.8 yields 0.6, and metallic at factor 1 yields 1. Changing roughness uses the same original image and leaves the other channels intact. An 8-bit mid-grey image reused for colour and a scalar must produce about 0.216 and 0.502 respectively, in either request order.

**Coordinates.** The default set policy follows the target: apply the Finish's metric settings on native and architectural surfaces, and use UV0 with unit repeat and zero rotation/offset on a whole-model remap. One shared Finish can therefore serve a Wall and a model. A creator can explicitly require a coordinate source for the whole set or replace it on one binding, for example AO on UV1. Reset rejoins the set. An explicit requirement must be satisfied on every affected target. E3 compares one shared, rotated, non-square Finish on a Form and GLB before and after cutover, including one *All* edit that retains sharing. The two sources are:

- **Surface scale in metres.** Use the evaluated UV basis for Forms, Wall sides and horizontal Layout surfaces. Preserve S4 primitive repeat, including its documented box approximation. Use independent positive tile width/height in the existing 0.01–100 m range, rotation in radians and fractional offsets. Match the actual `texture-store` matrix, including its (0.5, 0.5) pivot and repeat wrapping. Freeze a non-square, rotated, offset checker as the oracle.
- **Mesh UV.** Select an available UV0 or UV1 with dimensionless U/V repeat, rotation and offset. Whole-model defaults preserve the source's UV0 and untransformed mapping. Meshes with missing UVs or a degenerate normal basis report the affected channel and mesh. Disable that sampled contribution in the inspection fallback and require repair before accepting a new incompatible assignment. Never synthesize UV1, infer metres on a model or retarget an imported material slot by index. Model-owned materials keep the source's sampler and geometry conventions.

Each consumer supplies the coordinate sets and frames available on its evaluated geometry. The compiler continues to own all architectural frames. Test orientation after moving/rotating a subject, opposite wall sides, Region underside, mirrored tangents, model image Y origin and normal Y convention independently. A later local planar or triplanar projection will need an explicit frame, scale and normal reorientation rule. The first family requires no new saved geometry.

**Channel management and import.** The manual planner accepts an existing project image or staged file, channel, component, inversion/convention and optional mapping override. Support replace, disable, reset and inspect-effective-source. A proposed automatic import groups by common stem, then matches explicit suffixes and known packing templates (ORM = occlusion R, roughness G, metallic B. RMA = roughness R, metallic G, occlusion B). Separate stems yield separate candidates. Derive proposals from stable sorted input, surface duplicate roles and ambiguous names, and leave unrecognized files unassigned. A generic “normal” needs a declared convention or explicit acceptance of the proposed +Y default. A height file never fills Normal. The user can correct every choice through the manual operation. Accepting one set creates its pins, definition, Finish and any requested assignment in one expected-revision operation. Review, cancel and stale acceptance create zero history entries. Reuse P20 digest deduplication, retention and targeted retry. Keep static PNG/JPEG/WebP admission at 25 MiB and 4096 px per edge. For the first family qualify 8-bit sRGB colour and raw 8-bit data. Prefer lossless data maps and diagnose lossy normal/packed inputs. Report unsupported containers, depth/colour encodings or resolution variants before staging. Applying curated Finishes and editing project instances stay local-first. Verified P20 upload, cloud Save and private-library transfer use the existing signed-in scope. Upload completion alone cannot alter a Finish.

**Inspection conditions.** Fix framing, light positions, linear working space, exposure 1 and sRGB output for reference thumbnails. Use a studio reflection environment only inside the inspection scene to make metal and roughness legible. The grazing-light preset reveals inverted relief. Current-World inspection reads the accepted Sky, lights and Treatment, and the actual Stage/Preview supplies the in-place comparison with architectural shadows and occluders. Channel solo bypasses lighting and Treatment. Display scalar values numerically in their original linear domain and label normal vectors in tangent space. Cache a thumbnail by resolved recipe, geometry, lighting/presentation preset and renderer profile revision. Never mount a canvas per shelf tile.

## Rendering, persistence and delivery

**Sampling and lifetime.** Split the existing store's responsibilities at the binding. Cache verified bytes by scope and pin. Decode under a declared image orientation and transfer policy with no implicit colour conversion of data maps. Lease compatible sampled views by role/transfer, sampler and UV requirements. Key material descriptors by the complete effective recipe, including selectors, conversions, signed normal convention and mapping. A short display hash or rounded scalar alone cannot establish equality. Use built-in standard PBR response and the shared material factory. Lower special component reads through portable TSL at that boundary and compose with the existing slice, cutaway and shadow masks. A shared ORM sample can feed three inputs when its image view and coordinates agree. Different coordinate sets legitimately cost another sample. Count both.

Bound concurrent decodes and GPU residency per active canvas generation. Start with two simultaneous decodes and one active interactive material preview. Queue additional work and cancel stale requests. Share verified source bytes when authorized, isolate project/release scopes, and retire textures, material leases and pending callbacks on generation loss, preview replacement or unmount. A changing scalar can update the effective material without decoding its images again. E0 records a byte ceiling per supported reference configuration by adding texture sets until frame or recovery gates first fail and retaining the last passing working set with headroom for the largest admitted in-flight decode. Report the selected ceiling and measured margin, then freeze it for E2. Estimate from decoded dimensions, mip levels and distinct allocations. Evict least-recently-used unleased views before reserving new bytes. At pressure, keep active leases, queue requests that can fit after retirement and diagnose an over-budget working set when no eviction can help. In a new set proposal, offer smaller supplied sources before acceptance. Never silently change the effective release profile. E2 forces a small budget to prove eviction, pressure reporting, successful retry and zero live-lease disposal. A single RGBA8 4096² image with a full mip chain costs about 85 MiB before other CPU/GPU copies. Keep originals immutable. Defer compression or display derivatives until a measured failure establishes the target, quality floor and versioned conversion.

**Save and portability.** One enumerator walks the current Scene texture registry, definition inputs and instance overrides, resolves material locks and texture pins, and reports a stable path for each problem. Retain P20's existing texture-record closure and the placed-only Artwork rule for delivery. Share validated facts among Save, cold Load, detached Preview and release preparation. Save verifies project ownership, ready status, MIME, length and SHA against the authored pin and stored bytes, then rechecks the captured metadata under the conditional save transaction. Load verifies before replacing the open project. Multiple roles, Finishes and Artwork sharing one image result in a single pin per logical image. With bytes unavailable, Stage may show a diagnosed scalar fallback and retry the affected image. A wrong digest, unsupported required profile or missing input blocks executable delivery.

**Cold repair.** If a private project Load cannot obtain a pinned image, retain its reference, expected digest, MIME and size in the failed-load result. An authenticated owner can supply the exact original to repair storage for that project asset. Verify the bytes and ownership, stage into private storage, recheck the expected pin before attaching the verified object, then retry Load from the start. Wrong bytes or an ownership/metadata conflict refuse. Only a fully verified project replaces the open session. E3 proves wrong-file refusal and exact-file recovery with an identical saved head, Finish bindings and history. Unsupported formats follow the separate cutover recovery. Visitors receive delivery diagnostics.

A prepared delivery descriptor declares the material profile, effective portable inputs, mapping requirements and immutable byte references. The same evaluated material contributes to Stage, snapshot, detached Preview and eligible visitor subjects. T4 owns the outer release format, admission of object kinds and public activation. Prove the material contribution through detached Preview and an already-admissible cold public fixture with editor storage empty. Exercise native Forms and ineligible delivery subjects in Stage/Preview and keep the existing public refusal. Visitor code needs neither the import recognizer, authoring planners, library service nor preview tools. **Format cutover.** Plan one coordinated Scene/resources cutover (12/3 if they land next) for the new base reference, channel bindings, material recipe and lock validation. Keep F2's five units. Route current curated and S4 writers, API validators, saved-base capture, runtime preparation and all readers through the new shape together. Carry the six curated IDs, palette semantics and S4 one-image results forward on current fixtures. Refuse old or mixed stamps and future required families with a precise diagnostic. Preserve pending capture bytes for download and leave the open session, cloud head and receipt intact on refusal. Before activation inventory stored heads, versions, pending captures and releases, rehearse restore with the outgoing reader, and provide a bounded scripted conversion with verified output for any designated trial project. Keep rollback reader plus source/byte backups. Owner review applies to data disposition and activation. ## What reaches UX planning

Engineering hands over a callable command/query inventory with sample inputs and results, the supported channel × mapping × target matrix, the preview recipes, the small licensed library, and reproducible examples of conflicts, incomplete imports, missing UVs, cold-load refusal and targeted repair. Each result identifies the affected Finish, users, source, override state and corrective operation where applicable. Include the slowest measured operation and the evidence for its progress or cancellation state.

Design one curated-first journey and validate it against four tasks. An occasional creator paints a wall with walnut and changes its sheen. A material artist corrects a gloss/ORM set, compares grain and normals under two lights, and gives one of three surfaces a different scale. A returning creator moves the result to another project and can explain what is shared. A creator with an incompatible model or missing image can identify and repair the affected channel without losing the rest.
