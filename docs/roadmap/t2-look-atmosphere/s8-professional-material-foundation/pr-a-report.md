# PR A · Characterization and material contract (E0 + E1)

**Status: ready for review.** Based on `main` at `30da19b3` (planning PR #386, renderer PR #385).
No Scene/resources source format changed, no renderer ownership moved, and no material UX was added.
This report records what was observed and what remains unmeasured; it is not a claim that the full
product suite was run locally.

## Result

- A reproducible E0 baseline now exists for the six catalogue bases, S4 single-image Finishes,
  palette followers, a shared rotated non-square Finish on a Form and a legacy GLB, Natural/Clay/
  Flat descriptors, a missing optional map, an authored zero and an explicitly disabled map.
- The two known defects are captured as observed results, not assumptions: one cached source
  texture gives a colour role and a data role the first role's `colorSpace`, and Region geometry
  emits no `uv` attribute.
- The portable `pbr-metallic-roughness/v1` contract is implemented under
  `packages/project-model/src/materials/` and exported as `@portfolio/project-model/materials`.
  It has strict recipe/override readers, sorted canonical bytes, the repository hash primitive,
  an immutable catalogue manifest, target qualification, pure resolution and pure binding.
- The neutral hash oracle matches in Node and in the browser. The six existing catalogue bases keep
  their tint, factors, tile, maps and normal readings through the compatibility adapter.

### Grammar and identity decisions

- A recipe has all six non-map properties plus `maps`; an empty map object is canonical, not omitted.
- `null` is admitted only in overrides, where it disables exactly one role. A complete recipe carries
  bindings or omits them; the recipe reader correctly refuses `maps.role: null`.
- Omission inherits the complete parent binding (including convention and per-map mapping). Replacing
  a binding replaces the whole value; removing its mapping makes it follow the set mapping.
- Duplicate image bytes under different local IDs are all admitted as source aliases of one
  canonical digest. The first source stays the canonical `byHash` identity; every alias resolves
  back to that digest instead of producing a false `missing-pin`. A source claimed for two
  different digests is a conflict: the first verified claim wins and the second identity is not
  admitted.
- Factors accept zero where their domain includes zero. An authored value equal to the base remains
  authored and reports `override`.
- Canonical bytes are sorted-key UTF-8 with no trailing newline. Arrays keep authored order. Local
  texture IDs, palette slots, project IDs and display names are outside identity.
- The neutral recipe hash is exactly
  `sha256-ce95db1ce6fb2381d7ff4542e05f83b857599e8dc673ca01d082cfc129c973bc`.
  The browser probe reproduced it independently.
- In-range rotations/offsets are returned byte-identically (not modulo-wrapped) to avoid float drift
  changing canonical bytes; out-of-range values wrap, `-0` normalizes to `0`.
- Catalogue roughness uses component `g`, matching the established roughnessMap reading. The curated
  images are grayscale, so the existing six readings do not move.
- The technical `pbr-neutral-v1` base is frozen and excluded from the creator-facing count.

### Targets and binding

- Draw facts respect indices, groups and draw range. A UV set needs a finite pair for every referenced
  vertex. A normal frame additionally needs a nonzero-area triangle with nonzero UV edges and
  `abs(det) > 1e-6 × |duv1| × |duv2|`. Empty ranges contribute nothing.
- **Metric repeat is a native-UV multiplier**, not a surface tile count. It is
  `materialMetricRepeat(basis.uvMeters, tileMeters)`: a metre chart (`uvMeters = [1,1]`)
  gets `1 / tileMeters`, and a normalized chart (`uvMeters = surfaceMeters`) gets
  `surface / tileMeters`. A 3.2 m surface with a 0.8 m tile therefore samples 1.25 across on a
  metre chart (3.2 × 1.25 = 4 tiles) and 4 across on a normalized chart. Both are tested.
- `target` mapping uses that metric result on a Form and identity UV0 with unit repeat/zero
  rotation and offset on a legacy GLB.
- `surface` mapping requires a metric basis; on a GLB it refuses with
  `mapping-requires-metric-basis` rather than silently using identity.
- The renderer's default `drawRange.count = Infinity` is accepted as the unbounded range. A
  finite range must be an integer and whole triangles; an out-of-bounds start clips to an empty
  draw, as the renderer does.
- Material groups intersect the draw range (`max(drawStart, group.start)` …
  `min(drawEnd, group.end)`). A group clipped away contributes nothing; the remaining slices are
  the actually rendered triangles. Malformed indices, out-of-range vertices, non-triangle slices,
  malformed groups or a malformed position array become `invalidGeometry` facts and bind as
  `invalid-target-geometry`.
- Missing UV, missing normal frame, pending facts, stale facts and non-finite/invalid targets all
  return ordered diagnostics, and a refused target has `bound: null` while retaining `inputs` for
  inspection.
- `qualifyAcrossTargets` reports the availability intersection across every affected draw and target;
  an unused Finish is authorable with no target issue.

### Compatibility seam

`sceneFinishToContract` adapts the existing Scene 11 instance fields to the v1 shape. The production
`resolveSceneMaterial` was deliberately **not** rewired in A. Instead, a parity suite resolves the
same inputs twice — once by the shipped resolver, once by `sceneFinishToContract` + `resolveFinish` —
over 34 cases covering every catalogue base, S4 image, palette follower, rotated non-square mapping,
both normal signs, ignored normal scale without a map, and all scalar roles. The pure result matches
the shipped readings for colour, roughness, metalness, tile, rotation, offset, map URIs and the
signed normal pair.

## Deviations and scope boundaries

1. **Renderer and dev-bench cutover deferred to B.** The plan's E1 prose says to adapt
   `scene-instance-material` and the bench to these functions. A rewiring would change production
   appearance/error behavior before B owns sampling, so A provides the adapter and the 34-case parity
   proof instead. This is an explicit sequencing choice, not an architecture change; B should replace
   the resolver internals and keep this suite green.
2. **Dangling Scene texture IDs differ at the contract boundary.** The shipped resolver warns and
   leaves the base slot when a texture record is missing. The pure resolver (correctly) reports
   `missing-pin`. Because A does not wire the pure path into production, no behavior changed; B must
   choose whether to preserve the legacy fallback at the adapter or repair the dangling reference.
3. **Pixel capture is an explicit B entry gate.** E0 freezes descriptors, evaluation inputs, fixture
   bytes and patch interiors, but does not render the product canvas; headless WebGL is SwiftShader
   with no WebGPU adapter. `e0-baseline.json` records `pixelBaseline.status = "deferred-to-B"` plus
   the hard requirement that B capture the pre-change product-canvas rendering (catalogue, S4 image,
   palette follower, shared Form/GLB, each Treatment) before replacing the resolver or sampling path,
   and retain those labelled pixels as the replacement oracle.
4. **Headless display cadence is not physical.** The 59.9 Hz rAF reading is context, not a gate.
5. **Diagnostic tie-break.** The plan requires sorting by path, role and target. The implementation
   adds `code` as a final deterministic tie-break; this does not reorder any distinct path/role/target.
6. **Scene/resources formats unchanged.** A/B intentionally do not cut over the source format; the
   current Scene 11 codec, resources 2 codec, catalogue facade, texture store and renderer store remain
   the integration points for D.
