## 0. Reconciled geometry-solve boundary

The original plan treated the per-Wall mesh too much like the geometry-solving unit.
The reconciled model separates **ownership/output** from **solving**:

```text
canonical Wall graph                     (LayoutDocument — authoring authority)
        ↓
compiled Wall paths + Junction incidence (CompiledPhysicalWall.samples, start/end Junction ids)
        ↓
Junction-local network resolution        (inspector sees ALL canonical incident legs together)
        ↓
Wall-attributed resolved end/boundary geometry
        ↓
per-Wall mesh packaging                  (renderer/picking/highlight unit)
```

> **Per-Wall ownership/output remains the unit; per-Wall geometry solving does
> not.**

A Junction resolver must inspect **all canonical incident Wall legs together**
before any final Wall endpoint geometry is determined. Per-Wall meshes remain the
final renderer/picking/highlight packaging unit, and pick/highlight/drag maps are
unchanged.

This is the one structural change that makes the plan survive T/X joins, mixed
thickness, curves and future polygonal/oval/enclosure topology without a second
compiler later.

## 2. Junction-local tangent semantics (the ambiguity fix)

Canonical Wall orientation is arbitrary relative to a Junction, so an "arrival
tangent" contract is ambiguous and cannot drive sorting, continuity, offset sides
or miters consistently. Define a **Junction-local ray that always points outward
from the Junction into the Wall**:

```ts
const tangentOut: LayoutVec2 =
  end === 'start'
    ? samples[0].tangent
    : negate(samples.at(-1)!.tangent);
```

`tangentOut` (with the matching handed normal) is used **consistently** for:

- angular sorting / cyclic adjacency;
- continuity classification;
- left/right (front/back) offset interpretation;
- miter/bevel/trim calculations.

With this convention the degree-2 policy table is corrected:

| Outward-ray relationship at a degree-2 Junction | Classification | Result |
|---|---|---|
| outward rays ≈ **180°** (collinear, opposite) | straight / tangent continuation | suppress only the **overlapping/common** interface; emit exposed **difference surfaces** for a thickness/height/opening-profile mismatch (see below) |
| outward rays show a **real tangent break** | visible bend | deterministic **trim / miter / bevel** |
| outward rays ≈ **0°** | overlapping / fold / invalid | **rejected** (`junction_seam_fold`) |

> **Do not classify every pair of reversed directions as a fold.** A normal straight
> continuation and the through-pair of a T or X Junction both contain opposite
> outward rays — those are *continuations*, not folds. The `fold` refusal is the
> ≈0° same-direction case only.

This matches the existing room-loop classification, read in the outward-ray
convention: `cornerSide` refuses only `|det| < ε` **and** `dot < 0` over
*travel* directions, which is exactly the ≈0° outward-ray fold; a straight
continuation (`dot > 0`) stays a miter.

**Continuation is a centerline relationship, not an endpoint-identity assertion.** A
tangent continuation with mismatched cross-sections is still a continuation — there is
no corner and no notch — but there **is** a physical step:

```text
0.20 m wall ───── J ───── 0.30 m wall     straight: no corner, but a thickness step
1.2 m wall  ───── J ───── 3.0 m wall     common band suppressed, upper exposed step
opening reaching J on one leg            suppressed only where the profiles overlap
```

The durable rule is therefore:

```text
tangent continuation
→ suppress only the overlapping / common interface (across the shared cross-section)
→ emit exposed difference surfaces for thickness / height / opening-profile mismatch
→ no buried internal cap
```

**Not** "tangent continuation → universally no added geometry".

**Acceptance:** a straight Wall split at a Junction produces **visually identical**
geometry — canonical topology changes, the 3D shell does not, and a normal split inherits
identical thickness/height/profile (case A below); a tangent continuation with a
thickness or height change emits its difference step deterministically (cases H/I below).

Method (reproducible — Task 6 turns it into a test helper):

```text
                current square caps span, not an arbitrary neighborhood
coverage        2D point-in-triangle over every emitted triangle projected to XZ, on a
                0.002 m grid; every fixture edge lies on the 0.05 lattice and every cell
                centre sits 0.0025 m off it, so the counts are exact, not sampled
join            compiled Wall → document Junction by wallId (compiled Walls carry no
                junction ids today, which is why the probe had to re-read the document)
```

| Fixture | Junction block | Covered | **Uncovered** | Reading |
|---|---|---|---|---|
| 90° corner, both `t = 0.2` | 0.0400 m² | 0.0300 m² | **0.0100 m²** | exactly `(t/2)²` — a 10 cm square hole at the **outer** face of every corner |
| 90° corner, `t = 0.2 / 0.3` | 0.0600 m² | 0.0450 m² | **0.0150 m²** | exactly `(t_a/2)·(t_b/2)` — the notch grows with the thicker Wall |
| degree-3 T, through 0.2 / stem 0.1 | 0.0200 m² | 0.0200 m² | 0.0000 m² | no uncovered area, but only through **interpenetration**: the through Walls' solids bury the stem's square cap (overlap, not a weld) |
| degree-4 X, 4 × 0.2 | 0.0400 m² | 0.0400 m² | 0.0000 m² | no uncovered area, but **overlap multiplicity 4** at the junction square — four coincident/interpenetrating solids |
| 90° corner, mixed height 3.0 / 1.2 | 0.0400 m² | 0.0300 m² | **0.0100 m²** | same notch as the equal case; each mesh carries exactly its own top (`[0, 3]` and `[0, 1.2]`) with no band split at the neighbour's top |
| 90° corner, one curved leg (bow), `t = 0.2` | 0.0344 m² | 0.0280 m² | **0.0064 m²** | the arrival frame is the bow tangent — `samples[0].normal` is `[-0.857, -0.514]`, ~31° off the chord normal `[-1, 0]` — while the end cap is still square to that frame; meshes: 17 samples (`line`), 33 (`cubic-chain`) |

Read the table as follows:

- The visible defect is a **degree-2 turning corner** defect (equal or unequal
  thickness, straight or curved, any height pair). The matrix in Task 6 sweeps
  30°–175° turns rather than assuming the 90° numbers extrapolate.
- Degree 3 and degree 4 have **no uncovered area**, but that is not a passing
  result. Degree 3 is closed by **interpenetration** and degree 4 by **overlap
  multiplicity 4**. "No uncovered area" is therefore **not** a sufficient validity
  predicate; the slice fixes **ownership and reconciliation** at a Junction, not
  only holes. Otherwise the same seam work is redone the first time a Wall is
  highlighted, hidden or dragged at a shared end.

Code reading behind those numbers:

- `buildRoomWallMesh` already implements the full corner machinery for a **closed
  room loop**: `computeCorners` → `cornerSide` (miter / bevel past the miter limit /
  `fold` refusal), bridge faces with a named owner, and room-wide height breakpoints
  that split every face at opening sills/springs so coincident edges weld without
  T-junctions.
- The standalone path deliberately does **not** use any of it: "the Wall as its own
  neighbour with trivial corners", both ends exact square miters.
- `CompiledPhysicalWall` carries **no** `startJunctionId` / `endJunctionId`, and
  `CompiledLayoutGeometry` has **no** junction records at all. The renderer therefore
  cannot see a Wall's neighbours today — this is the first thing the slice must fix,
  because the invariant is *one compiler output feeds all consumers*, not "hand the
  document to the renderer".

Consequence in product terms: every turning corner in Scene · 3D, Camera · 3D,
Preview and the published visitor shows a square notch — 0.0100 m² per equal-0.2 m
corner, 0.0150 m² where a 0.3 m Wall meets a 0.2 m one — and T/X Junctions are
"closed" only by overlapping solids.

## 5. Locked decisions (reconciled)

1. **Junction topology enters through the compiled contract.** `CompiledJunction` +
   `CompiledPhysicalWall.startJunctionId/endJunctionId` are additive compiled output,
   derived from `LayoutDocumentWallFirst` in the wall-first compile path. The
   renderer never receives the document; the visitor (which has no document) gets
   the same facts. No document schema change: `formatVersion` stays 5.
2. **Geometry is solved Junction-locally and network-aware; output stays per-Wall.**
   The resolution step inspects all canonical incident legs together and returns
   Wall-attributed resolved end geometry. Per-Wall meshes remain the packaging unit
   (§0).
3. **The corner policy is a deterministic function of the outward legs** — the legs'
   circular order around the Junction, each leg's `tangentOut` and half-thickness,
   and the vertical band set (§2). No new topology semantics, no proximity-derived
   welding, no degree support added: a document the codec rejects never reaches the
   builder, and the builder never invents a shape for one that does.
4. **One owner per seam, branch-cut-independent.** Angular order is used for **cyclic
   adjacency only**. After the relevant sector/pair is identified, physical
   ownership uses a deterministic rule that does not depend on an arbitrary angular
   zero — stable canonical Wall identity ordering (`wallId`) unless a stronger
   geometry reason exists. `atan2`'s `−π/+π` branch cut must never decide ownership.
   Consequence, stated openly: a wedge belongs to its owner Wall for highlight
   purposes. Acceptance asserts **rotation invariance** (adding a constant rotation
   to the whole document does not change any seam owner).
5. **Vertical bands are the mixed-height answer.** At a Junction, faces split at the
   union of the incident legs' bottom/top elevations (and at any opening sill/spring
   that reaches the Junction), exactly as `roomHeightBreakpoints` does per Room. A
   band in which only one leg exists emits an honest step face; nothing is stretched
   to fake a shared top.
6. **Curved legs use the compiled end tangent (first-order).** The compiled arrival
   frame is the authority; the chord is not. No arc–arc blending, no re-sampling, no
   change to the accepted P23.11 cubic-chain vocabulary, and **no second curve/path
   abstraction** — the leg references the incident `CompiledPhysicalWall` and its
   `end`, and reads `samples[0]` / `samples.at(-1)`. That same representation is what
   makes the future triangle/polygon/concave/oval cases work; rectangles are never
   assumed.
7. **Validation lives in canonical compile acceptance; builders are
   defense-in-depth.** The pure validator runs on the **resolved** compiled geometry
   during compile acceptance and reports a blocking `LayoutGeometryIssue`; only valid
   compiled geometry reaches consumers. Both builders may repeat the same pure
   predicate so the renderer is never the first place a defect is discovered.
8. **Degree policy (replaces the old Decision 8):**

   ```text
   degree 1                          → exposed terminal cap
   degree 2, tangent/straight (≈180°)→ suppress the overlapping/common interface;
                                       emit exposed difference surfaces for any
                                       thickness/height/opening-profile mismatch
                                       (no corner, no notch, no buried cap)
   degree 2, hard turn               → resolve deterministic trim / miter / bevel
   degree 3+                         → resolve the local Junction region across ALL
                                       incident Walls, including suppression /
                                       partitioning of already-overlapping solids
   ```

9. **Degree ≥ 3 is resolved, not left to interpenetration.** "Area covered by a
   neighbour's solid" is not a pass. The resolver inspects every incident leg
   together, partitions/trims the Junction region deterministically, suppresses
   buried/internal surfaces, avoids double-painted coincident faces and invalid
   overlap/interpenetration, and retains Wall attribution. Distinguish
   **zero added volume** (a T/X may need no new material) from **zero geometry
   reconciliation** (it still must re-tessellate/partition its endpoints).
10. **The resolution carries endpoint Opening/solid facts already compiled.** The leg
    must let the resolver know whether an incident Wall endpoint is solid or
    interrupted by an Opening (offset 0 / `offset + width === length`), reusing the
    compiled `sections` / `solidSpans` / `openings` and the existing
    `endpointProfileIntervals` / `wallOpensAtStart` / `wallOpensAtEnd` logic. **Do
    not re-read `LayoutDocument` from the renderer; do not migrate Opening ownership;
    do not invent split/Opening mutation semantics** — existing canonical
    split/edit mutation remains authority.
11. **Compiled identity is separate from cache key.** Keep stable logical identity
    independent of thickness, tangent, angle, etc.:

    ```ts
    junction.id       // stable from canonical Junction identity
    junction.cacheKey // may include geometry-affecting inputs (point, leg inputs, …)
    ```

    Follow the existing `CompiledIdentity` conventions (`geometryId` + relevant-input
    cache key).
12. **Compiled bounds include resolved Junction geometry.** Resolved seam/Junction
    geometry contributes to the **owner Wall's** `bounds2`/`bounds3`, to
    `CompiledJunction.bounds3`, and therefore to `CompiledFloor.bounds3` and
    `CompiledLayoutGeometry.bounds`. Acceptance invariant: **every emitted vertex
    lies inside the appropriate compiled aggregate bounds** (and inside its owner
    Wall's bounds). `CompiledJunction.bounds3` is never left disconnected from
    aggregate geometry bounds. This matters because a Junction-resolved miter can
    extend beyond the sampled centerline ± half-thickness, especially at acute
    angles — the current `wallBounds2`/`wallBounds3` under-covers it.
13. **Dependency invalidation is explicit.** After P23.15 final Wall geometry depends
    on neighbouring Wall/Junction state:

    ```text
    Wall/Junction change
      → recompute affected Junction resolution
      → invalidate every incident Wall body/mesh
    ```

    Do **not** claim "Wall changes → only that Wall is geometrically affected". No
    incremental-cache rewrite is required unless current code needs it for
    correctness; current consumers may rebuild broadly.
14. **Room model is preserved; RoomVolume stays deferred.** `LayoutWallFirstRoom.
    boundary: OrientedWallRef[]` is the canonical form (semantic enclosed space →
    ordered oriented Wall loop); Wall remains the physical architectural element. No
    Room-owned ring solid; no `RoomVolume` type promoted into reference truth. The
    architecture must extend to triangle / arbitrary polygon / concave polygon /
    many-sided Room / straight+curved / curve+curve / tangent-continuous / future
    oval-or-circular enclosure represented by multiple curved Walls — but **no exact
    circle/ellipse primitive and no `ClosedWall`** is implemented. The preserved
    invariant is:

    > **Junction existence defines topology; tangent continuity determines whether
    > that Junction produces a visible corner.**
15. **Production validity is analytic/topological; raster coverage is a test oracle.**
    The grid/coverage technique is kept as a fixture oracle, regression-test helper
    and diagnostic tool — never the production geometry-validity predicate (Task 4).
16. **All new algebra lives in `@portfolio/layout-core`.** The two builder copies stay
    byte-identical (already a pinned contract) and `layout-core` gains no renderer or
    app dependency.

### Task 2 — Junction-local resolution in `layout-core` (pure, renderer-neutral)
**Files:** Add `packages/layout-core/src/layout-junction-resolution.ts`; export from
`index.ts`.

This replaces the original "seam patching" framing. The durable model is a pure,
renderer-neutral Junction-local solve:

```text
CompiledJunction + incident compiled Wall endpoint/path facts
        ↓
CompiledJunctionResolution
        ↓
resolved Wall-end geometry for every incident Wall
```

```ts
type CompiledJunctionResolution = {
  junctionId: string;
  legOrder: readonly { wallId: string; end: 'start' | 'end' }[]; // cyclic adjacency
  joins: readonly CompiledLegJoin[];
  bounds2: LayoutBounds2;   // full resolved Junction region
};

type CompiledLegJoin = {
  wallId: string;
  end: 'start' | 'end';
  kind: 'terminal' | 'suppressed' | 'miter' | 'bevel' | 'trim';
  endBoundary: readonly LayoutVec2[];        // resolved footprint for this Wall end (plan, CCW)
  interfaceSuppressed: boolean;              // continuation / T-butt / X-through
  ownedSeam?: { sector: number; polygon: readonly LayoutVec2[] } | null; // branch-cut-independent owner
  bands: readonly { bottomY: number; topY: number }[]; // resolved vertical bands incl. neighbours' tops and opening sill/spring
};
```

`resolveJunction(junction, options)` returns `{ resolution, issues }` where `issues`
is `LayoutGeometryIssue[]`. The resolution must be capable of describing:

- exposed terminal caps;
- suppressed internal interfaces;
- trim/extend results;
- miter/bevel corners;
- T Junction cleanup;
- X / higher-degree accepted Junction cleanup;
- mixed-thickness transitions;
- vertical exposure/step surfaces;
- curve endpoint tangents;
- Opening-sensitive endpoint geometry.

The Junction does **not** become a physical owner. Resulting surfaces/boundaries
retain Wall provenance (`wallId` + `end`).

Policy (the table is the contract, one row per configuration):

| Configuration | Result |
|---|---|
| degree 1 (dangling Wall) | `terminal` — exposed square terminal cap |
| degree 2, outward rays ≈ 180° (tangent/straight continuation) | `suppressed` — suppress only the overlapping/common interface; add exposed step surfaces where thickness/height/opening-profile differ (no visible corner, no buried cap) |
| degree 2, hard turn; apex within `miterLimit × halfThickness` | `miter` — one shared apex per side |
| degree 2, hard turn; apex past the limit | `bevel` — both offset points kept, plus closing bridge strips |
| degree 2, outward rays ≈ 0° (overlap/fold) | `fold` issue, no seam |
| degree ≥ 3 | inspect all incident legs together; partition/trim the Junction region deterministically into angular sectors, suppress buried/internal surfaces, avoid double-painted coincident faces and invalid overlap/interpenetration; mixed thickness adds bridge strips; ownership by Decision 4 |

### Task 3 — Junction-aware standalone Wall mesh builder contract (both copies, byte-identical)
**Files:** Modify `apps/editor/src/lib/layout/wall-mesh-builder.ts` **and**
`apps/museum/src/lib/layout/wall-mesh-builder.ts` with the same edit.

The original `buildStandaloneWallMesh(wall, floorElevation, junction, options)` is
insufficient: a Wall has both a start and an end Junction, and the renderer must not
perform the topology solve itself. The builder receives **already-resolved**
endpoint/boundary information:

```ts
buildStandaloneWallMesh(
  wall,
  floorElevation,
  { start: resolvedStart, end: resolvedEnd },
  options
);
```

Exact shape may differ. The builder's responsibility is approximately:

```text
resolved Wall footprint/boundaries
+ vertical bands
+ Wall-hosted Opening cuts
→ triangles / pick ranges
```

The builder must **not** independently decide whether a Junction is a miter, T, X,
tangent continuation, etc.

- End geometry resolves in three explicit branches — there is no silent fallback:
  1. **degree 1** → today's `squareEndCorner` terminal cap;
  2. **degree ≥ 2 with a valid compiled resolution** → consume
     `CompiledLegJoin.endBoundary` / `bands` for the Wall's own start/end;
  3. **degree ≥ 2 with a missing/invalid resolution** → structured blocking issue and
     **no mesh** (fail closed). A connected endpoint must never silently fall back to a
     square cap — that recreates today's geometry and makes the renderer an authority
     the compiler is not.
- Wedge faces are emitted as the **existing** `Layout3dWallSurface = 'bridge'` class,
  through the existing `pushBridgeSide` / `pushBridgeCap` helpers, so the material
  grouping and pick partition stay intact (`pickRanges` stays a sorted,
  non-overlapping partition of the index buffer, with the wedge owned by its owner
  Wall: `{ kind: 'wall', roomId: wallId, segmentId: wallId, surface: 'bridge' }`).
- Vertical bands: split the end faces at the neighbour's top/bottom and at the
  Junction's band set (`segmentBands` already implements exactly this shape for the
  room path). Mixed height must not stretch either Wall.
- Openings that reach the Wall end stay authoritative: clip the end faces with the
  existing `wallOpensAtStart` / `wallOpensAtEnd` + `endpointProfileIntervals` logic so
  a door at offset 0 cannot be sealed by a wedge.
- Curved Walls: corners use the resolved end tangent (from `samples[0]` /
  `samples.at(-1)`), and the wedge is planar — matching `squareEndCorner`'s current
  planar cap.
- **Acceptance:** `wall-mesh-builder.test.ts` and
