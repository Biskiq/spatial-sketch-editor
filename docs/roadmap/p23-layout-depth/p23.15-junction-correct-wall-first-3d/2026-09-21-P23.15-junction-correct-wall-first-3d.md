# P23.15 — Junction-correct wall-first 3D · Implementation-Ready Plan

**Goal:** make the architectural Plan a creator authored produce credible **connected**
Wall geometry in 3D, Preview and visitor output — every Junction configuration that
canonical P23 topology already accepts renders without visible gaps, invalid overlaps or
degenerate surfaces, from one compiled contract, identically in the editor and the visitor.

**Architecture:** junction topology becomes part of `CompiledLayoutGeometry` (additive), the
miter/bevel/bridge policy becomes a pure renderer-neutral function in `@portfolio/layout-core`,
and the standalone Wall mesh path stops ending every Wall in a square cap. No new document
fields, no format-version change, no second topology or geometry compiler, no consumer
re-samples a curve.

**Tech stack:** TypeScript · `@portfolio/layout-core` (pure, renderer-free) · Svelte 5 runes ·
Threlte/Three only above the existing `wall-geometry-adapter` boundary. No new libraries.

**Baseline:** `main` @ `f52b32a` (P23.14 closed — implementation PR #61, closeout PR #71,
provenance fix). Branch `p23.15`. `buildStandaloneWallMesh` is byte-identical in
`apps/editor/src/lib/layout/wall-mesh-builder.ts` and
`apps/museum/src/lib/layout/wall-mesh-builder.ts` (1444 lines each, pinned by tests).

**Phase context:** P23.15 sits between the closed shell slice (P23.14) and the P23.16 closeout
gate. It is *not* the final gate: satisfying this plan's acceptance makes P23 closer to closable,
never closed.

## Global constraints

- One `LayoutDocument` → `compileLayoutGeometry()` → Plan/3D/visitor authority. Connectivity comes
  only from Junction IDs — **never** from coordinate proximity (`north-star.md` §1140, §1326).
- One compiler output feeds all consumers; the renderer consumes canonical topology validity and
  never defines or expands it. Mesh state is derived and never persisted.
- Nothing renderer-specific (THREE, DOM, WebGL, materials) enters `@portfolio/layout-core`
  (`tests/lib/layout/layout-geometry-boundary.test.ts`).
- Editor/visitor isolation: `/museum` chunks import no editor code; the two builder copies stay
  **byte-identical** and no new editor-internal import appears in the visitor path
  (`tests/lib/editor/layout-mesh-parity.test.ts`, `tests/lib/layout/layout-render-safe-validation.test.ts`,
  `tests/lib/museum/layout/wall-mesh-shell-boundary.test.ts`).
- Render-safe validation fails closed: a structured `LayoutGeometryIssue` and **no** mesh, never a
  silent omission or a fallback shape (`layout-wall-offset-clearance.ts` is the model).
- Any UI this slice touches enters through the P23.14 shell grammar
  (`docs/reference/design-system/editor-shell-and-visual-system.md`); this slice adds no new panel
  and no new shell surface.
- Not in scope: P23.14 residuals (TD-2, manual-owed a11y rows, §0.3 owner calls) and **TD-1**
  (canonical camera placement, owner-deferred to P24 — do not work around it here).
- No commits unless asked.

## Measured current state (2026-09-21, probe deleted after use)

A throwaway vitest probe built canonical wall-first documents, compiled them with
`compileWallFirstLayoutGeometry`, built every Wall with `buildStandaloneWallMesh(wall,
floor.elevation)`, and measured the **plan coverage of each Junction** by the union of the
incident Walls' own solids — which is exactly what the current standalone path emits, since it
ends every Wall with `squareEndCorner(...)` (`wall-mesh-builder.ts:273-274`, `:285`).

Method (reproducible — Task 6 turns it into a test helper):

```text
junction block  AABB over the incident legs' builder end-face corners
                (`sample.point ± normal · thickness/2`) — i.e. precisely the box the
                current square caps span, not an arbitrary neighborhood
coverage        2D point-in-triangle over every emitted triangle projected to XZ, on a
                0.002 m grid; every fixture edge lies on the 0.05 lattice and every cell
                centre sits 0.0025 m off it, so the counts are exact, not sampled
join            compiled Wall → document Junction by wallId (compiled Walls carry no
                junction ids today, which is why the probe had to re-read the document)
```

| Fixture | Junction block | Covered | **Uncovered** | Reading |
|---|---|---|---|---|
| 90° corner, both `t = 0.2` | 0.0400 m² | 0.0300 m² | **0.0100 m²** | exactly `(t/2)²` — a 10 cm square hole at the **outer** face of every corner |
| 90° corner, `t = 0.2 / 0.3` | 0.0600 m² | 0.0450 m² | **0.0150 m²** | exactly `(t_a/2)·(t_b/2)` — the notch grows with the thicker Wall |
| degree-3 T, through 0.2 / stem 0.1 | 0.0200 m² | 0.0200 m² | 0.0000 m² | already closed: the through Walls' solids bury the stem's square cap |
| degree-4 X, 4 × 0.2 | 0.0400 m² | 0.0400 m² | 0.0000 m² | closed, but **overlap multiplicity 4** at the junction square — four coincident/interpenetrating solids |
| 90° corner, mixed height 3.0 / 1.2 | 0.0400 m² | 0.0300 m² | **0.0100 m²** | same notch as the equal case; each mesh carries exactly its own top (`[0, 3]` and `[0, 1.2]`) with no band split at the neighbour's top |
| 90° corner, one curved leg (bow), `t = 0.2` | 0.0344 m² | 0.0280 m² | **0.0064 m²** | the arrival frame is the bow tangent — `samples[0].normal` is `[-0.857, -0.514]`, ~31° off the chord normal `[-1, 0]` — while the end cap is still square to that frame; meshes: 17 samples (`line`), 33 (`cubic-chain`) |

Read the table as: the defect is a **degree-2 turning corner** defect (equal or unequal
thickness, straight or curved, any height pair). Degree 3 is already closed and degree 4 is closed
by stacking. The matrix in Task 6 sweeps 30°–175° turns rather than assuming the 90° numbers
extrapolate.

Code reading behind those numbers:

- `buildRoomWallMesh` already implements the full corner machinery for a **closed room loop**:
  `computeCorners` → `cornerSide` (miter / bevel past the miter limit / `fold` refusal), bridge
  faces with a named owner, and room-wide height breakpoints that split every face at opening
  sills/springs so coincident edges weld without T-junctions.
- The standalone path deliberately does **not** use any of it: “the Wall as its own neighbour with
  trivial corners”, both ends exact square miters.
- `CompiledPhysicalWall` carries **no** `startJunctionId` / `endJunctionId`, and
  `CompiledLayoutGeometry` has **no** junction records at all. The renderer therefore cannot see a
  Wall's neighbours today — this is the first thing the slice must fix, because the invariant is
  *one compiler output feeds all consumers*, not “hand the document to the renderer”.

Consequence in product terms: every turning corner in Scene · 3D, Camera · 3D, Preview and the
published visitor shows a square notch — 0.0100 m² per equal-0.2 m corner, 0.0150 m² where a 0.3 m
Wall meets a 0.2 m one. Degree-3 junctions are already closed by interpenetration rather than by
welded geometry, and degree-4 by four stacked solids, so the slice fixes **ownership** at a Junction
rather than only plugging holes; otherwise the same seam work would have to be redone the first
time a Wall is highlighted, hidden or dragged at a shared end.

## Locked decisions

1. **Junction topology enters through the compiled contract.** `CompiledJunction` +
   `CompiledPhysicalWall.startJunctionId/endJunctionId` are additive compiled output, derived from
   `LayoutDocumentWallFirst` in the wall-first compile path. The renderer never receives the
   document; the visitor (which has no document) gets the same facts. No document schema change:
   `formatVersion` stays 5.
2. **The corner policy is a deterministic function** of (a) the legs' order around the Junction,
   (b) each leg's arrival tangent and half-thickness, (c) the vertical band set. No new topology
   semantics, no proximity-derived welding, no degree support added: a document the codec rejects
   never reaches the builder, and the builder never invents a shape for one that does.
3. **One owner per seam.** The wedge between two legs is emitted by exactly one leg's mesh
   (deterministic rule: the leg with the lower arrival angle, then the lower `wallId`), mirroring
   the room path's "bridge faces have an owner" convention adapted to per-Wall meshes. Per-Wall
   meshes stay the unit — no new consumer collection, no change to the pick/highlight/transient-drag
   maps. Consequence, stated openly: a wedge belongs to its owner Wall for highlight purposes.
4. **Vertical bands are the mixed-height answer.** At a Junction, faces split at the union of the
   incident legs' bottom/top elevations (and at any opening sill/spring that reaches the Junction),
   exactly as `roomHeightBreakpoints` does per Room. A band in which only one leg exists emits an
   honest step face; nothing is stretched to fake a shared top.
5. **Curved legs miter on the end tangent (first-order).** The compiled arrival frame is the
   authority; the chord is not. No arc–arc blending, no re-sampling, no change to the accepted
   P23.11 cubic-chain vocabulary.
6. **Validation is a pure predicate with codes**, in the shape of `wallOffsetClearanceFailure`:
   `layout-core` owns the rule and the codes, both builders consume it, and both fail closed. The
   visitor keeps rendering an explicit failure surface rather than silently dropping a Wall.
7. **All new algebra lives in `@portfolio/layout-core`.** The two builder copies stay byte-identical
   (already a pinned contract) and `layout-core` gains no renderer or app dependency.
8. **Degree-1 keeps today's square cap; collinear degree-2 keeps today's coincident butt.** The
   slice adds geometry only where the union is actually open (measured above) — it does not
   re-tessellate junctions that are already closed.

## Task sequence

### Task 1 — Compile canonical Junction topology
**Files:** Modify `packages/layout-core/src/layout-geometry-types.ts` (new `CompiledJunction`,
`CompiledJunctionLeg`; `startJunctionId`/`endJunctionId` on `CompiledPhysicalWall`),
`packages/layout-core/src/layout-geometry.ts` (emit them in `compileWallFirstWithPhysicalWalls`,
beside the physical-Wall loop), `packages/layout-core/src/index.ts` (export via the existing
`./layout-geometry-types` star export).

This is **forwarding existing canonical identity, not inventing it**: `LayoutDocumentWallFirst`
Walls already carry `startJunctionId` / `endJunctionId` (read throughout `layout-duplicate.ts`,
`layout-face-extraction.ts`, `layout-migration.ts`), and the document's `junctions` array is the
canonical owner of junction points. What is missing is only their presence in *compiled* output
(`CompiledPhysicalWall` ends at `wallId`…`bounds3` with no junction ids, and
`CompiledLayoutGeometry` has no junction records) — which is why no renderer can see a Wall's
neighbours today. Naming note: `layout-junction-identity.ts` already exists but owns only the
point-coincidence epsilon (`coincidesAsJunction`), not topology; the new module names below are
chosen to stay distinct from it.

- `CompiledJunction`: `CompiledIdentity` + `junctionId` + `point` + `legs: CompiledJunctionLeg[]`
  + `bounds3`. Leg record: `{ wallId, end: 'start' | 'end', role, thickness, halfThickness,
  bottomY, topY, tangent, normal, arrivalAngle }` (`bottomY`/`topY` from the Floor elevation and the
  Wall's authoritative height — the same contract the standalone builder already consumes).
- Ordering is part of the contract: legs sorted by `arrivalAngle` (CCW from +X, `atan2`, epsilon-
  snapped) then by `wallId`, so two runs over the same document produce byte-identical order.
  A Junction's `id`/`cacheKey` derive from its relevant inputs through `geometryId` (existing
  compiled-identity convention), never from iteration order.
- A Junction with no incident Wall is not emitted (the document may hold one; it is not render
  geometry). Floor elevation comes from the document's single Floor datum.
- **Acceptance:** new `tests/lib/layout/layout-junction-topology.test.ts` pins degree 1–4 fixtures,
  mixed thickness/height legs, curved arrival tangents, order determinism (same document → same
  order, and a shuffled wall array → same order), and that a codec-rejected document still produces
  blocking compile issues with no invented junction. Existing compile/parity suites stay green
  (`layout-geometry.test.ts`, `layout-geometry-parity.test.ts`, `layout-mesh-parity.test.ts`).

### Task 2 — Junction corner algebra in `layout-core` (pure, renderer-neutral)
**Files:** Add `packages/layout-core/src/layout-junction-corners.ts`; export from `index.ts`.

`resolveJunctionSeams(junction, options: { miterLimit })` returns
`{ seams: JunctionSeam[], issues: LayoutGeometryIssue[] }`, where a seam is
`{ ownerWallId, neighborWallId | null, side: 'front' | 'back', kind, polygon | apex, bands }` and
`kind ∈ 'cap' | 'butt' | 'miter' | 'bevel' | 'bridge' | 'step'`.

Policy (the table is the contract, one row per configuration):

| Configuration | Result |
|---|---|
| degree 1 (dangling Wall) | `cap` — the exact square end cap of today (Decision 8) |
| degree 2, collinear (`|det| < ε`, same direction) | `butt` — walls keep their coincident end faces, no added geometry |
| degree 2, turning; apex within `miterLimit × halfThickness` | `miter` — one shared apex per side |
| degree 2, turning; apex past the limit | `bevel` — both offset points kept, plus the closing bridge strips |
| degree ≥ 3 | per angular sector: an exterior sector (not covered by the legs' own solids) emits a `miter`/`bevel` wedge owned by the lower-angle leg; a sector covered by a neighbour's solid stays a `butt`; unequal thickness adds `bridge` strips to close the step |
| any two legs exactly reversed (180° fold) | `fold` issue, no seam — the same refusal the room path already makes |
| mixed heights | the wedge is emitted per vertical band; a band where only one leg exists emits `step` |

- The projector is shared with the room path: the offset-line intersection and the miter-limit test
  are the same algebra as `cornerSide`; the room path is refactored to call the shared function
  rather than keeping a second copy of the arithmetic (one rule, two callers).
- Purely numeric: `LayoutVec2` in, polygons/apexes out. No mesh types, no app imports.
- **Acceptance:** new `tests/lib/layout/layout-junction-corners.test.ts` walks the policy table
  (degree × angle × thickness × height) and asserts, per case, the seam kind, that the union
  coverage predicate returns zero uncovered area, and that no seam is degenerate (zero-area
  polygon, coincident apex with zero span). `layout-geometry-boundary.test.ts` still passes.

### Task 3 — Junction-aware standalone Wall mesh (both copies, byte-identical)
**Files:** Modify `apps/editor/src/lib/layout/wall-mesh-builder.ts` **and**
`apps/museum/src/lib/layout/wall-mesh-builder.ts` with the same edit;
`buildStandaloneWallMesh(wall, floorElevation, junction, options)`.

- `squareEndCorner` becomes the degree-1 branch; for degree ≥ 2 the end corners come from
  `resolveJunctionSeams` for the Wall's own `startJunctionId` / `endJunctionId` (a Wall appears once
  in its Junction's leg list per end).
- Wedge faces are emitted as the **existing** `Layout3dWallSurface = 'bridge'` class, through the
  existing `pushBridgeSide` / `pushBridgeCap` helpers, so the material grouping and pick partition
  stay intact (`pickRanges` stays a sorted, non-overlapping partition of the index buffer, with the
  wedge owned by its owner Wall: `{ kind: 'wall', roomId: wallId, segmentId: wallId, surface: 'bridge' }`).
- Vertical bands: split the end faces at the neighbour's top/bottom and at the Junction's band set
  (`segmentBands` already implements exactly this shape for the room path). Mixed height must not
  stretch either Wall.
- Openings that reach the Wall end stay authoritative: clip the end faces with the existing
  `wallOpensAtStart` / `wallOpensAtEnd` + `endpointProfileIntervals` logic so a door at offset 0
  cannot be sealed by a wedge.
- Curved Walls: corners use the compiled arrival tangent (`samples[0]` / `samples.at(-1)`), and the
  wedge is planar — matching `squareEndCorner`'s current planar cap.
- **Acceptance:** `wall-mesh-builder.test.ts` and `wall-mesh-watertight-matrices.test.ts` unchanged
  and green; new end-cap cases in the same suites cover 90°/45°/135° corners, mixed thickness and
  mixed height; `layout-mesh-parity.test.ts`'s byte-identical pin and its
  "never passes a floor-derived ceiling" pin still pass (the new parameter is a Junction record, not
  a vertical-extent scalar).

### Task 4 — Render-safe Junction validation (fail closed)
**Files:** Add `packages/layout-core/src/layout-junction-clearance.ts`; export from `index.ts`;
wire it into both builder copies before any face is emitted.

- Codes and messages follow `layout-wall-offset-clearance.ts`'s shape:
  `junction_seam_uncovered` (the union leaves a measurable hole), `junction_seam_overlap`
  (intersection beyond the tolerance the policy tolerates), `junction_seam_degenerate` (zero-area or
  zero-span seam), `junction_seam_fold` (180° reversal). Severity `error`, `targetId` = the Junction.
- The predicate is the durable form of the measurement: sample the Junction's plan block against
  the union of the legs' solids **plus** the resolved seams, with an explicit tolerance constant.
- Builders return `{ mesh: undefined, issues }` on failure. The shells already render an explicit
  failure surface for a refused room/Wall rather than omitting it — the same path is used, no new
  shell surface.
- **Acceptance:** `tests/lib/layout/layout-junction-clearance.test.ts` pins each code with a
  constructed fixture, asserts the builder returns issues and no mesh, and asserts the editor and
  museum builders report the same code for the same fixture (mirroring
  `layout-render-safe-validation.test.ts`'s core-vs-builder agreement test).
