## 1. Landed architecture

```text
canonical Wall graph
        ↓
compiled Wall paths + Junction incidence        (CompiledJunction / CompiledJunctionLeg)
        ↓
Junction-local network resolution               (resolveJunctionGeometry)
        ↓
Wall-attributed resolved end geometry           (CompiledLegJoin + CompiledJunctionResolution)
        ↓
per-Wall mesh packaging                         (buildStandaloneWallMesh)
```

- Per-Wall **ownership/output** remains the unit; per-Wall geometry **solving**
  does not. The resolver inspects every incident leg before any Wall endpoint is
  determined; the builder only triangulates.
- Renderers read `legJoinsByWall(geometry.junctions)` and pass
  `{ start, end }` into the builder. A connected end with no resolution is a
  blocking issue and produces **no mesh** (no square-cap fallback).
- Canonical compile acceptance owns validity: resolve → validate →
  `LayoutGeometryIssue` → only valid compiled geometry reaches consumers. Both
  mesh builders re-run the same pure predicate as defense-in-depth with the same
  codes.
- Production validity is analytic (finite coordinates, positive band spans,
  non-collapsed seam polygons, join completeness), never sampled grid coverage.
  The raster/coverage probe lives only in `tests/helpers/wall-mesh-fixtures.ts`
  as an independent oracle.

## 2. Implementation notes worth recording

- **Degree ≥ 3 pairing/partition.** The resolver pairs collinear antiparallel
  legs as the through Wall first and suppresses their interface; the core is the
  continuation pair containing the smallest `wallId`, and every remaining leg is
  a branch **trimmed against the resolved core material** (see §7 — the earlier
  `247528c` policy closed the region by interpenetration and has been replaced).
  The angular-neighbour pairing that preceded both mitred the through Wall
  against a branch, which buried a surface and produced a self-intersecting end
  quad and a real gap at the Junction; the independent coverage oracle caught it
  and the fixture matrix pins it.
- **Continuation is a centerline relationship.** A tangent pair suppresses only
  the common interface; thickness, height and Opening-profile differences still
  emit their exposed step. At degree ≥ 3 the Junction decides whether that step
  is exposed or buried by another leg, because only the Junction has every leg.
- **Corner seam ownership** is the start leg, else the smaller `wallId` — never
  an angle, so `atan2`'s branch cut cannot move physical ownership. This governs
  the miter/bevel wedge only.
- **Continuation difference-surface ownership follows the material**, not that
  tie-break: a thickness step strip belongs to the **thicker** leg and a
  sole-solid band cap to the **solid** leg, and the counterpart leg's own build
  evaluates the mirrored predicate and emits nothing. Both orders of a seam
  therefore produce the same attribution.

### 5.1 Self-review session (2026-09-21, editor dev server on 5173)

The reconciled implementation was reviewed against the running editor by driving
the app's **own module graph** in the browser (`import()` of the editor layout
preview store), so the check runs the shipped code, not a test copy. A 19-Wall
fixture spanning cases A–I was imported and the derived meshes were inspected:

| Check | Result |
|---|---|
| Import + compile of the fixture | 19 Walls / 25 Junctions / 1 Room, **0 issues** |
| Per-Wall mesh count | 19 meshes, 0 room meshes (wall-first Room renders via its Walls) |
| Case G — every emitted vertex inside compiled aggregate bounds | 0 violations, worst overflow 0 |
| Case A — identical split at a new Junction | no bridge surface, no Junction-plane face on **either** leg; combined projected area equals the unsplit Wall exactly (Δ = 0) |
| Case H — 0.20 → 0.30 thickness step | thinner leg silent; thicker leg carries the step, **0.300 m²** = 2 × 0.05 × 3 |
| Case I — 1.2 → 3.0 height step | shorter leg silent and capped at **1.2 m**; taller leg carries the step, **0.360 m²** = 0.2 × 1.8 |
| Decision 4 — rotation invariance | rotating the whole fixture 0.7 rad and 2.1 rad leaves **0 issues**, 19/19 meshes, and **no per-Wall change in surface area or step attribution** (total area 377.660 → 377.660) |

**One defect was found and fixed here.** The continuation step was emitted by the
seam's *start* leg rather than by the leg that owned the material, so a shorter
start Wall borrowed its taller neighbour's cross-section: its mesh grew to the
neighbour's height and the exposed step surface was packaged and pick-owned by
the wrong Wall. The thickness case only looked correct because the thicker Wall
happened to be the start leg. The raster coverage oracle could not see this —
coverage and area are identical either way, only *attribution* was wrong — which
is why it took a per-Wall live probe. Fixed by making the ownership predicates
per-band and material-based (see §2), synced to the museum builder, and pinned by
the new order-independence regression test above.

Triangle counts are deliberately **not** asserted as rotation-invariant: some
Walls legitimately re-triangulate under rotation (±8 triangles) while surface
area and attribution stay identical, so the invariant that is pinned is the
physical one, not the tessellation density.

## 7. Correction pass (post-`247528c` review)

The review found three blocking gaps in the landed implementation. All three are
addressed here. The follow-up review then found a fourth: a degree ≥ 3 Junction
with **no** straight-through continuation pair (Y/star) was still unresolved. Its
sector partition landed as the second correction pass (§7.5) and closed that gap;
nothing in this record is now "reported instead of solved".

### 7.1 Degree ≥ 3 is partitioned, not interpenetrated

```text
core = the continuation pair containing the smallest wallId (deterministic,
       rotation-invariant)
core legs        keep their own material; their shared interface is suppressed
                 and their thickness/height/Opening difference surfaces are
                 solved per vertical band
branch legs      trimmed at the distance where they leave the resolved core
                 material (analytic maximum over the branch's own cross-section;
                 never sampled, never iteration-order dependent)
```

Each trimmed branch's end cross-section is an internal interface. The parts no
core material covers are emitted as **Wall-attributed trim surfaces**
(`CompiledJunctionSurface`, `kind: 'branch-trim'`); the parts that rest on a core
face suppress that exact face region per band (`CompiledJunctionInterface`, whose
`normal` is the face's own outward normal, so no `front`/`back` convention can
drift). The result is overlapping-free by construction: no two Wall-owned bodies
occupy the same volume, no cap is buried, and no surface is double-painted.

A degree ≥ 3 Junction with **no** continuation pair (a Y/star) has no through
material to trim against and is partitioned by its own sector beams instead —
§7.5.

### 7.2 Continuation difference surfaces moved out of the builders

The resolver now emits `CompiledLegJoin.surfaces` — per band, per owner, with the
resolved plan segment, outward normal and band set. `buildStandaloneWallMesh` no
longer compares thicknesses, inspects a neighbour's bands, decides exposure or
attrs ownership: it triangulates the resolved surfaces it is handed. The
`buildStandaloneContinuationStep` decision path is deleted from both builder
copies (still byte-identical).

### 7.3 Per-band, Opening-aware exposure

Exposure is evaluated per vertical band against a covering leg's **material**
(plan footprint *and* solid band), not its 2D footprint: `legSolidInBand` reads
the compiled endpoint Opening bands. So the documented mixed case
(`through A: 3 m · through B: 3 m thicker · branch: 1 m`) exposes the thickness
step above the branch's top and buries it below, and an Opening void in a branch
never buries a step. The difference-surface split is exact (the sub-interval
boundaries are solved from every coverer's band/longitudinal bounds) and adjacent
sub-intervals with the same exposure are merged, so no spurious shared edge is
introduced.

### 7.4 Bounds, queries and cache keys

- `wall.bounds3` is now expanded by resolved Junction geometry alongside
  `wall.bounds2`, so a resolved miter/bevel/difference surface can no longer
  escape the owner Wall's vertical bounds.
- The Wall **query AABB** is reconciled from the final bounds instead of being
  left as the stale pre-resolution record.
- `CompiledJunction.bounds3` includes resolved surface endpoints, so Junction,
  Floor, document and query bounds stay consistent with emitted geometry.
- `CompiledJunction.cacheKey` now serializes every resolution-affecting endpoint
  fact — frame, thickness, extent, role **and** `endpointSolidBands` — so a
  changed endpoint Opening height/sill changes the key while `junction.id` stays
  stable (`junction-partition.test.ts` pins both directions).

### 7.5 Degree ≥ 3 with no continuation pair (Y / star) is partitioned

```text
beams            one equal-clearance beam per cyclically adjacent leg pair: the
                 line through the two *facing* offset lines' intersection,
                 parallel to the sum of the two outward rays. Equal clearance
                 (|lateral| - halfThickness), not equal angle, so mixed
                 thickness falls out of the same rule
wedge form       a leg whose neighbours leave on opposite sides gets its cap
                 (the two beam crossings on its own faces) plus the sector
                 triangle behind it
leg cell         every leg's Junction-local material is its own band, in front of
                 its Junction plane, on its own side of its two beams — a
                 half-plane intersection, so it needs no "neighbours on opposite
                 sides" precondition
difference form  solved by subtracting each neighbour's claim from the leg's
                 band, limited to that neighbour's own strip and to the material
                 in front of its own Junction plane, keeping the convex pieces
                 (a difference of convex polygons is emitted as convex polygons,
                 never as one region with a hole)
keel             the leg keeps a plain strip from its cap outward; the
                 Junction-local piece is published as a Wall-attributed keel
                 (regions + bands) with its exposed per-band boundary surfaces
wrap             a neighbour thinner than the sector it faces leaves material of
                 this leg's band beyond the neighbour's far face, where no
                 neighbour reaches; no neighbour can own it, so this leg owns it,
                 as a second keel region
```

Both forms are the same rule and neither leaves material to interpenetration. The
wedge form only **declines** (degenerate crossing, collapsed cap, thin-neighbour
wrap) and the difference form then solves that Junction exactly — declining is
never a silent approximation. Exposure of the resolved boundary is evaluated per
vertical band against each neighbouring leg's own material (its strip *and* the
solid bands of its endpoint Opening profile), so an Opening void never buries a
surface.

One configuration remains genuinely undefined: two cyclically adjacent legs
leaving in exactly the same direction (duplicate-direction authoring), or a
neighbour lying on another leg's own centreline, so no facing offset line — and
therefore no equal-clearance beam — exists. That fails **closed**: a blocking
`junction_partition_failed` error plus an unresolved join on every leg, so both
builders emit **no mesh** and the renderer never becomes the first place
overlapping Wall bodies are visible. `junction_partition_unresolved` no longer
exists anywhere in the codebase.

## 8. Deferred / not in scope

Incremental Junction invalidation is **not** implemented: a Wall/Junction edit
recomputes the affected Junction and invalidates every incident Wall mesh. Live
3D rows above need an owner session. No `RoomVolume`, no Room-owned Wall ring, no
CSG, no exact circle/ellipse primitive, no `formatVersion` change, no new
topology degree validity, no P24/P26 capability.
