## 1. Landed architecture

```text
canonical Wall graph
        ↓
compiled Wall paths + Junction incidence        (CompiledJunction / CompiledJunctionLeg)
        ↓
Junction-local network resolution               (resolveJunctionGeometry)
        ↓
Wall-attributed resolved end geometry           (CompiledLegJoin + CompiledJunctionResolution)
        ↓
per-Wall mesh packaging                         (buildStandaloneWallMesh)
```

- Per-Wall **ownership/output** remains the unit; per-Wall geometry **solving**
  does not. The resolver inspects every incident leg before any Wall endpoint is
  determined; the builder only triangulates.
- Renderers read `legJoinsByWall(geometry.junctions)` and pass
  `{ start, end }` into the builder. A connected end with no resolution is a
  blocking issue and produces **no mesh** (no square-cap fallback).
- Canonical compile acceptance owns validity: resolve → validate →
  `LayoutGeometryIssue` → only valid compiled geometry reaches consumers. Both
  mesh builders re-run the same pure predicate as defense-in-depth with the same
  codes.
- Production validity is analytic (finite coordinates, positive band spans,
  non-collapsed seam polygons, join completeness), never sampled grid coverage.
  The raster/coverage probe lives only in `tests/helpers/wall-mesh-fixtures.ts`
  as an independent oracle.

## 2. Implementation notes worth recording

- **Degree ≥ 3 pairing.** The resolver pairs collinear antiparallel legs as the
  through Wall first and suppresses their interface; every remaining leg is a
  branch **trimmed flush at the Junction plane**, closed by interpenetration. The
  earlier angular-neighbour pairing mitred the through Wall against a branch,
  which buried a surface and produced a self-intersecting end quad and a real gap
  at the Junction. The independent coverage oracle caught this; the fixture
  matrix now pins it.
- **Continuation is a centerline relationship.** A tangent pair suppresses only
  the common interface; thickness, height and Opening-profile differences still
  emit their exposed step. At degree ≥ 3 the Junction decides whether that step
  is exposed or buried by another leg, because only the Junction has every leg.
- **Corner seam ownership** is the start leg, else the smaller `wallId` — never
  an angle, so `atan2`'s branch cut cannot move physical ownership. This governs
  the miter/bevel wedge only.
- **Continuation difference-surface ownership follows the material**, not that
  tie-break: a thickness step strip belongs to the **thicker** leg and a
  sole-solid band cap to the **solid** leg, and the counterpart leg's own build
  evaluates the mirrored predicate and emits nothing. Both orders of a seam
  therefore produce the same attribution.

### 5.1 Self-review session (2026-09-21, editor dev server on 5173)

The reconciled implementation was reviewed against the running editor by driving
the app's **own module graph** in the browser (`import()` of the editor layout
preview store), so the check runs the shipped code, not a test copy. A 19-Wall
fixture spanning cases A–I was imported and the derived meshes were inspected:

| Check | Result |
|---|---|
| Import + compile of the fixture | 19 Walls / 25 Junctions / 1 Room, **0 issues** |
| Per-Wall mesh count | 19 meshes, 0 room meshes (wall-first Room renders via its Walls) |
| Case G — every emitted vertex inside compiled aggregate bounds | 0 violations, worst overflow 0 |
| Case A — identical split at a new Junction | no bridge surface, no Junction-plane face on **either** leg; combined projected area equals the unsplit Wall exactly (Δ = 0) |
| Case H — 0.20 → 0.30 thickness step | thinner leg silent; thicker leg carries the step, **0.300 m²** = 2 × 0.05 × 3 |
| Case I — 1.2 → 3.0 height step | shorter leg silent and capped at **1.2 m**; taller leg carries the step, **0.360 m²** = 0.2 × 1.8 |
| Decision 4 — rotation invariance | rotating the whole fixture 0.7 rad and 2.1 rad leaves **0 issues**, 19/19 meshes, and **no per-Wall change in surface area or step attribution** (total area 377.660 → 377.660) |

**One defect was found and fixed here.** The continuation step was emitted by the
seam's *start* leg rather than by the leg that owned the material, so a shorter
start Wall borrowed its taller neighbour's cross-section: its mesh grew to the
neighbour's height and the exposed step surface was packaged and pick-owned by
the wrong Wall. The thickness case only looked correct because the thicker Wall
happened to be the start leg. The raster coverage oracle could not see this —
coverage and area are identical either way, only *attribution* was wrong — which
is why it took a per-Wall live probe. Fixed by making the ownership predicates
per-band and material-based (see §2), synced to the museum builder, and pinned by
the new order-independence regression test above.

Triangle counts are deliberately **not** asserted as rotation-invariant: some
Walls legitimately re-triangulate under rotation (±8 triangles) while surface
area and attribution stay identical, so the invariant that is pinned is the
physical one, not the tessellation density.

## 6. Bounds

Every emitted vertex is asserted inside the document, Floor, owner-Wall and
Junction aggregate bounds (`junction-matrix.test.ts` case G), so resolved miters
and bevels cannot silently escape the compiled bounds that
`compileWallFirstJunctions` expands.

## 7. Deferred / not in scope

Incremental Junction invalidation is **not** implemented: a Wall/Junction edit
recomputes the affected Junction and invalidates every incident Wall mesh. Live
3D rows above need an owner session. No `RoomVolume`, no Room-owned Wall ring, no
CSG, no exact circle/ellipse primitive, no `formatVersion` change, no new
topology degree validity, no P24/P26 capability.
