## Findings

- **F1 — Scene workspaces can mount the Camera node editor.** With a camera node retained
  from the Camera domain, Scene · 3D renders `EditorCameraInspector` (position/target/FOV —
  framing authoring) while the Status Rail reads `No selection / 0 selected`. Contract:
  `design-shell-specs.md` §15 (“Scene workspaces may show Camera entries … without exposing
  sequence/timeline/framing authoring”) and §20. **Not patched** — clearing or scoping the
  retained camera selection is a selection-model decision, not shell polish.
- **F2 — Inspector header and body can describe different selections.** With the Assets panel
  focused, the sectionheader still read the camera node identity while the body rendered the
  asset-details panel. Same root as F1 (two selection models reaching one panel). Reported,
  not patched.
- **F3 — locality badges asserted the legacy format (fixed in this pass).**
  `CameraPlanInspector` hard-coded `Camera node · room-local` and printed an unguarded
  `Room` slot; `EditorCameraInspector` and `EditorTransformInspector` likewise. All now
  derive from the selection (`roomId ? 'Room-local' : 'World-local'`), matching P23.0b
  world-local being the canonical Scene format.
- **F4 — numeric fields report `:invalid` while holding legal values.** `min="0.001"` with
  `step="0.01"/"0.05"` puts the browser's step base off-grid (`0.1`, `3.75` both fail), so
  the a11y tree announces valid values as invalid. No stylesheet paints `:invalid`, so this
  is an AT-truth defect, not a visual one. **Not patched** — the fix (align `min` to `step`,
  or `step="any"`) changes arrow-key increments, which §7 territory; owner call.
- **F5 — `POV / Observer` appears twice in Camera 3D** (View Bar and the drawer transport
  strip). Both are coherent surfaces, so this is a deliberate-looking duplication; flagged
  for the owner, not patched.
- **F6 — progressive-density threshold was too high (fixed in this pass).** The container
  measured is the Navigator scroll track (232 px inside the reference 268 px column), so a
  `16rem` (256 px) threshold hid row metadata at the *reference* width. Now `216px`: fires
  only when the column is squeezed below ~252 px, i.e. between the reference and the 240 px
  minimum.
