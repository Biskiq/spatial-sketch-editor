### 4.1 H2 primary question — answered

> **Is equivalent curved geometry recomputed independently across topology, face extraction,
> reconciliation, compile and mesh preparation?**

```text
YES for topology (pre AND post), face extraction, the Opening set and the compile: five independent
consumers, ≈280 sampling operations per release on E3, each calling the same
`wallCenterlineSamples:314` → `sampleSegment:384` seam on the same (document, Wall) with no shared
representation (F-P2).
NO for reconciliation (it consumes extracted face polygons and does not sample — F-C2).
NO for mesh preparation (it consumes the compiled samples — F-P4).
NO for snap (memoized geometry index) and NO for the Plan model (pure projection) — F-P3/F-P11.
```

### 4.2 Reuse opportunities and their equivalence proof obligations (EQ-1)

Each row is an **obligation, not a recommendation**. None may be treated as safe without the proof.

| # | Candidate reuse | What must be proven before it is safe |
|---|---|---|
| EQ-1 | Share one sampled centerline per Wall between `topology-pre` and `topology-post` | The two calls consume the same Wall object and the same centerline values. **False today**: `topology-post` runs on the RECONCILED document (`:1575`), while `topology-pre` runs on the pre-reconciliation candidate (`:1518`) — reconciliation can rewrite Room boundaries even though it does not rewrite Wall centerlines. Prove the centerline set is invariant across reconciliation (or key the cache on centerline identity, not document identity). |
| EQ-2 | Share the compile's samples with the topology gate | Both must consume the same normalized centerline under the same sampling options (sample count/tolerance) and the same traversal. The gate walks canonical `'forward'`; face extraction and `roomBoundaryPolygon` walk traversal-dependent directions (`'reverse'` mirroring is real, `layout-wall-centerline.ts` `mirrorSpanView`).
