## P23B.0 owner-fixture measurement — 10 rooms, 40 Bézier walls

Read-only. No repository files, benchmark code, or baselines were changed. Commit `85f47ec`. Cursor embedded Chrome 148, device pixel ratio 2, ANGLE Metal on Apple M2, 8 cores. The dev server at `127.0.0.1:5173` imported the supplied layout. Times are milliseconds, p50 / p95. Stage marks overlap and must not be added.

### Fixture

The export is 10 separate rooms, 40 cubic walls, 40 junctions, no openings. Raw payload 36,456 bytes, SHA-256 `37a857690ca255e0355f08519a195575d12e53b43ca9bb2f7820b18bb36dc27f`. Each wall samples to 33 points (1,320 total). Compile reports no issues, and both Plan and 3D draw it. Import does not run the curve-crossing gate, so the document loads. The same four knot ids are copied onto every room. Renaming them does not change the rejection.

### Wall rejection

Drawing a wall in empty space, with Snap 0.25 m and Grid on, was rejected:

> Walls 'wall-chain-1.2-copy-copy-copy-copy-copy-copy' and 'wall-chain-1.4-copy-copy-copy-copy-copy-copy' have unsupported centerline crossing

That pair is the right-hand wall of one packed room and the left-hand wall of the next. The curves really intersect: two proper crossings, closest samples 0.02 m apart. Two more pairs in that right-hand row do the same. The first six rooms are clear. The crossing appears once the eighth room is included. The bows reach about 1.7 m into a gap of about 1 m, so the chords miss and the curves do not.

A new wall, a closed room, a bend, and a knot drag all rescan every pair, so this one existing crossing rejects all of them. An empty-space wall fails in about 10 ms. An empty-space rectangle fails in about 23 ms. Bend and knot release fail in 6.5–7.5 ms and never reach compile or mesh rebuild.

Room duplicate uses a chord-only check. A far duplicate of an isolated room still succeeds. That is how curved copies can be placed so their bows cross, after which the wall tools are stuck.

### Cost

On the exported layout, edits die at topology:

| Path | 40 Bézier walls | Same rooms, walls forced straight |
|---|---:|---:|
| Topology validation | 5.7 / 6.0 | 0.2 / 0.3 |
| Wall-first compile | 12.4 / 13.7 | 4.2 / 7.7 |
| 3D wall meshes only | 6.1 / 6.9 | — |
| Plan model | 0.1 / 0.1 | 0.1 / 0.2 |
| Plan SVG string | 0.3 / 0.4 | — |
| 200 hit queries | 23.9 / 24.5 | 16.9 / 17.5 |
| Pointer-move proposal and preflight | 6.0 / 9.8 | — |
| Release, rejected before compile | 6.5 / 7.2 | — |
| Document `JSON.stringify` | 0.1 / 0.2 | — |
| Warmed snap query | 0.2 / 0.4 | — |

After the crossing rooms were separated in memory, the same bend release was accepted every time: **41.8 / 49.3 ms**, about two and a half frames at 60 Hz. Overlapping stages on that release: curve sampling 14.1 / 17.2, acceptance compile 13.7 / 16.0, topology before and after 7.0 each, candidate mesh prebuild 7.4 / 9.5, room-geometry compile 5.8 / 6.7, face extraction 4.5 / 5.7. Junction resolution is 0.2 ms. A clean 40-wall pointer move is 6.5 / 6.8 ms.

Compile p50 from 1 to 10 rooms: 1.4, 2.5, 5.0, 7.7, 10.3, 13.2 ms. Topology on the still-valid six-room subset is 2.9 ms.

In the live Plan view, idle frames after import sat at 16.7 ms. That surface was only 196×626 CSS pixels, so it is not a full-screen result. 3D drew the curved walls. Long tasks of 64–314 ms appeared around import and the wall clicks. Those include this browser session, so the 41.8 ms instrumented release is the number to use.

### For P23B.1

The repeated curve walk through topology and compile is the main release cost, now measured on this layout. Candidate mesh rebuild is next. Junction resolution, snap, Plan model construction, and `JSON.stringify` cache keys are small here. Separate from the cost: chord-only room duplicate can install bow crossings, and the wall-authoring gate then rejects every later wall because it rescans the whole document.
