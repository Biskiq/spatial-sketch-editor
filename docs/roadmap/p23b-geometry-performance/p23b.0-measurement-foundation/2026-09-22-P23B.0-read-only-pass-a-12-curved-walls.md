## Limits and finding

This reproduces a **measurable curved-geometry release hitch**: the synthetic case’s 18.6 ms median synchronous release exceeds one 60 Hz frame interval. It does **not** establish the owner’s reported continuous choppy interaction or an owner-case baseline. The owner’s exact curve shapes, shared versus separate room boundaries, gesture, snap setting, browser and machine were not supplied. The exact fixture was profiled in the browser runtime without mounting it in the live Plan and 3D views, so its SVG flush, Three adapter, paint and presented-frame costs remain unmeasured.

There is a consequential diagnostic mismatch. The current editor derives a transient proposal on pointer move and performs full acceptance **once on release**. The existing `/dev/perf/bend` matrix instead restores and runs the release operation every sample. Its `bend-3-room` input begins with 12 straight Walls and curves only the edited Wall. Its reported “gesture-frame” time therefore cannot serve as the requested twelve-Bézier-Wall interaction baseline. On that existing, different browser scenario it reported 16.8 ms p50 / 17.0 ms p95.

P23B.1 should use these measurements to inspect repeated curve sampling through topology and compile, fresh candidate mesh construction, and the unmeasured Plan/3D frame path. The measured Junction resolver is small here. Cache-key generation has no separate timing mark; source shows `cacheKeyOf` uses `JSON.stringify`, so its share of compilation remains unknown. The geometry-identity mesh cache and accepted-compile reuse were effective for baseline restore and install in this run.
