### 2.1 The five fixture SEMANTIC CLASSES (added — Option E revision)

The historical reports stay immutable evidence. What the owner-directed direction changes is that a
fixture's EXPECTED VERDICT now belongs to one of five semantic classes, and **a fixture may not be moved
between them by relabelling**. Because **D-11 = ARRANGEMENT 1 ships the policy BEFORE this slice**, the
executable classes are written against the **POST-POLICY** validator — and any class that was "future"
only for sequencing reasons is now live:

```text
CLASS 1  HISTORICAL EVIDENCE (E2, and the historical E1/E3) — IMMUTABLE
  Reported, uncommitted, unrecoverable bytes. What P23B.0 Pass B recorded stands as recorded: under the
  validator shipped AT THAT TIME, E2 was an admitted curved crossing whose crossing later blocked
  unrelated edits. Its numbers, source hash, environment and original verdict are NOT rewritten, NOT
  re-derived and NOT promoted to a baseline. Historical E2 is never "the old version of N-2".

CLASS 2  REGRESSION FIXTURES — RE-BASED, because the policy ships FIRST
  Under D-11 = ARRANGEMENT 1 the topology-policy slice lands BEFORE this one, so the verdicts these
  fixtures pin are the FIXED ones, committed against the SHIPPED POST-POLICY validator and labelled
  `post-policy, shipped`. The earlier `current-behaviour, revisable when the topology-policy change
  lands` label described the pre-selection sequencing and is WITHDRAWN — nothing here waits on a policy
  that has not landed. The decision record §6 sets remain the reference, with T3 as the case that FLIPS
  and T13 as the case that must NOT move. N-2 is RE-BASED, not relabelled (see CLASS 3).

CLASS 3  OPTION-E POSITIVE CASES — NOW EXECUTABLE (the policy ships first)
  The F1–F8 cases: independent-group overlap as PERMITTED geometry, INCLUDING the D-9 positive case —
  two independent Junctions at exactly coincident coordinates with DISTINCT ids (F3), and INDEPENDENT
  groups deliberately sharing no Junction. Because ARRANGEMENT 1 lands the policy BEFORE this slice,
  these are no longer future-only: they are committed as PASSING expectations against the shipped gates.
  The ENABLING CONDITION IS THE LANDED CODE: if the policy slice had not landed, these must not be
  committed as passing, because a fixture asserting that an independent-group crossing is permitted
  while the document-global gates still reject it fails against unmodified code — the trap decision
  record §4.1 forbids.

  THE FIXTURE THAT CHANGES MEANING — N-2 / W2c.
    · Historical E2 is CLASS 1 and IMMUTABLE: its recorded verdict, hash and environment never change.
    · The COMMITTED fixture N-2 is a DIFFERENT artifact and follows the SHIPPED policy. Once E ships, an
      independent-group curved crossing is a POSITIVE case, so N-2 moves out of "negative-correction
      ONLY" and into this positive class.
    · If a NEGATIVE curved-crossing fixture is still wanted, it must be built as an INTRINSIC case — a
      crossing INSIDE one explicitly connected group — which is CLASS 4. It must NOT be a reused N-2, and
      its identity must not inherit N-2's.

CLASS 4  NEGATIVE CASES FOR INTRINSIC VALIDITY (executable NOW, and they must SURVIVE the policy change)
  Self-intersecting centerlines, an invalid boundary INSIDE one explicitly connected group, illegal
  relationships within a connected group, zero-length Walls, malformed Room boundaries, and — the D-9
  NEGATIVE TWIN of CLASS 3's F3 — DUPLICATE JUNCTION POINTS WITHIN one connected component, which stay
  invalid. These pin the rejection set Option E's containment promises NOT to relax — the proof that E is
  a ONE-CLASS relaxation, and the fixtures a careless implementation breaks first.

CLASS 5  THE REPRODUCIBLE VALID CURVED PERFORMANCE FIXTURE
  The one fixture a timing claim may be taken against: valid under the gates CURRENT AT MEASUREMENT
  TIME, with a serialized identity. Because D-11 = ARRANGEMENT 1 places **P23B.3a BEFORE this slice**,
  it is recorded ONCE — the POST-POLICY, PRE-OPTIMIZATION baseline (synthesis §7.4). There is no
  pre-policy recording to keep alongside it, and no relabelling.
```

## 3. The control matrix (this is what makes a size/curvature claim possible)

**Correction to an earlier overstatement in this plan.** The historical passes did NOT vary only size
and curvature together: **both passes included a SAME-SHAPE STRAIGHT CONTROL** (Pass A: 12 curved vs 12
straight Walls in the same 3 rooms; Pass B: 40 curved vs the same 10 rooms with walls forced straight), so
curvature IS separately isolated within each pass, and Pass B even reports one within-environment
size series (compile p50 by room count, 1→10 rooms). What the controls do **not** provide is
reproducibility: they are ad-hoc constructions made in memory during a read-only pass, they are not
committed, they carry no fixture identity, and they were measured under two different browsers (harvest
UN-4, synthesis §2.5 CTRL-1/SWEEP-1 and C-4).

So the durable work is not "create the comparison" — it is **make the comparison reproducible**. P23B.0
durable replaces the reported matrix with a COMMITTED matrix measured in ONE environment, ONE session,
ONE sampling config:

| Axis | Levels |
|---|---|
| document size | 12 Walls (3 Rooms × 4) · 40 Walls (10 Rooms × 4) |
| curvature | all-straight · target-Wall-only-curved · **all-curved** |

```text
Deliverable: every cell of the matrix is a committed fixture with a stable id, and every cell has a
recorded measurement under the SAME provenance block. Only then may a statement like "curvature, not
size, drives stage X" be made — and only for the measured environment, which must be named.

Also required: a straight-Wall control for the SAME room/wall shape as each curved fixture, so
"curved vs straight" is one variable and "small vs large" is another. The historical passes already
built both kinds of control by hand; this slice COMMITS them.
```

## 6. Risks

```text
R-1  PROVENANCE DRIFT. A baseline recorded on a dirty tree is not reproducible from HEAD alone. The
     existing `treeDirty`/`contentHash` fields already handle this; the slice must record a CLEAN-TREE
     baseline for the authoritative one.
R-2  FIXTURE LEGITIMACY. A constructed fixture (BRANCH-C) is not the historical payload. If it is ever
     called "E2" or "E3" the phase has fabricated provenance. Naming discipline is the mitigation.
R-3  METRIC PROLIFERATION. Extending `BenchMetricName` invites unbounded growth. Add only metrics a
     slice will actually consume; every added name is a maintenance surface.
R-4  MEASUREMENT BECOMING A PRODUCT CHANGE. The DEV-gated marks must stay behind the flag; a mark in a
     hot loop that is not compiled out can itself perturb the measurement.
R-5  ENFORCED-BUDGET PERTURBATION. Adding cached key material or new fixtures can move
     `cache-key-code-units`/`compiled-memory` for existing tiers. Any movement must be explained, not
     re-baselined to silence a failure. Re-recording a budget to make a red test green is forbidden.
R-6  SAMPLING HONESTY. Wall-clock samples on a developer machine are advisory. Report p50/p95 with the
     sample count and the warmup; never one run.
```
