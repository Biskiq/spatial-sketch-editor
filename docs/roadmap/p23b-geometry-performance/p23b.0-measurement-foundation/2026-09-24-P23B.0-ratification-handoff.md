## 2. Corrected fixture ledger and expected post-policy verdicts

Semantic classes are the plan's §2.1. **"Expected verdict" is what the SHIPPED policy prescribes** for the
described relationship, supported by committed source/test bytes (§7) and by the landed P23B.3a policy. It
is **NOT verified for these exact fixtures** — none has been constructed, so the ledger records an
expectation, not an observation. B-4 below is the contract: the W2 fixture-contract tests promote each
expectation to an asserted verdict, and no verdict may appear in a baseline before then. The archived
reports' numbers are never re-derived here.

### 2.1 The six control-matrix cells (the ONLY performance fixtures) — all CLASS 5

| id | size × curvature | class | expected verdict | role |
|---|---|---|---|---|
| `ctl-12-straight` | 12 Walls (3 Rooms × 4), all `line` | 5 | admitted | control — curvature (straight) at 12 |
| `ctl-12-target` | 12 Walls, only target `w0` cubic-chain | 5 | admitted | control — target-only-curved at 12 |
| `E1C` | 12 Walls, all cubic-chain | 5 | admitted | timing cell — all-curved at 12 |
| `ctl-40-straight` | 40 Walls (10 Rooms × 4), all `line` | 5 | admitted | control — curvature (straight) at 40 |
| `ctl-40-target` | 40 Walls, only target `w0` cubic-chain | 5 | admitted | control — target-only-curved at 40 |
| `E3C` | 40 Walls, all cubic-chain, **no crossing** | 5 | admitted | timing cell — all-curved at 40 |

**All six are CLASS 5, per plan §2.1 — a CLASS 5 fixture is a TIMING INPUT, and every cell here is one.**
The `role` column separates the four controls from the two all-curved timing cells; it does not create a
second class. CLASS 2 is NOT used for the matrix; it is reserved for the distinct post-policy regression
fixtures in §2.2. All six are built by one deterministic committed constructor and measured in ONE
environment, ONE session and ONE sampling configuration (plan §3, A10). Every cell must avoid an
intra-Room self-intersection (the compile's intra-Room rule) and any component-level duplicate Junction
point.

### 2.2 Correctness and regression fixtures (never performance baselines)

| id / set | class | shape | expected verdict (shipped policy) |
|---|---|---|---|
| post-policy regression set — the "must NOT move" containment cases: within-group adoption; a deliberate shared Wall → one rigid group; an invalid boundary inside one connected group; same-component collinear overlap; refusal atomicity | 2 | the P23B.3a decision-record §6 permanent cases, referenced by identity and kept green by the P23B.3a suites | admitted / rejected exactly as the shipped gates produce — this is the set Option E must not relax |
| `N-2` | 3 (Option-E positive) | 40 Walls / 10 Rooms packed so **independent** Rooms' curved boundaries cross (the historical E2 SHAPE) | expected **ADMITTED** — independent-component overlap is permitted geometry |
| CLASS 3 set (F1–F5, F7, and F8's **negative half**) | 3 | independent overlap/coincidence, distinct ids, no implicit join | expected **ADMITTED** — no path other than a deliberate join creates shared topology |
| `N-2i` | 4 (intrinsic negative) | two Walls of **one connected component** whose spans cross away from their shared Junction | expected **REJECTED** — `unsupported_wall_topology`, "cross away from their shared Junction" |
| CLASS 4 set | 4 | self-intersection; invalid boundary inside one connected group; zero-length Wall; malformed Room boundary; duplicate Junction within one component | expected rejected, each with its own code |

**Historical E2 is CLASS 1 EVIDENCE, not a classified fixture.** The archived Pass B observation is the
evidence: the export **imported and compiled without issues**, and its **pre-existing crossing then caused
subsequent, unrelated authoring operations to be rejected** by the old document-wide gate. That is the
record of an *admitted* document becoming difficult to edit — not a fixture rejected at ingestion — and
it is preserved as reported, never rewritten using Option E. IF the payload is ever recovered and its
SHA-256 matches `37a857…dc27f`, its CURRENT executable correctness role is ledgered as a **SEPARATE**
entry — a CLASS 3 positive admission fixture — never as one fixture carrying two classes. Absent
recovery it is evidence only and has no ledger entry.

**The class/polarity correction in one line.** Historical E2 is CLASS 1 evidence of an admitted document
whose pre-existing crossing blocked the NEXT unrelated edit; the constructed `N-2` is a separate,
post-policy POSITIVE correctness fixture; and the admissible **negative** curved-crossing fixture is
`N-2i`, intrinsic to one connected component — never a reused `N-2`.

     shipped policy, supported by committed tests/source at the POLICY level (§7) — not the verified
     verdict of these exact fixtures, none of which has been constructed, and not the verdict of an
     unavailable historical payload. Each one must be ASSERTED by the W2 fixture-contract tests before

     `apps/editor/src/lib/bench/record-baseline.ts` so `contentHash` covers what determines the result.
B-6  METHOD-VERSION AND BUDGET NON-REGRESSION. The 3 → 4 bump changes the baseline's `methodVersion`;
     the deterministic enforced budgets must stay green and must NOT be re-recorded to hide a movement
     (plan R‑5, A8).
B-7  WRITE ISOLATION. `bench:record` must remain the only writer; `npm test` must provably never rewrite
     a checked-in baseline (plan A9). Needs an explicit test, not an assumption.
B-8  HISTORICAL BYTES UNAVAILABLE. Until O‑1 is answered with a matching hash, the 40-Wall case is
     CONSTRUCTED (`N-2`, `E3C`); the archived numbers stay non-comparable context (plan §2, AB‑6).

     component-level duplicate Junction points, or the constructor itself will produce a rejected fixture.

No blocker is a *scope* problem: each is either an owner input (B‑1/B‑2/B‑8), a W1–W5 deliverable
(B‑3/B‑4/B‑5/B‑7) or an existing discipline the slice must honour (B‑6/B‑9).
