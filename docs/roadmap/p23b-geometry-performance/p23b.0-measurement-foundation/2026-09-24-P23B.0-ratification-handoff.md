## 2. Corrected fixture ledger and expected post-policy verdicts

Semantic classes are the plan's §2.1. **"Pinned verdict" is what the SHIPPED gates produce**, verified
from committed source/test bytes (§7); the archived reports' numbers are never re-derived here.

### 2.1 The six control-matrix cells (the ONLY performance fixtures)

| id | size × curvature | class | pinned verdict (shipped) | role |
|---|---|---|---|---|
| `ctl-12-straight` | 12 Walls (3 Rooms × 4), all `line` | 2 | admitted | curvature control at 12 |
| `ctl-12-target` | 12 Walls, only target `w0` cubic-chain | 2 | admitted | isolation control at 12 |
| `E1C` | 12 Walls, all cubic-chain | 5 | admitted | perf cell (E1 role) |
| `ctl-40-straight` | 40 Walls (10 Rooms × 4), all `line` | 2 | admitted | curvature control at 40 |
| `ctl-40-target` | 40 Walls, only target `w0` cubic-chain | 2 | admitted | isolation control at 40 |
| `E3C` | 40 Walls, all cubic-chain, **no crossing** | 5 | admitted | perf cell (E3C role) |

All six are constructed by one deterministic committed constructor, measured in ONE environment, ONE
session and ONE sampling configuration (plan §3, A10). Every cell must avoid an intra-Room
self-intersection (the compile's intra-Room rule) and any component-level duplicate Junction point.

### 2.2 Correctness fixtures (never performance baselines)

| id | class | shape | pinned verdict (shipped) |
|---|---|---|---|
| `N-2` | 3 (Option-E positive) | 40 Walls / 10 Rooms packed so **independent** Rooms' curved boundaries cross (the historical E2 SHAPE) | **ADMITTED** — independent-component overlap is permitted geometry |
| `N-2i` | 4 (intrinsic negative) | two Walls of **one connected component** whose spans cross away from their shared Junction | **REJECTED** — `unsupported_wall_topology`, message "cross away from their shared Junction" |
| CLASS 4 set | 4 | self-intersection; invalid boundary inside one connected group; zero-length Wall; malformed Room boundary; duplicate Junction within one component | rejected, each with its own code |
| CLASS 3 set (F1–F5, F7, and F8's **negative half**) | 3 | independent overlap/coincidence, distinct ids, no implicit join | **ADMITTED** — no path other than a deliberate join creates shared topology |
| `E2-hist` (BRANCH-R only) | 1 + 3 | the recovered historical 40-curved-Wall export, hash-verified against `37a857…dc27f` | historical pre-policy verdict **recorded, never rewritten**; committed verdict **ADMITTED** |

**The class/polarity correction in one line.** Historical E2 (rejected, pre-policy) and the constructed
`N-2` (admitted, post-policy) are two different artifacts with two different verdicts, and the admissible
**negative** curved-crossing fixture is `N-2i`, intrinsic to one connected component — never a reused
`N-2`.

  `serializeWallFirstLayoutDocument` · document shape (rooms/walls/junctions/openings/curved-wall count/
  per-Wall centerline kind) · pinned shipped verdict · semantic class · construction provenance.
  Identity belongs to the FIXTURE; provenance belongs to the MEASUREMENT of it. They stay distinct.

## 5. Blockers to honest baseline recording

These block a *provenance-honest* baseline today. They are the reason the plan asks for ratification
inputs rather than silently recording.

```text
B-1  NO NAMED REFERENCE MACHINE. `deviceProfile` cannot be filled honestly without it; a number from an
     unnamed rig is a report, not a reproducible baseline (plan R‑1, R‑6).
B-2  NO CONFIRMED GESTURE. The owner's original choppy-interaction gesture was never supplied; measuring
     a different gesture would produce a baseline for the wrong symptom.
B-3  REAL-BROWSER ACQUISITION. The recorded browser tier in `apps/editor/src/lib/bench/browser-bench.ts`
     is DOM-free; the gesture and presented-frame measurements (W4) need a real browser + the DEV-gated
     `__P2311_PERF__` marks on `apps/editor/src/routes/dev/perf/bend/+page.svelte`. Until W4 lands and a
     browser is available, no presented-frame claim can be recorded.
B-4  FIXTURE VERDICTS ARE PROPOSED, NOT YET PROVEN. §2's pinned verdicts are derived from committed
     tests/source (§7) but must be ASSERTED by the fixture-contract tests before a baseline is recorded;
     until then no verdict may be claimed in a committed ledger.
B-5  CONTENT-HASH COVERAGE. The new fixture sources must be added to `CONTENT_SOURCES` in
     `apps/editor/src/lib/bench/record-baseline.ts` so `contentHash` covers what determines the result.
B-6  METHOD-VERSION AND BUDGET NON-REGRESSION. The 3 → 4 bump changes the baseline's `methodVersion`;
     the deterministic enforced budgets must stay green and must NOT be re-recorded to hide a movement
     (plan R‑5, A8).
B-7  WRITE ISOLATION. `bench:record` must remain the only writer; `npm test` must provably never rewrite
     a checked-in baseline (plan A9). Needs an explicit test, not an assumption.
B-8  HISTORICAL BYTES UNAVAILABLE. Until O‑1 is answered with a matching hash, the 40-Wall case is
     CONSTRUCTED (`N-2`, `E3C`); the archived numbers stay non-comparable context (plan §2, AB‑6).
B-9  CONSTRUCTION CONSTRAINTS. The all-curved 40-Wall cell must avoid intra-Room self-intersection and
     component-level duplicate Junction points, or the constructor itself will produce a rejected fixture.
```

No blocker is a *scope* problem: each is either an owner input (B‑1/B‑2/B‑8), a W1–W5 deliverable
(B‑3/B‑4/B‑5/B‑7) or an existing discipline the slice must honour (B‑6/B‑9).

## 6. Recommendation — **RATIFY**

**RATIFY the corrected P23B.0-durable plan, contingent only on the owner supplying the two inputs the
plan already requires (O‑1 = BRANCH‑C default, and O‑2 = gesture/snap confirmation + reference machine).**

Supporting evidence:

1. **The contradiction is resolved against shipped behaviour, not against a ruling.** The committed
   validator admits an independent-component curved crossing and refuses an intrinsic same-component one
   (§7). The ledger now mirrors exactly that, and every verdict-bearing fixture pins shipped behaviour
   (plan E‑4/A2).
2. **The plan is bounded and stays measurement-only.** No optimization, no Worker/Rust/WASM, no new
   harness, no new persisted schema, and **no new enforced wall-clock threshold**; all new curved metrics
   are ADVISORY and the existing deterministic budgets are preserved (plan W3/W7/A8).
3. **The remaining gaps are owner inputs and named deliverables, not unresolved design.** §4/§5 list
   them precisely; none requires a further plan edit, and the alternative (FOCUSED RETURN) would only
   restate the same two inputs.
4. **Historical provenance is protected by construction.** Historical E2 keeps its recorded verdict and
   is never a baseline; `E2-hist` identity requires a hash match; constructed fixtures publish their own
   hashes and are never presented as the historical bytes.

**FOCUSED RETURN is not recommended**, because the only defects Stage A found were the E2/N‑2 polarity
and the obsolete status/hypothetical wording — both corrected in place — plus the standing owner inputs
the plan has always required. A return would add a review cycle without changing the work.

**This recommendation is not authorization.** Stage A stops at the ratification gate: no fixture, harness
or baseline is committed, and no P23B continuation branch is created until the owner explicitly ratifies.
