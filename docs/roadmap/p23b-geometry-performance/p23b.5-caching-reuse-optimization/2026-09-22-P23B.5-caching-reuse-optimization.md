## 1. Problem, and the evidence that motivates it

```text
1.1  THE REUSE PATTERN ALREADY EXISTS DOWNSTREAM AND IS ABSENT UPSTREAM (F-P3).
     Working, geometry-identity-keyed reuse:
       · `derivedWallSnapIndex` / `wallSnapIndex`  `packages/layout-core/src/layout-snap.ts:580`
       · `derivedWallMeshes` / `resolveWallMeshes` `apps/editor/src/lib/editor/layout/layout-preview-state.svelte.ts:650`
     Unmemoized: `wallCenterlineSamples` (`layout-wall-centerline.ts:307`) — no cache key and no owner
     object to hang one on. The reuse boundary sits exactly at "has a compiled geometry object".
1.2  CANDIDATE RELEASE MISSES BOTH CACHES BY CONSTRUCTION (F-P9). Each release compiles a NEW
     `CompiledLayoutGeometry`, so geometry-keyed caches miss for the candidate and hit only on baseline
     restore. That is not a broken cache; it is a cache whose key cannot express "this part is
     unchanged".
1.3  THE UNCHANGED PART IS ALREADY SHARED BY REFERENCE (EQ-5). `spliceWallFirstArchitectureCandidate`
     keeps UNAFFECTED Walls and centerlines shared by reference with the baseline. So an artefact
     derived from an unchanged Wall's centerline CAN legitimately be reused across baseline→candidate
     — if it is keyed on that centerline's identity, and if identity implies equality.
1.4  ACCEPTED-COMPILE REUSE IS ALREADY EFFECTIVE, AND ITS PRICE IS DOCUMENTED (F-P7, F-P8). The
     canonical-JSON equality proof costs one whole-document `JSON.stringify` per install — measured
     ≈0.1/0.2 ms (E2). It is the price of a real guarantee and it is a NON-SUSPECT (T-7).
1.5  THE INVALIDATION EDGES ARE NOT WRITTEN DOWN. CI-1 is a harvest table, not a maintained contract.
     Without a recorded graph, P23B.6 and any later slice will invent incompatible keys — which is
     exactly the failure the synthesised direction (P23B.3 §8.2, "which slice owns each shared
     prerequisite") requires this slice to prevent.
```

## 4. Proposed mechanism, and the alternatives

```text
M-3  IDENTITY-keyed reuse for artefacts derived from UNCHANGED inputs.
     Rule (this slice's contribution, written once and consumed by P23B.6):
       An artefact may be reused across baseline→candidate iff
         (a) its key is the IDENTITY of its inputs (never the document), and
         (b) identity is proven to imply equality by a differential test against a from-scratch derive,
         (c) the reuse guard provably REFUSES when (a) or (b) does not hold.
     First application: per-Wall derived samples of UNCHANGED Walls, keyed on
     (centerline identity, traversal, resolved endpoints) — EQ-5's shared-by-reference fact is what makes
     this reachable without a per-document invalidation graph.
     Alternatives considered:
       (i)  per-document memo of the whole derive. REJECTED: the candidate is always a new document, so
            it would never hit where the cost is.
       (ii) content-hash keys over centerline JSON. REJECTED as the primary key: it costs a
            serialization per lookup and adds `cache-key-code-units` pressure (RL-3) for a hit rate no
            better than identity, given EQ-5.
       (iii) a new editor-level cache object. REJECTED: derived geometry in editor state creates
            pressure toward a second geometry truth.
LIFETIME POLICY (RL-1/RL-2).
     · chain-scoped by default; nothing derived retains a DOCUMENT object.
     · `WeakMap` keyed on the input object is the established pattern here (`layout-snap.ts:578`,
       `layout-preview-state.svelte.ts:630`) and is the model to imitate for any object-keyed store.
     · history/undo restore a PREVIOUS document object; identity-keyed reuse is safe exactly while the
       restored object IS the same object (which is why baseline mesh reuse works today). The slice must
       pin that assumption with a test rather than inherit it silently.
WHAT IS DELIBERATELY NOT DONE
     · no change to the accepted-compile proof: a cheaper identity than canonical JSON would have to
       cover every compiler input, and the current proof is not a measured cost (T-7, Q7 stays a
       P23B.2 question).
```

## 5. Correctness invariants and equivalence proof obligations

```text
INV-1  Reuse never changes an output: reused artefact ≡ from-scratch derive (geometry, model, issues,
       bounds) on the committed fixtures.
INV-2  Every reuse guard can REFUSE; a guard that cannot refuse is unsafe by construction.
INV-3  No artefact is keyed on a document when its inputs are sub-document (and vice versa).
INV-4  The two existing geometry-keyed caches keep their current keys and behaviour.
INV-5  No derived geometry is stored in `LayoutDocument`/`SceneDocument` or editor reactive state.
INV-6  Cache lifetime does not retain a replaced document (teardown proven, not assumed).
INV-7  `cache-key-code-units` and `compiled-memory` (ENFORCED) do not regress without an explanation.
       A regression must not be silenced by re-recording the budget.
OR-5   identity⇒equality + refusal, for every reuse this slice adds (the P23.11 pattern in
       `apps/editor/tests/lib/bench/bend-perf.test.ts` is the template: equivalence test first, cost
       test second, and the guard proven to refuse an unproven document).
OR-6   non-mutation of the checked-in baseline, and no baseline write from `npm test`.
OR-8   LIFECYCLE: after document replacement, undo/redo and baseline restore, (a) no stale artefact is
       served, (b) the caches do not retain the previous document (teardown observable).
OR-7   Plan/3D/visitor parity + visitor bundle gate.
```

## 8. Regression and resource-lifetime risks

```text
R-1  A key that omits traversal silently mirrors geometry (S-2 of P23B.3). The key grammar must state
     traversal explicitly.
R-2  A key that omits resolved endpoints can serve samples derived from moved endpoints. If P23B.4's
     finding shows reconciliation can move Junction points, endpoints must be in the key.
R-3  Document retention via a strong reference in a long-lived map (synthesis RL-1/RL-2). Mitigation:
     `WeakMap` on the input object, chain-scoped default, and the OR-8 teardown test.
R-4  `cache-key-code-units` is ENFORCED (620,268 code units for Chopin at the recorded baseline; target
     700,000 / fail 1,300,000). Storing key strings per Wall/traversal at authoring density must be
     measured against it. Re-recording a budget to silence a failure is forbidden.
R-5  A reuse that cannot refuse (INV-2/OR-5) is unsafe by construction: it can serve a stale artefact
     after a document change the guard never observed.
R-6  Undo/redo restores previous document objects. Identity-keyed reuse is only correct while the
     restored object is the same object; the slice must pin that with a test, because it is an
     assumption `restoreLayoutPreviewSnapshot` currently relies on implicitly.
R-7  Interaction with P23B.4's threaded context: two derivations (chain-scoped and reused) must not
     disagree. One grammar, one owner.
R-8  Measurement perturbation: hit/miss counters must not themselves be hot-path work (a counter in the
     inner loop changes what it measures).
```
