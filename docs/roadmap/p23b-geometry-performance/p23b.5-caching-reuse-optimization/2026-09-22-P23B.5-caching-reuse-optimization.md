## 2. Scope and boundaries

Deliver one key/invalidation/lifetime contract plus focused executable proofs.
M-3 is conditional sample reuse, not a promised release optimization. No new
cache is authorized merely by the shallow-splice observation. Keep the existing
chain-scoped derivation if the opportunity does not survive S0.

Preserve P23B.4's accepted threading, independently derived reverse traversal,
extent pruning, and fresh-sampling fallback. Preserve Option E and P23B.3a's
D-12 reconciliation proof: connectivity uses explicit Junction identity;
coordinate coincidence never establishes entity identity. Room reconciliation
is not an extra sampler input when its actual sampling inputs remain unchanged.

Out of scope: weakening cloning or canonical validation; replacing either
WeakMap or the canonical-JSON proof; content-hash interning; generation counters;
per-document caches; derived geometry in documents or editor reactive state;
a second evaluator/key grammar; incremental compile; topology-policy changes;
mesh/adapter caching, disposal or dependency implementation (P23B.6); Worker/WASM
(P23B.8); new budgets. Do not reopen P23B.3a/P23B.0/P23B.4.

## 3. One key and equality contract

The landed grammar is centerline OBJECT identity + traversal + resolved
canonical endpoint coordinates at full precision. Retain all those dimensions;
reverse remains independently derived. Coordinate values are dependencies
within an identity key, never a substitute for identity.

Before widening reuse, complete the SAME `WallSamplingDerivation` contract for
its full returned artefact: require matching Wall id (`segmentId`) as a key
dimension or an explicit refusal guard. Prefer that bounded completion over
splitting out a second metadata-free sample cache. A synthetic alias test must
use two Wall ids with the same centerline object and endpoints and compare the
entire returned `SampledSegment` with fresh results. Canonical parsing currently
separates those objects; this is a demonstrated API hazard, not evidence that
landed normal release operations already return wrong Wall metadata.

Identity implies equality only while ALL sampled input data is unchanged:
centerline kind, knots/points and span controls, resolved endpoints, traversal
and Wall id. The current API/types do not enforce deep immutability. S0 must
trace writers and aliases at the proposed lifetime, prove inputs cannot mutate
there or specify bounded mutation detection with refusal. Returned samples,
points, tangents and normals must remain unmodified by consumers. Tests must
cover input alias mutation and output contamination; do not infer safety from
an unchanged top-level reference or a TypeScript readonly annotation. If this
needs a document-wide mutation/ownership redesign, abandon M-3.

Sampling options are FIXED on this path: `wallCenterlineSamples` calls
`sampleSegment` without options (flatness 0.01, span 0.25, maxDepth 12,
maxSamples 100,000). There is no runtime options dimension to key or vary today.
Pin this call path/default policy; do not expose options to satisfy a test.
Any future configurable policy must extend the same grammar before sharing.

An adjacent Wall or Opening edit is not automatically a sample-cache refusal:
if a shared Junction moves, resolved endpoints change and reuse must refuse;
if every sample input remains identical and the same permitted store is reached,
reuse should hit and equal a fresh derivation. Changed centerline identity may
legitimately miss despite equal values. These sample rules do not establish
mesh equivalence. P23B.6 owns the wider Junction/adjacency/Opening/dimension/
material dependency cone (OR-9b / G15).

## 4. Ownership and lifetime

Current exact owner: the local `sampling` value in
`finalizeWallGeometryCandidate`, or the derivation created by each
`preflightWallFirstArchitectureCandidate` call. The former lasts through the
synchronous acceptance chain; the latter through that preflight. Neither is
returned in the plan/acceptance or retained by editor state. Its strong Maps
become unreachable when the call and consumers release them; this is an
ownership argument, not a deterministic garbage-collection claim.

S0 must name any proposed longer-lived owner, its construction site, caller
threading, allowed scope and every termination/reset path BEFORE S4. A bounded
non-reactive operation/gesture owner is only a candidate, not an approved new
editor cache. Its design must cover success, rejection, cancel, replacement,
undo/redo and disposal, and must not retain document objects through values,
keys, closures or diagnostic collectors. If no narrowly scoped owner can serve
real repeated calls safely, keep the current owner and drop M-3.

The two existing WeakMaps stay module-owned and geometry-keyed. History may
legitimately keep geometry and derived resources reachable; restoring a source
clone neither proves nor invalidates their geometry identity. Test reuse and
stale-result behavior, explicit owner resets and any enumerable store's bounded
entries. Never claim WeakMap population counts, deterministic GC, or that all
artefacts must die on document replacement. Mesh disposal counts and GPU
ownership remain P23B.6's responsibility.

## 6. Acceptance and abandonment

OR-5: complete-result equality and meaningful refusal, including Wall metadata
and mutation hazards. OR-9: both refusal and real hit directions, conditional
on a reachable S0-approved reuse boundary; unrelated metadata/mesh inputs must
not manufacture refusals. A dropped M-3 has no fabricated cross-chain hit gate.
OR-8/10/11: lifecycle behavior, baseline integrity after rejection and bounded
explicit ownership under repeated edit/undo/redo; no deterministic GC claims.
OR-6: checked-in baseline unchanged. OR-7: Plan/3D/visitor parity and isolation.
OR-9b remains a P23B.6 handoff, not this slice's acceptance test.

For implementation, run the full applicable repository verification owned by
`apps/editor/tests/README.md`: complete test/lane union, unconditional arch,
perf, check and both-app build/visitor gate. Preserve P23.11 equivalence and
accepted-compile assertions, and P23B.4 consumer/pruning proofs. This plan-only
reconciliation needs document/diff checks, not a claim of new runtime acceptance.

Keep enforced `cache-key-code-units` and `compiled-memory` gates unchanged.
Measure additional runtime sample-store/key retention separately: compiled
record size counters do not automatically account for a new sample store.
Never re-record the baseline or relax gates to hide a regression.

Abandon M-3 implementation if no useful real cross-chain identity reuse is
reachable; if it requires broad cloning, canonical-validation or ownership
changes; if identity/mutation/metadata/refusal safety cannot be proved; if the
owner retains documents or has unbounded growth; or if measured overhead defeats
the demonstrated saving. Keep the contract and current chain-scoped M-1 with an
explicit dropped disposition. Do not substitute hashes, interning, a second
cache, weaker validation or revived M-2b to manufacture success.

Exit requires recorded S0 disposition, applicable proofs/verification, direct
stage counts and their limits, one contract for P23B.6, and owner acceptance
before routine slice-closeout. No major-phase closure is implied.
