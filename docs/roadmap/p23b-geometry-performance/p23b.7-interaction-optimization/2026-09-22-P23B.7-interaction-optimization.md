## 1. Problem, and the evidence that motivates it

```text
1.1  THE PROPOSAL HALF IS ALREADY AFFECTED-SUBSET; THE PREFLIGHT HALF IS WHOLE-DOCUMENT (F-P5/F-P12).
     `transientArchitectureEdit` (`apps/editor/src/lib/editor/layout/layout-transient-edit.ts:130`)
     samples only the edited Wall through `proposeWallFirstArchitectureGeometry`, then runs
     `preflightWallFirstArchitectureCandidate` (`:148`) →
     `validateWallFirstTopology` (`layout-wall-first-precision.ts:1732`), which scans ALL Junction pairs,
     classifies ALL Wall pairs with the chord gate and samples EVERY curved Wall — PER POINTER MOVE.
1.2  THE PREFLIGHT'S INPUT IS A CONSTANT FOR THE WHOLE GESTURE — VERIFIED IN SOURCE.
     The call passes the **frozen pointer-down baseline** ("The frozen pointer-down baseline document —
     never the live preview", `layout-transient-edit.ts:132-134`), and
     `spliceWallFirstArchitectureCandidate` (`layout-wall-first-precision.ts:1052`) is a **shallow**
     splice: changed records are replaced, everything else is shared by reference. The document itself
     does not change during a drag; only the patch's affected records do.
     ⇒ The work that scans pairs BOTH of whose members are outside the patch is re-deriving a verdict
       that cannot have changed, on every single pointermove.
1.3  THE PREFLIGHT IS ALLOWED TO MISS BUT MUST NEVER BE WRONG. Its own contract states it is "sound by
     construction ... so a failure here is a failure at release too. A miss is merely pending, never
     wrong" (`layout-wall-first-precision.ts:1081-1092`). Any scoping must preserve exactly that
     asymmetry: it may decline to refute, but it must never produce a `pending` status where the current
     code produces `known-invalid` for a pair the gesture actually affected.
1.4  HIT-TEST AND SNAP ARE CHEAP BUT PER-FRAME (F-P11, M-2 of P23B.3). 200 Plan hit queries measured
     13.8/14.0 ms (E1) and 23.9/24.5 ms (E2) ⇒ ≈0.07–0.12 ms per query; warmed snap ≈0.2/0.4 ms. Neither
     is a leading suspect, and the snap index is already memoized by geometry identity.
1.5  THE INSTALL SEAM IS UNTAGGED (UN-1). `adapter-plan-apply` → `preview-install` is the untagged gap;
     the reactive re-render cost is unmeasured (UN-2).
1.6  THE CONFIRMATION THAT NO GESTURE SEMANTICS MAY CHANGE. Deterministic selection and history are
     product contracts; a drag's cost is not a reason to alter what is committed, when, or how it is
     undone.
```


## 4. Proposed mechanism, and the alternatives

```text
M-2 (per gesture)  GESTURE-SCOPED CANONICAL PREFLIGHT.
     Split the preflight's verdict set into:
       (a) GESTURE-INVARIANT pairs — pairs neither of whose members the patch can move. Their verdict is
           computed ONCE at gesture start (or on the first derivable move) against the frozen baseline
           and reused for every subsequent pointermove;
       (b) GESTURE-AFFECTED pairs — everything whose extent the patch can enter, plus the affected
           Wall(s) themselves. Recomputed per move through the SAME canonical gate and the SAME
           predicate.
     Why this preserves the contract: (a)'s verdicts are derived from inputs that provably did not
     change (the shallow splice replaces only the patch's records), so a reused verdict is the same
     verdict; (b) is always evaluated, so no pair the gesture affected is skipped. The preflight keeps
     its "failure here is a failure at release / a miss is merely pending" asymmetry unchanged.
     ALTERNATIVE (i): a full cached verdict map keyed per pointer move — rejected: it caches what changes.
     ALTERNATIVE (ii): Room-local scoping — REJECTED outright; F-C3 is the counterexample that makes
       locality unsound for exactly this gate.
     ALTERNATIVE (iii): leave the preflight whole-document and only thin the proposal half — rejected as
       the primary direction because F-P5 shows the preflight is the growing per-move term, but it is the
       FALLBACK if OR-3 cannot prove equality (synthesis §8.6 AB-2).
EFFECT-FREE-UNTIL-PROVEN RULE
     Land the mechanism so that an un-scoped call path still behaves exactly as today; the scoping is
     supplied by the caller (the gesture), never silently inside the canonical gate.
PRESENTATION (only if measured)
     the untagged derive/install gap and the reactive re-render are measured first (P23B.0-durable),
     and only then may this slice touch them.
NOT PROPOSED
     no change to hit-test priority, snap candidates, selection or history; no debouncing of pointermove
     that drops frames of feedback; no moving gesture work off the main thread (P23B.8).
```

## 5. Correctness invariants and equivalence proof obligations

```text
INV-1  IDENTICAL VERDICT AND STATUS. For any gesture, the scoped preflight's returned failure (or
       `undefined`) equals the whole-document preflight's for the same patch — including the code and
       message. A `pending` must never replace a `known-invalid` that today's code produces.
INV-2  No pair the patch can affect is ever skipped (the extent rule is conservative, not tight).
INV-3  The one crossing authority remains `detectWallCurveTopologyCrossings`; scoping changes WHICH
       PAIRS are evaluated, never the predicate.
INV-4  Gesture semantics unchanged: at most one planner call per release; exactly one of commit/cancel;
       exact baseline restored on refusal; no history entry for a refused or sub-threshold release.
INV-4b (Option E revision) A drag never creates, removes or re-targets CONNECTIVITY. No gesture may join
       two independent groups, share a Junction between them, or leave the document with a connectivity
       change the creator did not explicitly request — regardless of how much the groups overlap.
INV-5  Selection/history determinism unchanged; no new persisted or generated state.
INV-6  Hit-test and snap behaviour unchanged unless a measurement names them.
INV-7  Plan/3D/visitor parity; no editor code in `layout-core`; visitor bundle gate green.
OR-3   full vs scoped preflight on: (a) committed E1/E3(C), (b) a patch edited toward an inter-Room
       crossing (F-C3 shape), (c) a baseline that ALREADY carries a crossing, (d) a patch that produces
       self-intersection / duplicate junction points / a zero-length Wall — identical verdict+code+message
       in every case. THE EXISTING FULL PREFLIGHT IS THE ORACLE (P23B.2 §Q3/§E: use exhaustive
       validation as the differential oracle), and the emitted ISSUE ORDER must also match, not only the
       verdict.
OR-4   atomicity of refusal (RT-1 R-b): a refused release leaves document, identity, history and preview
       state unchanged. This is P23B.2 §E's independent requirement verbatim ("Unchanged document,
       selection and history after refused operations").
OR-8   gesture lifecycle: pointerdown → many moves → cancel and → release both end with no residue and
       no stale gesture-scoped state; two consecutive gestures on different Walls do not share a verdict;
       an overlapping/rapid gesture sequence must not let one gesture's scoped state answer for another.
OR-7   parity + bundle gates.
OR-9   (NEW, from P23B.2 §E) CROSS-ROOM IS MANDATORY IN THE CASE SET: the differential set must include
       edits that change a Wall's relationship to a Wall in ANOTHER Room and edits to CONNECTED
       JUNCTIONS, because "Room-local tests alone are insufficient" — the same warning F-C3 makes from
       our own code.
OR-10  (NEW, from the same principle) REJECTED-EDIT RESTORATION: after a refusal the frozen baseline is
       reinstated EXACTLY and no gesture-scoped verdict survives into the next gesture.
```

## 6. Implementation steps (each independently committable and reviewable)

```text
REFERENCE-FIRST RULE (same rule as P23B.4; a step that violates it cannot merge)
    No oracle may be merged that requires code which does not exist yet, and no mechanism may be merged
    without its green oracle in the SAME commit. OR-3 is written as "scoped preflight vs the current
    whole-document one", which cannot be green before the scoped preflight exists. So the reference is
    frozen first (S2) from TODAY'S whole-document behaviour, and the COMPARISON is added by the step that
    introduces the scoped path (S4), in that commit.
S1  MEASURE PER GESTURE (no production change)
    On the committed fixtures, report: per-move proposal, per-move preflight, the untagged
    derive/install gap, reactive re-render and the release chain — each separately, with mark nesting
    stated. This decides whether the preflight is still the per-move term after P23B.4.
S2  FREEZE THE REFERENCE — TODAY'S WHOLE-DOCUMENT VERDICTS (tests only)
    Record the current whole-document preflight's verdict, issue code, message and ISSUE ORDER for all
    four OR-3 cases (a)–(d), plus OR-8's lifecycle baseline. Green on landing, because it asserts today's
    code. This frozen set IS the oracle side of the later differential: nothing scoped may be compared
    against another scoped variant.
S3  AFFECTED-EXTENT DERIVATION
    Compute the gesture's affected extent from the patch (which Walls/Junctions the intent can move),
    conservatively, in `layout-core` beside the splice. Unit-test it against pathological intents
    (junction move, wall move, bend insert, knot move/delete).
S4  GESTURE-INVARIANT VERDICT SET AT GESTURE SCOPE
    Compute the invariant part once per gesture; evaluate the affected subset per move. Tests, IN THIS
    COMMIT: OR-3's whole-document comparison against S2's frozen reference (all four cases, verdict +
    code + message + issue order), OR-8, the transient-preview and transient-allocation suites, and the
    gesture suites (`layout-wall-edit-gesture`, `layout-lifecycle-semantics`). The scoped path may not
    merge without that comparison in the same commit.
S5  (CONDITIONAL) HIT-TEST / SNAP WORK — only if S1 names them.
S6  (CONDITIONAL) PREVIEW-INSTALL / REACTIVE WORK — only if S1 names them; belongs here rather than in
    P23B.6 because it is per-gesture, not per-frame.
S7  RE-MEASURE AND RECORD
    Same fixtures, same provenance block; report the per-move and per-release numbers that moved, and
    those that did not.
```

## 8. Regression and resource-lifetime risks

```text
R-1  A scoped preflight that MISSES a genuine failure changes visible feedback from "known-invalid" to
     "pending" (the drag renders as if fine, the release then rejects). That is a UX/semantics
     regression even though the release verdict is unchanged. OR-3 case (b) is the guard.
R-2  A reused NEGATIVE verdict on a baseline that ALREADY carries a crossing (OR-3c) is where the
     curved-crossing ruling enters — but a ruling does not change the validator (decision record §4.1).
     The test is what the SHIPPED gates do with such a baseline, and reuse is admitted only if
     equivalence is proven against the current FULL validator AND the shipped behaviour yields a stable
     verdict to reuse. A "reject at ingress" policy that has not landed leaves today's admission in
     place, so the reuse must be re-derived, not inherited (synthesis §8.6 AB-3).
R-3  Gesture-scoped state must not outlive the gesture (OR-8). A map keyed on a patch or a Wall that
     survives across gestures can serve a stale verdict for a DIFFERENT baseline.
R-4  The shallow splice shares records by reference with the baseline. Any scoping that assumes
     "unaffected means untouched" must rely on that splice's guarantee, not on the live preview being
     unchanged — the live preview changes on a genuine multi-step gesture.
R-5  Mark nesting: adding marks inside the preflight could double-count `preflight`/`preflight-topology`
     and make the advisory numbers unreadable.
R-6  Debouncing or coalescing pointermove work would change the drag's response even if it reduced cost;
     it is out of scope unless the owner accepts the interaction change explicitly.
R-7  Selection/history: a refused release must remain atomic and produce no history entry (INV-4/OR-4).
R-8  Reactive cost (UN-2) may dominate; if so, record it rather than optimizing a smaller term.
```
