## 1. Why this slice exists, and why it is last among the optimisation slices

```text
1.1  THE ENTRY CONDITION IS STRUCTURAL, NOT OPTIONAL (T-9 reason 2). The algorithmic and TypeScript
     opportunities are substantial and were UNIMPLEMENTED when P23B began: the same Wall's centerline is
     derived by four consumers per release (≈280 sampling operations on the all-curved case, F-P2), the
     preflight is whole-document per pointer move (F-P5), and the candidate re-derives everything it
     touches (F-P9). Rewriting the language before doing that work would optimize the wrong layer.
1.2  NO MEASURED COMPUTE-BOUND HOT PATH EXISTS YET (T-9 reason 1). The only measurements are two
     read-only passes on uncommitted documents in DIFFERENT environments with nested marks (M-2/M-4/M-5).
     That evidence base cannot justify a rewrite. The durable P23B.0 baselines are a prerequisite.
1.3  THE ONE-TRUTH INVARIANT IS THE HARD CONSTRAINT (T-9 reason 3). A WASM core would sit under the one
     canonical compiler/sampler. The umbrella requires exact result equivalence as a TESTED obligation
     and forbids a second source of compiled geometry.
1.4  A WORKER IS A DIFFERENT QUESTION WITH A DIFFERENT COST (T-8). It removes a synchronous block from
     the main thread; it does NOT reduce total work, it adds transfer cost, and the acceptance chain is
     sequential (structural-pre → topology-pre → face → reconcile → structural-post → topology-post →
     opening/portal → compile → install), so only a narrow slice is isolatable. It must therefore be
     judged on what REMAINS, not on what was measured at the start.
```

## 4. The evaluation (decision procedure, not a survey)

```text
D-0  IS THE SLICE EVEN OPEN? (gate)
     The entry condition is met only if, AFTER P23B.4–P23B.7, a stage remains that is (a) material to the
     demonstrated symptom and (b) measured as COMPUTE-BOUND rather than DOM/render/runtime-bound.
     If not met, the slice closes with D-A = not justified and D-B = not justified, each citing the
     measurement and the unmet entry condition (synthesis §8.6 AB-7). NO further enquiry is performed —
     a rewrite proposal without a measured hot path is not an evaluation, it is a preference.
     Expected outcome: this gate fails. Say so plainly.

D-A0 SUPERSEDED-RESULT ORDERING — A PRECONDITION, NOT A SUB-QUESTION (NEW from P23B.2 §Q8)
     The research identifies a correctness hazard this phase had not stated: as soon as acceptance can
     complete ASYNCHRONOUSLY, a result can arrive after the candidate it belonged to has been superseded.
     The required shape, adopted verbatim as an obligation:

       Baseline B  →  Candidate A starts  →  Candidate C supersedes A  →  Result A arrives
                                                                            ↓
                        A must NOT replace C, must not install stale geometry,
                        must not create a history entry, must not alter selection
     Therefore ANY asynchronous path requires: (a) a DOCUMENT REVISION / CANDIDATE TRANSACTION IDENTITY
     carried with every result; (b) SUPERSEDED-RESULT REJECTION on arrival; (c) an explicit CANCELLATION
     decision — ignoring an obsolete result prevents stale installation but does NOT stop its CPU work,
     while `Worker.terminate()` stops the work but discards reusable Worker state; (d) tests for
     OVERLAPPING GESTURES and for WORKER FAILURE/termination.
     This is independent of which library (if any) is chosen, which is why it belongs in the decision
     record even when the answer is "not justified", and why it RAISES THE BAR for admitting async
     acceptance: the phase's determinism requirement (selection/history) is not free to absorb a new
     ordering invariant just to move a block off the main thread.

D-A  WORKER DECISION (only if D-0 passes, and D-A0's obligations are accepted first)
     Must answer, with numbers:
       (a) which stage is isolatable under the sequential acceptance chain (T-8(b)) — P23B.2 §Q8 supplies
           the stage table: compile · topology validation · face extraction · CPU-only mesh preparation
           PLAUSIBLE; Svelte state installation, Threlte scene integration and GPU upload/presentation
           NOT solved by a compiler Worker;
       (b) the transfer cost of the isolatable value (structured clone of compiled geometry: walls +
           samples + junctions) measured against the main-thread time it removes;
       (c) whether the interactive edit can genuinely proceed asynchronously, given a release must be
           committed on pointerup, or whether the Worker only moves a block rather than removing it;
       (d) bundle/ownership cost: a Worker chunk must NOT pull editor-only code into visitor bundles
           (`visitor-import-boundary`, `wall-mesh-shell-boundary` stay green);
       (e) the "one compiler / one truth" position: a Worker must call the SAME compiler, never hold a
           second copy of its logic.
     DECIDE: justified / not justified, with the measurement. Either close is a success.

D-B  RUST/WASM DECISION (only if a compute-bound hot path REMAINS after D-A)
     Must answer, in this order:
       (1) which function(s), and the measured share of the demonstrated symptom they carry;
       (2) the equivalence contract: exact result equality against the TypeScript path, asserted by a
           differential test on the committed E1/E3(C) fixtures + the control matrix, INCLUDING
           degenerate cases (zero-length walls, self-intersecting chains, curved rooms, openings);
       (3) the one-truth position: the WASM core sits UNDER the canonical entry, with the TypeScript path
           retained as the reference implementation of record — NOT a second pipeline, and not a
           surface-dependent implementation;
       (4) toolchain/build-target impact for contributors and deploys (the umbrella forbids a MANDATORY
           change; an optional, verified-equal alternative would still need an owner call);
       (5) bundle impact and the visitor boundary;
       (6) maintenance ownership: who keeps two implementations equal, and what happens on divergence.
     DECIDE: justified / not justified. "NOT JUSTIFIED" IS THE EXPECTED DEFAULT and requires no
     apology — it needs the measurement that produced it.
     HONEST LIMIT (required in the record): state explicitly what the equivalence guard does NOT prove —
     e.g. that it covers only the committed fixtures and the exercised option range, not every input;
     that equal outputs on fixtures do not prove equal behaviour on inputs with no fixture; and that a
     passing differential test is not a proof of semantic identity.
```

## 5. Correctness invariants and proof obligations (if any adoption were decided)

```text
INV-1  ONE geometry truth. Whatever else is decided, `LayoutDocument → one compiler → Plan/3D/visitor`
       is unchanged; no surface may consume a different implementation than another.
INV-2  Exact-to-exact equivalence with the TypeScript path, TESTED on committed fixtures + degenerate
       cases, not assumed.
INV-3  No MANDATORY toolchain, build-target or contributor-workflow change.
INV-4  Visitor isolation preserved; the bundle guard's own coverage limits stated honestly.
INV-5  Determinism and identity preserved: the same inputs produce the same compiled geometry and the
       same issues/diagnostics ordering.
INV-6  No new persisted format, schema or document state.
INV-7  (NEW) DETERMINISTIC ACCEPTANCE UNDER ANY ASYNCHRONY: a superseded result never installs, never
       creates history and never alters selection; the installed document is always the result of the
       LATEST accepted candidate transaction.
INV-8  (NEW) ONE IMPLEMENTATION, also for Workers — P23B.2 §Q8: "a Worker should execute the same
       canonical implementation, not a separately maintained approximation." A Worker is a thread, never
       a second compiler.
OR-1'  the differential equivalence test above, as an EXECUTABLE gate (not a one-off script), including
       the degenerate cases and both traversals.
OR-7   Plan/3D/visitor parity + visitor bundle gate + `test:arch`.
```

## 7. Acceptance criteria

```text
A1  The residual-cost ledger exists and cites measured numbers with provenance, not the historical passes.
A2  D-0 is answered explicitly; a FAIL is a successful outcome and must not trigger further enquiry.
A3  D-A and D-B are each recorded as justified / not justified WITH the measurement or the unmet entry
    condition that produced the answer — and D-A0's obligations are RECORDED either way, so a later
    phase that introduces asynchrony for any reason inherits them instead of rediscovering them.
A4  If either is "not justified", the record states the entry condition that would open it again and
    which measurement would have to change — so a later phase re-opens it on evidence, not on mood.
A5  If either is "justified", the equivalence contract, boundary, toolchain/bundle impact and honest
    limits of the guard are written before ANY implementation is authorized (and the implementation
    itself is a new, owner-authorized slice — not this one).
A6  No product code path changed unless a decision positively required it, in which case the change is
    its own commit with its own OR-1'/OR-7 evidence.
A7  Nothing in the phase claims a Rust/WASM or Worker migration occurred; "not justified" is recorded as
    the outcome, not as unfinished work.
A8  Slice closed on the same branch; slice-closeout applied.
```

## 8. Risks

```text
R-1  OPTIMISM DRIFT. The failure mode this slice exists to prevent: opening a rewrite because the phase
     FEELS slow rather than because a measurement names a compute-bound path. D-0 is the guard, and a
     FAIL must be respected. P23B.2 reaches the same position for Workers independently — "a credible
     later experiment, not an established first optimization" — and for Rust/WASM: no evidence shows
     either beats "removing duplicate work, reducing unnecessary pair checks or reusing unchanged
     artifacts".
R-1b STALE-INSTALL REGRESSION (NEW, from P23B.2 §Q8). If async acceptance is ever admitted, the
     superseded-result hazard becomes a live correctness risk in a pipeline whose selection and history
     determinism is a product contract. D-A0 exists so it is designed for, not discovered.
R-1c LATENCY ILLUSION (NEW). A Worker does not reduce total work, and P23B.2 notes transfer cost, Worker
     startup, serialization and main-thread installation remain part of interaction latency. An
     "isolation" result must be measured end-to-end, not by main-thread block duration alone.
R-2  EQUIVALENCE THEATRE. A differential test that covers only the fixtures it was written against
     proves little. The honest-limits statement (D-B(6)) is mandatory.
R-3  DOUBLE MAINTENANCE. Two implementations drift; the record must name an owner and a policy before
     adoption, or the answer is not justified.
R-4  BUNDLE/ISOLATION LEAK. A Worker or WASM chunk is a new boundary through which editor-only code can
     reach the visitor. The boundary tests are the guard, and their coverage limits must be stated
     (AGENTS.md rules; the umbrella's visitor-safe requirement).
R-5  MEASUREMENT POLLUTION. A residual ledger compiled from ADVISORY wall-clock numbers on a developer
     machine is weak evidence. State the environment; prefer deterministic counts (call counts, sample
     counts) where they carry the argument.
R-6  SCOPE CREEP INTO CAPABILITY. A Worker/WASM path is infrastructure, not capability; it must not
     become the vehicle for a new feature or a new architecture.
```

## 9. Exit criteria

```text
X-1  A1–A8 satisfied.
X-2  The owner has ratified the decision record (in the expected case, a negative finding).
X-3  The rationale for NOT pursuing a rewrite is durable: a later phase can re-open it on the recorded

X-4  Slice closed on the same branch with an identifiable commit series.
```
