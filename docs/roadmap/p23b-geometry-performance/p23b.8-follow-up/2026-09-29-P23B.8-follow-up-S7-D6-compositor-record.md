## First check: does `devtools.timeline` carry the compositor events?

NO. Grep over the retained `nameCounts` of **all fifteen** local-only legs
(Chrome 152 headless + Electron 35, M1 / restore-split / arms / label-arms /
all nine grid legs — same method as the plan's first check):

- 144–152 distinct trace event names per leg;
- the ONLY compositor-ish name anywhere is `AnimationFrame::Presentation` —
  the presented-frame *instant marker* the runner already uses as its signal,
  not a stage duration;
- NO `CompositeLayers`, NO `DrawFrame`/`BeginFrame`, NO raster tasks, NO
  GPU/swap/vsync/present-stage events, on either runtime.

Per the plan, S7 therefore **reports that absence instead of pricing**.

## What this means

The compositor/raster/present stages cannot be priced from this harness: the
traced category does not emit them in the headless/offscreen setup. The
post-release tail (43–78 % of the window after the page's last attributed
mark) stays what the window-attribution pass proved it is — ~96–97 % page
JavaScript inside one Svelte runtime task per release — with the remainder
unmarked work no `devtools.timeline` event names. Pricing the true composite
stages would need a new tracing category or surface, which is a NEW named
item for owner routing — **none is proposed here; nothing else is built**.
