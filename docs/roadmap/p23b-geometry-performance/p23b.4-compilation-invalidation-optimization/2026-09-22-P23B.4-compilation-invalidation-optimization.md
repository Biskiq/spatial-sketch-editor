## 1. Problem, and the evidence that motivates it

```text
1.1  DUPLICATE DERIVATION (M-1). On the all-curved 40-Wall case the SAME Wall's canonical centerline
     is sampled by four active consumers per release — topology-pre 40 + face extraction 80 +
     topology-post 40 + acceptance compile 120 ≈ 280 sampling operations — all through
     `wallCenterlineSamples` (`packages/layout-core/src/layout-wall-centerline.ts:307`) with NO shared
     representation (F-P2). Face extraction pays twice per curved Wall because it samples BOTH half-edge
     directions, including the discarded negative-area outer ring.
1.2  SAMPLING OPTIONS ARE ALREADY EQUIVALENT (S-1, closing harvest UN-5). `wallCenterlineSamples`
     passes NO options to `sampleSegment` (`layout-geometry-curve.ts:384`), and no consumer in the tree
     overrides them. ⇒ The obstacle to sharing is NOT configuration. It is exactly three things:
     traversal (S-2), input endpoints/document identity (EQ-1), and array equality rather than
     near-equality (EQ-3).
1.3  WHOLE-DOCUMENT VALIDATION PER INTERACTION (M-2). The transient preflight is whole-document for a
     single-Wall gesture — all Junction pairs, all Wall pairs, every curved Wall sampled, PER POINTER
     MOVE (F-P5) — and the structural + topology pair runs twice per release with nothing scoped to what
     reconciliation changed (F-P6).
1.4  WHY SCOPING MUST BE EXTENT-BASED, NOT LOCAL. The crossing rule is all-pairs by design and carries
     no notion of the edited Wall. Room-local reasoning is provably insufficient: a Room duplicate that
     translates a curved Wall into a crossing with a Wall OUTSIDE its own Room is admitted today (F-C3).
     A sound scope is therefore "which pairs can have CHANGED relationship", which is an extent/AABB
     argument, plus (conditionally) reuse of verdicts that did not change.
```

## 4. Proposed mechanism, and the alternatives

```text
M-1  ONE DERIVATION PER WALL PER RELEASE, PROVIDED EXPLICITLY.
     Preferred: `finalizeWallGeometryCandidate` (`:1512`) constructs ONE derivation context for the
     candidate document and threads it into the topology gates, face extraction, the Opening set and
     the compile. The context derives a Wall's samples once per (centerline identity, traversal,
     resolved endpoints) and returns THE SAME array object to every consumer.
     Why explicit threading over the alternatives:
       (a) no global/`WeakMap` module state ⇒ no document retention (RL-1) and no lifetime ambiguity;
       (b) the key grammar is visible at the call sites that must document it;
       (c) it is testable without reaching into module internals.
     Alternatives, and why not first:
       (i)  memoize inside `wallCenterlineSamples` with a module `WeakMap` keyed on the centerline
            object. Cheapest to write; rejected as the FIRST move because it silently changes every
            caller including tests and callers outside the acceptance chain, and because a module-level
            memo is exactly the resource-lifetime risk RL-1 names. Retained as a fallback if threading
            proves structurally impossible (see AB-1).
       (ii) a scene/editor-level sample cache. REJECTED — it puts derived geometry in editor state and
            creates pressure toward a second geometry truth, which the umbrella forbids.
M-1 TRAVERSAL HANDLING (S-2).
     The key MUST include traversal. Whether `reverse` may be served by reversing the `forward` array
     instead of re-deriving is an OPEN EQUIVALENCE QUESTION, answered by OR-2, not assumed. Ship the
     conservative form (key includes traversal) first; adopt reverse-on-read only if OR-2 proves array
     equality AND the slice records the proof.
M-2a EXTENT-DERIVED PAIR PRUNING.
     A Wall pair whose swept extents (AABB of the sampled polyline / chord, per the existing geometry)
     cannot overlap after the edit cannot newly cross. Prune those pairs from the sampled crossing scan
     while KEEPING the same predicate and the same reporting. This is a broad phase, not a new rule:
     the P23.11 precedent already shipped a conservative broad phase for the crossing predicates and
     its equivalence tests are the pattern.
     START WITH THE CHEAPEST FORM: a plain conservative extent scan, no new dependency. P23B.2 §Q2
     (SOURCE-VERIFIED precedents, but its own limitation) says an R-tree's economics are unproven at our
     document sizes, so a spatial-index library is NOT the first mechanism and NOT a rescue for a
     disappointed measurement (AB-10). The index is admitted only if the extent scan is measured
     insufficient on the committed fixtures AND the index is measured to beat it.
     SUBJECT-CONSERVATIVE (Option E revision). Pruning is defined against the validator that SHIPS.
     P23B.3a shipped FIRST (D-11 = ARRANGEMENT 1), so the validator this slice is stated against IS the
     post-policy, group-scoped one: an independent-group overlap is PERMITTED and must NOT be reported as
     a failure, while a genuine failure WITHIN one connected component must still be. Stating M-2a's
     oracle against the pre-policy document-global model would now fail against correct code, and
     dropping the within-component failure would be worse — so the oracle is stated against the SHIPPED
     post-policy validator, and pruning must never widen its subject or its verdict (OR-3, OR-9).
M-2b VERDICT REUSE ACROSS THE PRE/POST PAIR  — CONDITIONAL, BLOCKED, AND NOW GATED ON TWO THINGS.
     Pre and post run the same two functions on different documents (EQ-1/EQ-6); if a pair's inputs did
     not change AND a stable verdict exists to reuse, reuse it (keyed on the pair's inputs). BLOCKED on:
       (i)  the ruling — under "leave as-is / admit-as-invalid" a cached NEGATIVE verdict becomes product
            semantics, not an optimization (synthesis §8.6 AB-3); and
       (ii) the SHIPPED BEHAVIOUR — a ruling does not change the validator (decision record §4.1). Where
            the fix is deferred, the gates still admit what they admit today, so M-2b remains disabled
            regardless of how the policy reads. It is admitted only if its equivalence is proven against
            the CURRENT FULL validator (already-invalid baselines included, OR-10) and the shipped gates
            admit a stable verdict — and it is RE-EVALUATED, never inherited, if a fix later lands.
     AND, UNDER OPTION E, A THIRD DEPENDENCY THE KEY DOES NOT HAVE TODAY (synthesis §6.7): if
     independent-group overlap becomes permitted, the pair's classification becomes policy-dependent,
     so a reused verdict must INVALIDATE when a deliberate JOIN changes the pair's CONNECTIVITY — not
     only when the pair's geometry changes. Any reuse key that cannot express "these two Walls stopped
     being in the same connected group" is not admissible for M-2b under E (AB-3).
     Do not implement before all applicable conditions hold. "The owner ruled reject" is not a green
     light for this half.
```

## 6. Implementation steps (each independently committable and reviewable)

```text
REFERENCE-FIRST RULE (applies to every S-step below; a step that violates it cannot merge)
    No oracle may be merged that requires code which does not exist yet, and no mechanism may be merged
    without its green oracle in the SAME commit. A step that reads "equivalence test first" therefore
    means: FIRST freeze the REFERENCE side — today's behaviour, which is executable against today's code
    by construction — THEN introduce the mechanism together with the assertion that compares it against
    that frozen reference. An OR-1 written literally as "shared derivation vs fresh call" cannot be
    green before the shared derivation exists; that is a sequencing bug, not a standard to relax.
S1  FREEZE THE REFERENCE (tests only, no production change)
    Record the CURRENT per-consumer behaviour on the committed fixtures: the sampled-centerline arrays
    each consumer derives today (per call site, per traversal), captured as committed expectations. This
    is the reference OR-1 and OR-2 later compare against, and it is green the moment it lands because it
    asserts today's code. It commits alone. From here on it fails loudly if any later change moves a
    consumer's samples — exactly the divergence alarm the slice needs. The OR-1/OR-2 COMPARISON against
    this reference is added by whichever step introduces the shared derivation, in that step's OWN
    commit: merging the oracle with the mechanism is the requirement, merging it early is impossible,
    and merging it late is forbidden.
S2  THREAD THE DERIVATION THROUGH ONE CONSUMER — face extraction (the largest, 80 samples/release)
    Introduce the context type and pass it from `finalizeWallGeometryCandidate` (`:1541` region) into
    `extractBoundaryCandidateFaces`. Default behaviour (no context) = today's per-call sampling, so the
    change is inert for every other caller. Tests, IN THIS COMMIT: OR-1 (shared derivation vs S1's
    frozen reference, for this consumer) + OR-2 where the traversal is exercised + the full
    face-extraction and curved-room suites.
S3  EXTEND TO topology-pre and topology-post
    Both gates receive the context. This is where EQ-1 is actually exercised (pre on the candidate,
    post on the reconciled document) — the test must prove the shared derivation is CORRECT for both
    inputs, not merely fast.
S4  EXTEND TO the compile's three sampling call sites (`layout-geometry.ts:933`, `:260`, `:367`)
    `:260` (canonical forward arc length for Opening mirroring) must keep `'forward'`: a change there
    is a behaviour change. Tests: Opening offset/mirroring suites (`layout-openings`, curve read-path).
S5  EXTEND TO the Opening set (`layout-opening-set.ts:84`) and verify with the OPENING-BEARING fixtures
    (`bend-10-wall-openings`, `bend-3-room-openings`) — the all-curved fixtures have 0 Openings and
    cannot exercise this consumer.
S6  REMOVE the now-dead duplicate derivation only when every consumer is covered; measure on the
    committed fixtures; record before/after with provenance. No promise of a proportional saving.
S7  M-2a EXTENT PRUNING for the crossing scan
    Conservative broad phase over Wall pair extents, same predicate, same reporting. Tests: OR-3 (all
    four cases) + the existing sampled-crossing equivalence tests.
S8  (BLOCKED) M-2b VERDICT REUSE — not before the ruling AND not before the shipped behaviour admits a
    stable verdict; if admitted, its own commit with its own differential test against the current FULL
    validator, on a baseline that ALREADY carries an inter-Room crossing (OR-10). If either gate is
    unmet, record the mechanism as dropped rather than postponing it silently.
S9  RECONCILIATION CHANGE CONTRACT (OR-11, finding only)
    Trace each reconciliation outcome's inputs/outputs and record the contract, or record that it
    cannot be completed. No post-validation scoping is proposed either way in this slice; this step
    exists so the answer is a finding rather than an assumption, and so P23B.5/P23B.7 inherit it.
S10 DEPENDENCY-MAP FINDING for incremental compilation (X-5)
    Record which compile outputs are document-global (junction resolution, finite-thickness, aggregate
    bounds) and which are candidates for sub-graph locality. A FINDING, never an implementation.
```

## 8. Regression and resource-lifetime risks

```text
R-1  A shared derivation that returns a MUTABLE array lets one consumer corrupt another. Mitigation:
     hand out frozen/read-only views or document the non-mutation contract and assert it in a test.
R-2  Face extraction currently samples BEFORE the `signedArea < 0` discard (`layout-face-extraction.ts:215`).
     Serving it from a shared derivation must not accidentally change the polygon-construction order or
     the discard decision.
R-3  Traversal misuse (serving a `reverse` request from `forward` data) would silently mirror geometry.
     OR-2 is the guard; without it the key must include traversal.
R-4  Threading a context through `layout-core` signatures is an API change with many call sites. Keep
     the parameter OPTIONAL with today's behaviour as the default so no other caller changes behaviour,
     and so a partially-migrated tree is never wrong — only slower.
R-5  Reconciliation between pre and post (EQ-1): if a shared derivation is keyed on document-scoped
     values it can be wrong for the post pass. Key on centerline identity + endpoints + traversal.
R-6  Resource lifetime (synthesis RL-1/RL-2/RL-3): a derivation that outlives the acceptance chain must
     not retain documents; prefer chain-scoped. Cached key material must respect the ENFORCED
```
