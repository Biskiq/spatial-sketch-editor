## S10 — Dependency-map finding for incremental compilation (X-5; finding, never implementation)

Traced from `compileWallFirstLayoutGeometry` (adapter, `:187`) →
`compileWallFirstWithPhysicalWalls` (wrapper, `:320`) → `compileLayoutGeometrySource`

DOCUMENT-GLOBAL outputs (downstream of ALL walls + the junction graph — a per-Wall
edit can move every one of these):

- `geometry.walls: CompiledPhysicalWall[]` — every document Wall exactly once
  (canonical wall-start frame); vertical extent is wall-local, but the SET is global.
- `geometry.junctions` — canonical incidence + local resolution; the resolution
  cache key covers every resolution-affecting endpoint fact.
- Wall `bounds2/3` expanded by junction miter/bevel (`wallEndExpansion`); per-wall
  query-AABB reconcile against the canonical set.
- `floors[].bounds3`, `floor`/top-level `document` query AABBs, top-level `bounds` —
  rebuilt as aggregates over rooms + physical walls + junctions.
- Room-path strip: rooms keep identity + floor/ceiling + polygons + bounds, with
  `walls: []` / `openings: []` (records live on the canonical path only).
- Issues: core issues + per-wall clearance + junction seam issues.

PER-ROOM / PER-WALL-LOCAL outputs (downstream of one room's boundary walls only):

- `CompiledRoom`: floor/ceiling polygons, room `bounds2/3`, derived ceiling
  (`floor.elevation + max(boundary heights)`).
- `CompiledWall` / `CompiledOpening`: spans, sections, center records, bounds.
- Room-floor polygon + room/floor/object query records.

Consequence for any incremental proposal: per-room floor polygons and room AABBs are
the only locality candidates, and only for rooms whose boundary set AND junction
positions AND ceiling inputs are untouched. Everything else (physical walls set,
junction resolution, all aggregates, all canonical query records) is document-global
by construction. No sub-graph locality is proven here; a future proposal must prove
per-Wall/per-Room granularity against the full validator, not assume it.
