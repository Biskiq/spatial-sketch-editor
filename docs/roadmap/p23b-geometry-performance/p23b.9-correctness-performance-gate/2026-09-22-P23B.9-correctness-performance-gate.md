```text
STATUS:   PLANNED, UNRATIFIED. This is a GATE, not an optimization slice.
ROLE:     prove the whole pipeline is still equivalent after P23B.4–P23B.8, that diagnostics are
          deterministic, and that no performance regression was traded for a silent correctness loss.
          Nothing here changes product behaviour; a failure here BLOCKS the phase.
NOT:      an optimization · a benchmark redesign · a place to re-record a budget to make a red check
          green · a substitute for any slice's own equivalence tests · an audit of unrelated subsystems ·
          a numeric budget ratified by this document
AUTHORITY: umbrella gates → ../2026-09-22-P23B-geometry-performance-stabilization-umbrella.md §Gates
          oracles per mechanism → ../p23b.3-synthesis-optimization-direction/2026-09-22-P23B.3-synthesis.md
```

## 1. What this gate must prove, and why each item exists

```text
G1  WHOLE-PIPELINE EQUIVALENCE. Every optimization in P23B.4–P23B.8 must be shown, on committed
    fixtures, to produce the SAME compiled geometry and the same derived artefacts as the pre-P23B
    pipeline. Exists because a cache/reuse/early-out is only legitimate if it is equivalent to the
    recomputation it replaces (umbrella invariant: equivalence over approximation).
G2  DETERMINISTIC DIAGNOSTICS. Same input ⇒ same issue codes, same messages, same crossing Wall id
    pairs, same ORDER. Exists because scoping and pruning change WHICH pairs are evaluated; a verdict
    must not depend on evaluation order. Also covers duplicate/self-intersection/zero-length/topology
    rejection codes.
G3  CROSS-ROOM CASES. The inter-Room crossing class must be exercised explicitly — it is the class
    Room-local reasoning misses (F-C3) and the class scoping is most likely to get wrong.
G4  CANDIDATE REJECTION / RESTORATION. A refused release leaves document, identity, history and preview
    state unchanged and restores the exact baseline. Exists because scoped validation and reuse both
    touch the refusal path.
G5  UNDO / REDO. History restores PREVIOUS document objects and relies on identity keyed reuse (RL-2);
    the gate must prove no stale artefact is served across undo/redo and that the restored state is
    byte-equal to the original.
G6  PLAN / 3D / VISITOR PARITY. All three surfaces consume the same compiled result; a speedup that
    changes one surface's answer fails HERE (umbrella invariant: parity is correctness).
G7  TYPECHECK / BUILD. `npm run check` + root build across both apps.
G8  APPLICABLE TEST SUITES. The repository-level verification contract, not a narrowed subset.
G9  VISITOR BUNDLE GATE. `/museum` stays editor-free through whatever shipped.
G10 PERFORMANCE COMPARISON WITH PROVENANCE. Baseline vs candidate on the SAME committed fixtures, same
    environment, with the provenance block; ADVISORY unless the owner enforced a threshold.
G11 ENFORCED DETERMINISTIC METRICS. The existing ENFORCED set is unchanged and still passes.
G12 SLICE ORACLES STILL EXIST AND PASS. The equivalence tests each slice shipped must still be present
    and green — a mechanism must not be able to outlive the test that guarded it (a deleted oracle is a
    gate failure).
```

```text

  E3 (or E3C)  40 curved Walls (10 Rooms), valid                     — the scale/curvature case

  controls     straight + target-only-curved at both sizes            — isolates curvature from size
  E4           committed straight controls (`P2311_FIXTURES`)
REGRESSION TESTS
  RT-1 R-a…R-d from the harvest (curved-copy reproduction · duplicate atomicity · unrelated edit
  against a pre-existing crossing · import verdict) — their EXPECTED verdicts depend on the
  curved-crossing ruling; the gate records the ruling's outcome with the result.
BASELINES
  the P23B.0-durable recorded baselines (pre-optimization) — the comparison target for G10.
METHOD LIMITS THIS GATE MUST RESPECT (harvest §12.2)
  · marks are NESTED and OVERLAPPING — never summed;
  · the historical two-pass ratio is NOT a scaling law and must not appear in the gate record;
  · E2 numbers are never used as a performance baseline;
  · browser long tasks (64–314 ms) are NOT attributable to geometry;
  · every number is a measurement of a document in an environment, not a pipeline property.
```

## 3. The gate, check by check

| # | Check | How it is evidenced | Blocking? |
|---|---|---|---|
| G1 | whole-pipeline equivalence | a differential test comparing the current pipeline against a **recompute reference** (the equivalence pattern of `apps/editor/tests/lib/bench/bend-perf.test.ts`), on E1/E3/controls: compiled geometry, Plan render model, meshes (room+wall maps), issues, bounds | YES |
| G2 | deterministic diagnostics | same-input repetition (≥2 runs, plus a deliberately shuffled input order where the API allows) asserting identical codes, messages and crossing id pairs | YES |
| G3 | cross-Room cases | explicit fixtures/tests for (a) an edit producing an inter-Room crossing, (b) a document imported while already carrying one, (c) a Room duplicate that would create one | YES |
| G4 | candidate rejection / restoration | refusal leaves document/identity/history/preview unchanged; baseline restored exactly (RT-1 R-b) | YES |
| G5 | undo / redo | undo to N−2 → redo to N yields byte-equal document and identical compiled geometry; no stale reused artefact served | YES |
| G6 | Plan/3D/visitor parity | the existing parity suites + `layout-mesh-parity` + a cross-surface assertion on the compiled result | YES |
| G7 | typecheck / build | `npm run check` (svelte-check) + root `npm run build` (both apps) | YES |
| G8 | applicable suites | full suite / lane union: `npm test` · `npm run test:arch` (always, never path-gated) · `npm run test:heavy` · `npm run test:perf` | YES |
| G9 | visitor bundle gate | the existing visitor bundle check (server/client entry counts) + `visitor-import-boundary` | YES |
| G10 | performance comparison | pre/post on identical fixtures, same environment: advisory p50/p95 + provenance block; every claim names the cost class it moved | NO (advisory) unless the owner enforced a specific metric |
| G11 | enforced deterministic metrics | `compiled-memory` · `cache-key-code-units` · `svg-node-count` · `three-{object,material,draw-call,triangle}-estimate` unchanged (or explained with the owner informed) | YES |
| G12 | slice oracles present | each equivalence test P23B.4–P23B.8 shipped still exists and is green | YES |

```text
RELATIVE ASSERTIONS where a wall-clock floor would be dishonest
  Where a check would otherwise assert an absolute millisecond bound, assert a RELATIVE fact on identical
  input instead (the shipped P23.11 precedent: the broad phase must beat the quadratic enumeration by a
  wide margin). A timing assertion that can pass or fail on machine noise alone is not a gate.
NO NUMERICAL BUDGET IS PROPOSED BY THIS DOCUMENT. Enforcement is an owner ratification; this gate
enforces only what already exists plus the deterministic/relative assertions above.
```

## 4. Correctness invariants the gate asserts in aggregate

```text
INV-1  One `LayoutDocument` authority; one canonical compiler; one compiled-geometry truth.
INV-2  Plan/3D/visitor parity on the acceptance fixtures.
INV-3  Visitor/editor isolation intact.
INV-4  `LayoutDocument`/`SceneDocument` ownership unchanged; room-local transforms unchanged.
INV-5  Deterministic selection and history.
INV-6  Svelte 5 runes + existing Threlte ownership unchanged.
INV-7  No new capability, view, schema, persisted format or second geometry pipeline.
INV-8  Sampling options unchanged (P23B.3 S-1): `sampleSegment`'s defaults are untouched, so compiled
       geometry cannot have silently changed quality.
INV-9  Reuse is provably equivalent: every reuse path has an OR-5-style guard that can refuse.
```

## 5. Steps

```text
S1  ASSEMBLE THE GATE (no production change)
    Freeze the fixture ids, the commands, the environment and the provenance block into one gate record
    artifact in this slice workspace.
S2  RUN G1–G12 and RECORD RAW OUTPUT
    Raw command output attached or summarized with the exact commands. Failures are recorded, not
    smoothed.
S3  REPORT THE PERFORMANCE COMPARISON (G10) AS ADVISORY
    Pre/post per stage per fixture, nesting stated, environment named.
S4  ON ANY FAILURE: route it, do not weaken the check
    A failure returns to the slice that owns the mechanism, with the failing oracle named. Forbidden
    remedies: re-recording a baseline, widening a budget, deleting an oracle, relaxing an equivalence
    test to near-equality, or declaring the check advisory after it failed.
S5  OWNER-REPORT + RATIFICATION REQUEST
    Report the gate result, the outstanding advisory numbers, and any decision the gate surfaces (e.g.
    whether an advisory metric should become ENFORCED).
```

## 6. Acceptance criteria

```text
A1  G1–G9, G11, G12 pass with raw evidence recorded; G10 is reported as advisory with provenance.
A2  Every failure that occurred is recorded with its resolution — including mechanisms abandoned under
    synthesis §8.6 (an abandoned mechanism is a legitimate result, not a gate failure, provided it did
    not ship).
A3  No baseline was re-recorded, no budget widened, no oracle deleted or relaxed to make a check pass.
A4  The gate record states its own limits: fixture coverage, environment, what the equivalence tests do
    NOT prove (fixtures + exercised option range, not semantic identity over all inputs).
A5  The visitor bundle gate result is recorded with the counts.
A6  The gate makes the phase CLOSABLE; it does not close it (closure is owner-invoked at P23B.10).
```

## 7. Risks

```text
R-1  ORACLE EROSION. The most likely real failure: a mechanism ships in P23B.4–P23B.8, then its
     equivalence test is quietly relaxed later. G12 exists for this.
R-2  FIXTURE-TAUTOLOGY. A differential test that compares a mechanism to ITSELF proves nothing. The
     recompute reference must be a genuinely independent path (the pre-P23B behaviour, retained as the
     control), not the optimized path called twice.
R-3  MACHINE NOISE. Advisory numbers on a developer machine must never gate.
R-4  BUDGET PRESSURE. A red deterministic metric creates pressure to re-record the baseline. A4/INV
     discipline forbids it; the correct response is to understand the movement.
R-5  MISATTRIBUTION. Browser long tasks and reactive/Svelte cost are not geometry cost; the gate record
     must not fold them in (harvest §12.2 point 5, PM-1 §9.3).
R-6  RULING DEPENDENCE. RT-1 R-a/R-c/R-d expectations depend on the curved-crossing ruling; if the ruling
     is still open at gate time, the gate records that dependency rather than asserting a verdict.
R-7  SCOPE DRIFT. The gate verifies P23B's changes; it must not become a general product audit (that is
     a different mechanism the phase must not create).
```

## 8. Exit criteria

```text
X-1  A1–A6 satisfied.
X-2  The gate record is landed, reviewed and accepted.
X-3  Every mechanism that shipped has a live oracle; every mechanism that failed was abandoned and
     recorded as such.
X-4  The phase is CLOSABLE (the advance to P23B.10 is a closeout, not a new optimization).
```
