## 1. What this gate must prove, and why each item exists

```text
G1  WHOLE-PIPELINE EQUIVALENCE. Every optimization in P23B.4–P23B.8 must be shown, on committed
    fixtures, to produce the SAME compiled geometry and the same derived artefacts as the pre-P23B
    pipeline. Exists because a cache/reuse/early-out is only legitimate if it is equivalent to the
    recomputation it replaces (umbrella invariant: equivalence over approximation).
G2  DETERMINISTIC DIAGNOSTICS — ORDER-PRESERVING, NOT ORDER-INVARIANT. Same ORDERED input ⇒ same issue
    codes, same messages, same crossing Wall id pairs, and the same emitted ORDER. Exists because scoping
    and pruning change WHICH pairs are evaluated, so neither a verdict nor a diagnostic may move for a
    given input. NOT REQUIRED, and deliberately not asserted: PERMUTATION INVARIANCE.
    `detectWallCurveTopologyCrossings` is order-dependent BY DESIGN — it walks `document.walls` in order,
    tests self-intersection first, then returns the FIRST crossing pair it finds — so shuffling the Wall
    array is expected to change which crossing is reported first. Demanding identical first-crossing ids
    under a shuffled input would require a behaviour change no evidence justifies, and would turn an
    existing, accepted property into a gate failure. The gate instead RECORDS the order-dependence as
    observed behaviour, naming the traversal, and treats a NEW order-dependence as a finding.
    Also covers duplicate/self-intersection/zero-length/topology rejection codes.
G3  CROSS-ROOM CASES. The inter-Room crossing class must be exercised explicitly — it is the class
    Room-local reasoning misses (F-C3) and the class scoping is most likely to get wrong.
G4  CANDIDATE REJECTION / RESTORATION. A refused release leaves document, identity, history and preview
    state unchanged and restores the exact baseline. Exists because scoped validation and reuse both
    touch the refusal path.
G5  UNDO / REDO. History restores PREVIOUS document objects and relies on identity keyed reuse (RL-2);
    the gate must prove no stale artefact is served across undo/redo and that the restored state is
    byte-equal to the original.
G6  PLAN / 3D / VISITOR PARITY. All three surfaces consume the same compiled result; a speedup that
    changes one surface's answer fails HERE (umbrella invariant: parity is correctness).
G7  TYPECHECK / BUILD. `npm run check` + root build across both apps.
G8  APPLICABLE TEST SUITES. The repository-level verification contract, not a narrowed subset.
G9  VISITOR BUNDLE GATE. `/museum` stays editor-free through whatever shipped.
G10 PERFORMANCE COMPARISON WITH PROVENANCE. Baseline vs candidate on the SAME committed fixtures, same
    environment, with the provenance block; ADVISORY unless the owner enforced a threshold.
G11 ENFORCED DETERMINISTIC METRICS. The existing ENFORCED set is unchanged and still passes.
G12 SLICE ORACLES STILL EXIST AND PASS. The equivalence tests each slice shipped must still be present
    and green — a mechanism must not be able to outlive the test that guarded it (a deleted oracle is a
    gate failure).
```

## 4. Correctness invariants the gate asserts in aggregate

```text
INV-1  One `LayoutDocument` authority; one canonical compiler; one compiled-geometry truth.
INV-2  Plan/3D/visitor parity on the acceptance fixtures.
INV-3  Visitor/editor isolation intact.
INV-4  `LayoutDocument`/`SceneDocument` ownership unchanged; room-local transforms unchanged.
INV-5  Deterministic selection and history.
INV-6  Svelte 5 runes + existing Threlte ownership unchanged.
INV-7  No new capability, view, schema, persisted format or second geometry pipeline.
INV-8  Sampling options unchanged (P23B.3 S-1): `sampleSegment`'s defaults are untouched, so compiled
       geometry cannot have silently changed quality.
INV-9  Reuse is provably equivalent: every reuse path has an OR-5-style guard that can refuse.
INV-10 (NEW) Scoped/pruned validation equals the EXISTING FULL validator on every case, including a
       baseline that already carries a crossing — the oracle is exhaustive validation, never another
       scoped variant (P23B.2 §Q3/§E).
INV-11 (NEW) No mechanism shipped on an external precedent alone. Every shipped mechanism names its
       internal evidence ID and its passing oracle; a precedent we could not establish leaves a
       mechanism `unresolved` rather than shipped (synthesis §4.4 U-1/U-2, §8.6 AB-8).

P23B.2 §E's verification principles were reached independently of ours and agree with §4 above, so the
gate adopts them as its own checklist: differential correctness against the existing full pipeline ·
identical validity decisions with DETERMINISTIC DIAGNOSTIC ORDERING · cross-Room cases (Room-local tests
insufficient) · unchanged document, selection and history after refused operations · separate baseline and
candidate identities · explicit resource lifetime and disposal · reproducible fixture identity and
environment provenance · distinct synchronous/reactive/adapter/GPU/presented-frame measurements.
```

## 5. Steps

```text
S1  ASSEMBLE THE GATE (no production change)
    Freeze the fixture ids, the commands, the environment and the provenance block into one gate record
    artifact in this slice workspace.
S2  RUN THE WHOLE CHECK SET (G1–G20) and RECORD RAW OUTPUT
    Binding: G1–G9, G11–G14, G17–G20. Conditional: G15 (only if P23B.6 shipped M-3m) and G16 (only if
    P23B.8 shipped an asynchronous path) — where the condition did not arise, record NOT APPLICABLE with
    the reason rather than omitting the row. G18 runs against the SHIPPED validator, which under
    D-11 = ARRANGEMENT 1 is already POST-POLICY, so there is NO separate post-policy pass to defer; and
    G20 is BINDING for the same reason, not a conditional check that may be marked not applicable. G10 is
    reported advisory and names WHICH recorded baseline it compares against (synthesis §7.4). Raw command
    output attached or summarized with the exact commands and the environment. Failures are recorded, not
    smoothed.
S3  REPORT THE PERFORMANCE COMPARISON (G10) AS ADVISORY
    Pre/post per stage per fixture, nesting stated, environment named.
S4  ON ANY FAILURE: route it, do not weaken the check
    A failure returns to the slice that owns the mechanism, with the failing oracle named. Forbidden
    remedies: re-recording a baseline, widening a budget, deleting an oracle, relaxing an equivalence
    test to near-equality, or declaring the check advisory after it failed.
S5  OWNER-REPORT + RATIFICATION REQUEST
    Report the gate result, the outstanding advisory numbers, and any decision the gate surfaces (e.g.
    whether an advisory metric should become ENFORCED).
```

## 6. Acceptance criteria

```text
A1  G1–G9, G11, G12, G13, G14, G17 pass with raw evidence recorded; G15/G16 are conditional on P23B.6
    shipping mesh reuse and P23B.8 shipping an async path, and are recorded as N/A with the reason when
    not applicable; G10 is reported as advisory with provenance.
A2  Every failure that occurred is recorded with its resolution — including mechanisms abandoned under
    synthesis §8.6 (an abandoned mechanism is a legitimate result, not a gate failure, provided it did
    not ship).
A3  No baseline was re-recorded, no budget widened, no oracle deleted or relaxed to make a check pass.
A4  The gate record states its own limits: fixture coverage, environment, what the equivalence tests do
    NOT prove (fixtures + exercised option range, not semantic identity over all inputs).
A5  The visitor bundle gate result is recorded with the counts.
A6  The gate makes the phase CLOSABLE; it does not close it (closure is owner-invoked at P23B.10).
```

## 7. Risks

```text
R-1  ORACLE EROSION. The most likely real failure: a mechanism ships in P23B.4–P23B.8, then its
     equivalence test is quietly relaxed later. G12 exists for this.
R-2  FIXTURE-TAUTOLOGY. A differential test that compares a mechanism to ITSELF proves nothing. The
     recompute reference must be a genuinely independent path (the pre-P23B behaviour, retained as the
     control), not the optimized path called twice.
R-3  MACHINE NOISE. Advisory numbers on a developer machine must never gate.
R-4  BUDGET PRESSURE. A red deterministic metric creates pressure to re-record the baseline. A4/INV
     discipline forbids it; the correct response is to understand the movement.
R-5  MISATTRIBUTION. Browser long tasks and reactive/Svelte cost are not geometry cost; the gate record
     must not fold them in (harvest §12.2 point 5, PM-1 §9.3).
R-6  RULING DEPENDENCE. RT-1 R-a/R-c/R-d expectations depend on the curved-crossing ruling AND on the
     behaviour shipped at gate time. If the ruling is still open, or a fix it authorizes has not landed,
     the gate records that dependency and the shipped behaviour rather than asserting the ruled verdict.
     Asserting a verdict only the ruling implies — and the gates do not produce — would make the gate red
     against correct code, and would pressure the next reader to weaken it (R-4).
R-7  SCOPE DRIFT. The gate verifies P23B's changes; it must not become a general product audit (that is
     a different mechanism the phase must not create).
```
