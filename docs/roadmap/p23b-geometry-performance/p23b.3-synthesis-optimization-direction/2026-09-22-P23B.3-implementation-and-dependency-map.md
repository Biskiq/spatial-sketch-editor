## 3. Review checkpoints and commit shape

```text
Every slice:  implement → focused tests → applicable regression suites → measure where relevant →
              commit → report/review → fix and re-review until accepted → slice-closeout on the SAME
              branch → self-check → next slice.
One branch (`p23b`), one PR (#82). No child PRs. Slice boundaries preserved in Git; a merge commit is
preferred over a squash at the end.

REFERENCE-FIRST ORACLE RULE (binds every slice; a commit that violates it is rejected at review)
  Wherever a mechanism's oracle needs that mechanism's own code, it takes TWO commits, not one:
    1. FREEZE THE REFERENCE — commit TODAY'S behaviour as executable expectations. Green on landing,
       because it asserts code that already exists; it fails loudly from then on if a later change
       diverges, which is the alarm that matters.
    2. LAND THE MECHANISM WITH ITS COMPARISON — one commit introduces the mechanism AND the assertion
       comparing it against commit 1's frozen reference.
  An oracle written as "new path ≡ old path" CANNOT be green before the new path exists; demanding that
  is a sequencing bug, not a standard to relax. The converse is equally forbidden: a mechanism whose
  oracle arrives in a later commit. Every mechanism has a green oracle IN ITS OWN COMMIT, and no oracle
  may require code that does not yet exist.
  Applied: P23B.4 S1/S2 (frozen per-consumer samples · shared derivation) · P23B.7 S2/S4 (frozen
  whole-document verdicts · gesture-scoped preflight) · P23B.5 S2/S4 and P23B.6 S2/S3 already had the
  reference step first and needed no correction.

GATE 0 (PATH 1 ONLY)            the owner approves the umbrella scope amendment AND the §SEQUENCE
                                insertion AND the policy slice's plan and acceptance criteria, BEFORE
                                that slice starts. This gate does not exist under PATH 2.
GATE 0b (PATH 1 ONLY, after     owner confirms a POST-POLICY baseline is recorded and that NO CLASS 3
        the policy slice)       fixture was committed as a passing expectation (P23B.0 §2.1).
GATE A (after P23B.0-durable)   owner confirms the fixtures are authoritative and the baselines recorded.
GATE B (after P23B.4)           owner reviews the key grammar + OR-1/OR-2/OR-3 evidence BEFORE P23B.5
                                generalizes the grammar. This is the point where a wrong key would
                                propagate furthest.
GATE C (after P23B.5)           owner reviews the invalidation graph + guard/refusal evidence before
                                P23B.6 reuses it for meshes.
GATE D (after P23B.7)           owner reviews interaction semantics (no gesture/history change) before the
                                P23B.8 decision is taken against the post-P23B.7 code.
GATE E (P23B.9)                 the full gate; a failure returns to the owning slice.
GATE F (P23B.10)                merge + closure decisions (both owner-only).
```

## 6. Critical path and what can run in parallel

```text
CRITICAL PATH (strictly sequential — each removes a confound for the next):
  ruling D-1 (policy) ┐
                      ├─► P23B.0-dur ─► P23B.4 ─► P23B.5 ─► P23B.6 ─► P23B.7 ─► P23B.8 ─► P23B.9 ─► P23B.10
  ruling D-7 (slot)  ┘
                      └─► (what the verdict-bearing fixture PINS; M-2b admissibility)

THE RULING IS TWO DECISIONS, AND THE CHAIN NEEDS THE THIRD THING TOO (decision record §4.1):
  D-1 policy        — planned: consumed by P23B.0-dur (fixture polarity) and P23B.4 (M-2b).
  D-7 delivery slot — UNOWNED. P23B.4 excludes defect fixes, P23B.7 excludes gesture semantics,
      P23B.9 verifies only, P23B.0-dur is measurement infrastructure. If D-7 lands as "an in-phase fix
      slice", the owner amends §SEQUENCE itself (this map does not); if it lands as "outside P23B" or as
      Option D, only RT-1 is in scope.
  THE SHIPPED BEHAVIOUR — what the two consumers are ACTUALLY keyed to. A ruling does not change the
      validator, so under a deferred fix the fixtures pin today's admitted behaviour (labelled as such,
      revisable) and M-2b is judged against the current full validator. Naming D-7 unblocks the DECISION;
      only landed code changes what may be asserted. Anti-pattern to refuse in every shape: an implicit
      fix, or a ruling-shaped assertion, arriving inside whichever slice next touches the crossing scan
      or the preflight.
  THE OPTION E PATH — the one gate that can RESTRUCTURE this chain (decision record §4.1, D-11):
      PATH 1 inserts a topology-policy slice, so P23B.0-dur moves behind it under placement (a) or gains
      a predecessor under (b), and a POST-POLICY pre-optimization baseline becomes a required
      prerequisite before P23B.4 (synthesis §7.4).
      PATH 2 changes NOTHING on this chain: every slice proceeds against today's shipped behaviour and
      the direction is deferred whole (DEF-10).

PARALLEL-SAFE (no shared prerequisite conflicts):
  · P23B.2's review (§9.2) alongside P23B.0-durable — the report is already folded into the synthesis,
    so a later acceptance or partial return sharpens mechanism CHOICE inside an admitted row rather than
    changing what is admitted (§9.2)
  · P23B.6's PLAN-side verification (Plan model / SVG cost) can run once P23B.0-durable lands, without
    waiting for P23B.5, because it changes nothing
  · test/oracle authoring for a later slice (S1/S2-style "tests first" steps) can be authored early, but
    must not be MERGED as if the mechanism existed

SERIALIZED BY DESIGN (do not parallelize):
  the key grammar (P23B.4 → P23B.5 → P23B.6) and the invalidation graph (P23B.5) — a second author
  inventing a key is exactly the failure this map exists to prevent.
```
