## 3. Review checkpoints and commit shape

```text
Every slice:  implement → focused tests → applicable regression suites → measure where relevant →
              commit → report/review → fix and re-review until accepted → slice-closeout on the SAME
              branch → self-check → next slice.
One branch (`p23b`), one PR (#82). No child PRs. Slice boundaries preserved in Git; a merge commit is
preferred over a squash at the end.

REFERENCE-FIRST ORACLE RULE (binds every slice; a commit that violates it is rejected at review)
  Wherever a mechanism's oracle needs that mechanism's own code, it takes TWO commits, not one:
    1. FREEZE THE REFERENCE — commit TODAY'S behaviour as executable expectations. Green on landing,
       because it asserts code that already exists; it fails loudly from then on if a later change
       diverges, which is the alarm that matters.
    2. LAND THE MECHANISM WITH ITS COMPARISON — one commit introduces the mechanism AND the assertion
       comparing it against commit 1's frozen reference.
  An oracle written as "new path ≡ old path" CANNOT be green before the new path exists; demanding that
  is a sequencing bug, not a standard to relax. The converse is equally forbidden: a mechanism whose
  oracle arrives in a later commit. Every mechanism has a green oracle IN ITS OWN COMMIT, and no oracle
  may require code that does not yet exist.
  Applied: P23B.4 S1/S2 (frozen per-consumer samples · shared derivation) · P23B.7 S2/S4 (frozen
  whole-document verdicts · gesture-scoped preflight) · P23B.5 S2/S4 and P23B.6 S2/S3 already had the
  reference step first and needed no correction.

GATE A (after P23B.0-durable)   owner confirms the fixtures are authoritative and the baselines recorded.
GATE B (after P23B.4)           owner reviews the key grammar + OR-1/OR-2/OR-3 evidence BEFORE P23B.5
                                generalizes the grammar. This is the point where a wrong key would
                                propagate furthest.
GATE C (after P23B.5)           owner reviews the invalidation graph + guard/refusal evidence before
                                P23B.6 reuses it for meshes.
GATE D (after P23B.7)           owner reviews interaction semantics (no gesture/history change) before the
                                P23B.8 decision is taken against the post-P23B.7 code.
GATE E (P23B.9)                 the full gate; a failure returns to the owning slice.
GATE F (P23B.10)                merge + closure decisions (both owner-only).
```
