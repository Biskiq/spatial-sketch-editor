### T-1 Repeated curve sampling across topology pre/post, face extraction and compilation

```text
Question  Are the existing consumers' sampling configurations equivalent, and is a shared sampled
          representation therefore justified?
Evidence  P-2 (five consumers, ≈280 operations/release on E3), S-1 (all options equivalent by
          construction — one adapter, no override anywhere), S-2 (traversal is the only divergence and
          reverse is re-derived), EQ-1…EQ-5 (proof obligations).
VERIFIED CURRENT BEHAVIOR
  · one sampler seam, uniform sampling options, no shared representation;
  · the same (document, Wall) centerline is re-derived independently 4x per release on E3;
  · face extraction samples BOTH half-edge directions per curved Wall (80), including the discarded
    negative-area outer ring.
CONCLUSION — the blocker to sharing is NOT sampling configuration (S-1 closed it). It is exactly three
  things, all provable:
    (a) TRAVERSAL — a key must include it, or a reversed read must be proven equal to an independent
        reverse sample (S-2/EQ-2);
    (b) INPUT ENDPOINTS + DOCUMENT — topology-pre runs on the candidate, topology-post on the
        reconciled document, the compile on the reconciled document, face extraction on the candidate
        (CG-1b). Endpoints are read per document, so equality of inputs is an obligation (EQ-1), and a
        key must be built from values the code can actually compare;
    (c) ARRAY EQUALITY on hit vs miss, not geometric near-equality (EQ-3).
CLASSIFICATION  proposed direction — a per-Wall sampled-centerline derivation, keyed on
  (canonical centerline identity, traversal, resolved endpoints), consumed by topology-pre/post, face
  extraction, the Opening set and the compile, is JUSTIFIED and is the single highest-value structural
  change available. It is not justified as a "global sample cache" and must not become a second
  geometry truth (see §6, M-1 row).
DO NOT  propose one cache for all consumers before (a)–(c) are tested; do not sum the 280 operations
  into a predicted saving (M-3); do not touch `sampleSegment`'s default options — changing them
  changes compiled geometry and is a product change, not an optimization.
```

### T-2 Whole-document preflight versus affected-subset validation

```text
Question  Can the whole-document validation that runs per pointer move and twice per release be
          scoped, given a genuinely document-wide invariant — including cross-Room crossings — and
          given that baseline documents may already be invalid?
Evidence  P-5 (whole-document preflight per move), P-6 (pre/post pair per release), P-10 (four divergent
          scopes; the crossing gate is all-pairs by design), F-C3 (the counterexample: a Room duplicate
          that translates a curved Wall into a crossing with a Wall OUTSIDE its own Room), EQ-7.
VERIFIED CURRENT BEHAVIOR
  · the crossing rule is all-pairs and carries no notion of the edited Wall;
  · Room-local reasoning is provably insufficient — F-C3 is a case where locality misses the defect.
CONCLUSION  Locality is the WRONG basis for scoping. Sound scoping must be an EXTENT argument: after an
  edit, which Wall pairs can have changed relationship? A pair whose swept extents cannot overlap
  cannot newly cross, and a pair whose verdict has not changed may reuse its recorded verdict. This
  makes scoping a dependency/verdict-reuse problem (P23B.4), not a "shrink the loop bound" problem.
CLASSIFICATION
  proposed direction — extent/AABB-derived pair pruning plus reuse of UNCHANGED pair verdicts for the
    pre/post pair (P-6), because the post gate differs from the pre gate only by what reconciliation
    changed;
  unresolved — whether "reuse the unchanged remainder's verdict" is admissible depends on the
    curved-crossing ruling (§9.1): an admitted-invalid document (PO-1 option B/D) makes a *cached
    negative verdict* part of the product's semantics rather than a pure optimization. P23B.4 must not
    implement verdict reuse before that ruling.
MUST NOT  present any scoped validation as equivalent until the differential test in §8.4 proves
  full-vs-scoped equality on the E1/E3 fixtures AND on a fixture edited into an inter-Room crossing.
```

```text
  · the compiler's input is a `CompilerSource` derived from the WHOLE document, and its outputs include
```

## 7. The optimization direction

### 7.1 The direction, in one paragraph

The measured hitch is a **synchronous release/acceptance block** whose dominant tagged component is the
canonical compile, and whose most redundant component is that the **same Wall centerline is re-derived
independently by four consumers per release**. The direction is therefore: (1) complete the durable
measurement foundation so any claim is reproducible; then (2) **derive each Wall's samples once per
release behind the existing seam** and let topology, face extraction, the Opening set and the compile
consume one representation, keyed on centerline identity so the same key serves pre/post reuse and
baseline→candidate reuse; then (3) **scope validation by extent rather than locality** and reuse the
unchanged remainder of the pre/post pair; then (4) **reuse unchanged per-Wall/per-Room artifacts across
a candidate** with the identity⇒equality discipline the existing WeakMaps already demonstrate; then
(5) take the missing **presentation measurements** and only then touch rendering; then (6) re-measure
interaction and decide **honestly** whether anything remains that a Worker, or Rust/WASM, would fix.
Every step is equivalence-preserving, and each one's first test is an equivalence test, not a timing
test.

### 7.2 Ordering and what each step must NOT become

```text
step  slice        outcome                                        must not become
----  -----------  ---------------------------------------------  ---------------------------------

                   provenance, recorded baselines                  format; a scaling law
 1    P23B.4       one sampled derivation per Wall per release;    a second geometry truth; a
                   extent-scoped validation + verdict reuse        "shrink the loop" micro-opt
 2    P23B.5       honest, documented cache keys + lifetimes;      a new cache layer duplicating the
                   baseline→candidate identity reuse               existing WeakMaps
 3    P23B.6       CPU-side mesh/adapter reuse at authoring         GPU/paint claims before the PM-1
                   density                                         measurements exist
 4    P23B.7       per-gesture interaction cost (drag, hit, snap,    changing gesture semantics or
                   preview install)                                 selection/history behaviour
 5    P23B.8       a DECISION on Worker / Rust-WASM, with the       a migration; a second implementation
                   measurement behind it                            added "just in case"

                                                                    machine noise

```

```text

  Recorded, compared, reported. Never the sole cause of a red test.

RELATIVE ASSERTIONS (the P23.11 precedent, already shipped)
```

### 8.4 The correctness oracle for each proposed shortcut

```text
A "shortcut" may only ship when its oracle is executable. These are the oracles; naming the test is
each slice's obligation, writing it is part of that slice's commit.

OR-1 (M-1)  EQUIVALENCE: for the committed E1/E3 fixtures, for every curved Wall and BOTH traversals,
            the shared derivation's output must be ARRAY-EQUAL (not near-equal) to a fresh
            `wallCenterlineSamples` call, and the fresh call must remain reachable as the control.
            Two runs of the full pipeline must produce byte-identical compiled geometry
            (`serializeWallFirstLayoutDocument` + the compiled-geometry comparison the existing
            parity tests already use).
OR-2 (M-1)  REVERSE: reverse-traversal output must equal the independent reverse derivation. If and
            only if the reversed forward array is proven equal may reverse-on-read replace it; on
            failure the key must include traversal (S-2).
OR-3 (M-2)  FULL-vs-SCOPED: a differential test runs the full document-wide validation and the scoped
            validation on (a) E1, (b) E3, (c) a document edited into an inter-Room crossing
            (F-C3 shape), (d) a document that ALREADY carries a crossing, and asserts identical
            verdict, identical issue code, identical message pair (crossing Wall ids).
OR-4 (M-2)  ATOMICITY: a refused batch leaves document, Room/Junction identity, history and preview
            state unchanged (RT-1 R-b) — the oracle that scoping did not turn a rejection into a
            partial mutation.
OR-5 (M-3)  IDENTITY⇒EQUALITY: a reused artefact must be proven equal to a from-scratch derive of the
            same document (geometry, model, issues, bounds), and the reuse guard must be proven to
            REFUSE reuse for a document acceptance did not prove. This is the shipped P23.11 pattern
            in `bend-perf.test.ts`; P23B.5 extends it rather than inventing a new one.
OR-6 (M-4)  NON-MUTATION: a measurement run must not change the checked-in baseline (the existing
            `bench:record` CLI is never a default-suite test) and must not perturb compiled output.
OR-7 (all)  PARITY: Plan, 3D and visitor consume the same compiled result; the visitor bundle gate
            stays green. A speedup that changes one surface's answer fails the correctness gate
            (umbrella invariant), not the performance gate.
```

### 8.5 Resource-lifetime risks to carry

```text
RL-1  A per-Wall sampled derivation that outlives a gesture must not retain document objects. The
      existing WeakMap pattern (geometry-keyed) is the model; a strong Map keyed on a Wall object
      leaks documents across history entries.
RL-2  Cache lifetime vs undo/redo: history restores a PREVIOUS document object. Any reuse keyed on
      object identity is safe only if the restored object is the same object (which baseline restore
      relies on today — mesh reuse works precisely because it is). A keyed derivation must be
      re-validated against the undo/redo path in P23B.9's gate.
RL-3  Cached key MATERIAL is bounded by an ENFORCED budget: `cache-key-code-units` (620,268 UTF-16
      code units for Chopin at the recorded baseline; target 700,000 / fail 1,300,000). Storing a
      per-Wall, per-traversal key string at authoring density must be measured against it.
RL-4  Worker ownership (if ever admitted): a Worker must not become a second compiler, and its chunk
      must not pull editor code into visitor bundles.
RL-5  Mesh lifetime: adapter meshes are disposed per change; a reuse path must not skip a dispose and
      must not share a BufferGeometry that one surface mutates.
```

```text
AB-2  M-2  if scoping cannot produce an identical verdict+diagnostic on every OR-3 case, ABANDON

AB-3  M-2  if the §9.1 ruling chooses PO-1 option D (leave as-is, document), verdict reuse across an

AB-4  M-3  if identity reuse cannot be shown to refuse an unproven document (OR-5 second half),

AB-5  M-3  if the per-Wall derivation fails RL-1 (retains documents) or RL-3 (breaks the enforced

AB-6  any    if P23B.0-dur cannot produce a committed, reproducible E3 identity, then the 40-Wall case
```
