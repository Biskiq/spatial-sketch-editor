## 1. What M-4 is, as landed

```text
CORE               The `WallChainPlan` success variant carries
                   `acceptance: WallFirstAcceptanceCompile` =
                   { documentJson: validated.canonicalJson, geometry: compiled.geometry,
                     issues: compiled.issues } — the gate's own result, not a re-derivation and not
                   a new compile. `planWallSegment` inherits it: it delegates to `planWallChain`.
EDITOR             `commitWallChain` / `commitWallSegment` call
                   `deriveInstallBundle(state, plan.document, state.project.name, plan.acceptance)`
                   — the wall-chain analogue of the precise path's `applyWallFirstDocumentPlan`
                   call, the `:1247` contract the plan names.
GUARD UNCHANGED    `reusesAcceptedCompile` still re-proves the RE-PARSED document against
                   `documentJson` (serializeWallFirstLayoutDocument equality) before a byte of the
                   payload is installed. The acceptance is a result, never an authority; a
                   differing document falls back to `preview-compile` exactly as before.
ORDER UNCHANGED    `derivePreviewBundle` still compiles BEFORE provisional identity resolution
                   (R-6). That is what makes the guard able to hit: the accepted document has no
                   identity block, the compile is identity-independent, and the resolved document
                   is installed with the accepted geometry.
REJECTION          A rejected chain returns before any install: zero install compiles, zero
                   `wall-chain-commit-install` boundary, document and history untouched.
NO PROBE CHANGE    The node probe measures the planner, not the install; the browser capture (S7)
                   is where `preview-compile-reused` appears in the containment tree under
                   `wall-chain-commit-install`. Probe re-run at S6 for regression only (§4).
```

## 2. The OR-5 oracle (4 tests, green in the same commit)

```text
EQUALITY       For both planner entry points (a closed boundary chain and a straight segment):
               `acceptance.documentJson` === `serializeWallFirstLayoutDocument(plan.document)`, and
               `acceptance.geometry` / `acceptance.issues` are JSON-equal to a fresh
               `compileWallFirstLayoutGeometry(plan.document)` whose issues are empty.
INSTALL PATH   After `commitWallChain`: `chain-canonical-gates` 1 · `wall-chain-commit-install` 1 ·
               `preview-compile-reused` 1 · `preview-compile` 0; and the installed state (geometry,
               model, issues, bounds) equals a from-scratch `derivePreviewBundle` of the committed
               document. After `commitWallSegment`: the same counts and the same equality.
FALLBACK       With a REAL acceptance payload for a DIFFERENT document (one Wall's thickness
               changed): `preview-compile-reused` 0 · `preview-compile` 1; the fallback geometry is
               JSON-equal to a fresh control derive of that other document and differs from the
               payload's geometry. The accepted document itself still reuses its exact compile
               (`reused` 1 / `compile` 0, bundle geometry === payload geometry).
WHY THE COUNTS ARE LOAD-BEARING
               `preview-compile-reused` is reachable ONLY through the `reuse` argument of
               `resolvePreviewCompile`, and the two commit functions are the only callers in the
               commit path — so `reused 1 / compile 0` is itself the proof that the acceptance
               flowed into the install and was consumed, and `reused 0 / compile 1` is the proof the
               guard refused an unproven document.
```

## 3. The deterministic count row (§7(iv))

```text
per accepted boundary chain commit (marks, one chain):
  before M-4    chain-canonical-gates 1 (the plan's compile) + preview-compile 1 (install)  = 2
  with M-4      chain-canonical-gates 1 (the plan's compile) + preview-compile-reused 1      = 1
  guard refusal = 2 — the fallback row above shows the install paying its OWN compile, so a
                  refused reuse is never cheaper than today.
The commit path cannot be forced to refuse by construction (it installs exactly `plan.document`),
so the refusal row drives `derivePreviewBundle` — the same entry point the commit path calls — with
a real payload for a different document. Deterministic, asserted relative to the mark counts, never
a wall-clock budget.
```
