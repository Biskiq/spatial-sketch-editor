## 1. Problem, and the evidence that motivates it

```text
1.1  THE NAMED CAUSE, IN CODE. For every boundary-role chain the commit block runs, in order:
     `extractBoundaryCandidateFaces(candidate)` → `buildCorrespondenceComponents(...)` (predecessor
     polygons + witnesses from the baseline, faces from the candidate) → `reconcileRooms(...)`. The
     components call's pair loop evaluates, for EVERY face × EVERY predecessor room:
       witness inside face      `pointStrictlyInsidePolygon(face.polygon, witness)`
       positive interior overlap `polygonsShareInteriorArea(polygon, face.polygon)`
     and only THEN consults `unionAuthorized` (the D-12 identity authority, a pure map comparison).
     `polygonsShareInteriorArea` probes vertices and edge interior points through a tolerance ring
     test, runs an O(|a|·|b|) proper-crossing loop, and falls through to ear-clipping interior
     derivation (`polygonInteriorPoint` → `distanceToPolygonRing`) whenever nothing was found —
     which is the common adjacent-Room case. On all-curved-40 that is 100 pair tests over 2,560 face
     vertices at ~92 % of plan time.
     MEASURED SHAPE (§0.8): of those 100 pairs, 90 are CROSS-GROUP — D-12 can never union them, so
     the computed geometry is discarded — and the 10 same-group pairs are each Room against its OWN
     face, whose `inside` is already true while `polygonsShareInteriorArea` still runs (the merge
     gate is `inside || overlap`, `layout-room-reconciliation.ts:350`). Both are exact skips, and
     together they are the main lever (§4 M-1).
1.2  REQUIRED / REDUNDANT / AVOIDABLE (the diagnosis's own split, verbatim intent).
     required   Room correspondence itself — P23B.3a (Option E, D-12) and the P23.8 correspondence
                engine require an exact proof that independent components cannot claim each other's
                rooms (`unionAuthorized`); the verdict must stay EXACT.
     redundant  running the WHOLE-DOCUMENT proof for operations whose affected extent is one new
                Wall and zero changed faces — P23B.7 S3 already derives per-move affected extents,
                but that machinery serves the gesture preflight only.
     avoidable  geometry evaluated for pairs D-12 has ALREADY refused (90 of 100 on the committed
                fixtures), the overlap predicate evaluated when `inside` is already true, no
                broadphase bbox reject, no scoping — the algorithm, not the requirement, is the
                cost. (Cross-commit memoization was also named as avoidable; this slice does NOT

1.3  THE TOOL IS `wall-chain` (boundary role). An early `partition`-role probe did not reproduce:
     the delay belongs to boundary-role commits, i.e. Wall authoring and Room creation. The
     committed fixtures are 10 unconnected single-Room islands each (§0.8), so a fixture-based
     ranking must be read with §0.8(d) attached: the CONNECTED case is added to this plan's case set
     because it is the shape the fixture numbers cannot represent.
1.4  NON-CAUSES CONFIRMED (do not re-litigate): curve-sampling ~40 ms total · finite-thickness ~0 ·
```

## 4. Proposed mechanisms, and the alternatives

```text
M-1  THE EXACT PAIR SHORT-CIRCUITS, IN THE MEASURED ORDER (the main lever; low risk).
     For each (face, predecessor Room) pair, evaluate in this order and stop as soon as the verdict
     is decided:
       (a) GROUP CHECK FIRST. `unionAuthorized` is a pure component-label comparison and does not
           depend on geometry: when the two sides resolve into DIFFERENT groups (or exactly one
           resolves), no union is possible, so the pair is skipped BEFORE any geometric work. This
           is the same decision today's code makes — after computing and discarding the geometry.
           MEASURED EFFECT (§0.8): ~705 of the measured 768 ms overlap-check time on all-curved-40,
           ≈90 %, because the committed fixtures are islands and 90 of 100 pairs cross groups.
       (b) BBOX REJECT BEFORE EITHER PREDICATE. Compute each face's and each predecessor polygon's
           bounding box once per commit, inflate by the predicates' own tolerance
           (`ON_RING_TOLERANCE = 1e-9`, and the nearest-point tests' margin), and skip the pair when
           the inflated boxes are disjoint: both merge conditions (a point strictly inside; positive
           shared interior area) require the boxes to overlap, so a disjoint box rules out `inside`
           AND `overlap` at once. Touching or overlapping boxes still go exact — this can only skip
           a pair it PROVES cannot merge. Precedent and shape: P23B.4's `sampledWallExtentsOverlap`
           + `disableExtentPruneForTest` (verdict-neutral by construction, exhaustive path kept
           executable in tests).
       (c) INSIDE, THEN OVERLAP ONLY IF NEEDED. The merge gate is `inside || overlap`; evaluate
           `pointStrictlyInsidePolygon(face.polygon, witness)` and SKIP `polygonsShareInteriorArea`
           whenever `inside` is true — the pair has already decided, so the overlap result could not
           change it. Exact by the same gate. This removes the remaining same-group cost: each Room
           against its OWN face has `inside` true and is the slowest overlap case (§0.8).
       (d) The overlap predicate itself is UNCHANGED.
     THE ORDER IS PART OF THE MECHANISM: (a) O(1) label comparison → (b) O(1) against precomputed
     boxes → (c) O(|face|) point-in-polygon → (d) the expensive predicate last. Both orders give
     the same verdicts; this one is the cheaper exact order.
     EXPECTED (owner measurement, advisory): all-curved-40 authoring falls from ≈776 ms to a few ms
     of correspondence in node with no verdict change; S1/S7 re-derive the numbers on the fixtures
     AND on the CONNECTED case, which is what decides M-2/M-3.
     NOT TAKEN with M-1: cross-commit memoization of verdicts (a new cache — outside the boundary).
M-2/M-3  ONE CONDITIONAL DECISION (was: M-2 the "large lever", M-3 conditional).
     The affected-extent scope (was M-2) and the room-neutral early-out (was M-3) are the SAME
     question asked twice. A skipped pair still needs a VERDICT, and nothing stores the baseline's
     (a cache is forbidden): the only sound source is the identity statement "an unchanged face
     matches its own Room, and nothing else" — which IS the early-out's condition. Consequences:
       · the extent scope MUST take its skipped-pair verdicts from the early-out condition, so both
         mechanisms carry the same medium-high risk and neither may be rated lower;
       · the extent derivation additionally needs a baseline face extraction the chain path does not
         run today (cost), which is part of what the connected-case evaluation must price;
       · both are taken ONLY if the CONNECTED case (§0.8(d)) shows they matter AND the equality
         proof holds there, and only on an OWNER RULING after S3's connected-case measurement (no
         numeric target exists, so the call is not the implementer's);
       · M-3 alone is a valid close; M-2 NEVER lands without M-3 — its skipped-pair verdicts ARE
         M-3's condition, so M-2-alone is exactly the unsound case §0.8(c) closed. M-2 failing
         alone blocks M-2 only, and X-4 records which;
       · on the committed island fixtures M-1(a–c) already removes the cost, so M-2/M-3 are not
         needed there — exactly why the connected case is added to the probe and OR-1.
     PRESERVED from the original M-2/M-3: the identity-set construction the precision path already
     uses in `finalizeWallGeometryCandidate` (one component per Room,
     `candidateFaceKeys: [canonicalBoundaryCycleKey(candidateRoom.boundary)]`); the OR-4
     component-label equality oracle including the D-12 hazard rows; the whole-document fallback on
```
