## What changes from the umbrella

Manual assignment still precedes recognition. Move packed-channel selection and gloss conversion into that first manual capability. Deferring them would hard-code “one file equals one property” into import, caching and delivery. Give new assets a neutral PBR base so a creator's plaster cannot accidentally inherit walnut roughness or a brass tint. Keep opacity, emission and fixture models out of the first family. A channel called *Shading* cannot stand for ambient occlusion, height and a baked lighting pass. Each requires a different evaluator. Earlier S8 control sketches are design inputs to the single UX phase.

**E1 wire vocabulary.** Add `packages/project-model/src/materials/` and export the runtime-safe `@portfolio/project-model/materials` subpath for editor, API and visitor. The following is the proposed data contract. `Hash` is the existing lowercase `sha256-<64 hex>` value. Each map key fixes the allowed binding type.

```text
Metric = { tileMeters: [width,height], rotation: radians, offset: [u,v] }
Mapping = { kind: "target", metric: Metric }
        | { kind: "surface", metric: Metric }
        | { kind: "uv", set: 0|1, repeat: [u,v], rotation: radians, offset: [u,v] }

Colour<I> = { image: I, mapping?: Mapping }
Normal<I> = { image: I, convention: "+Y"|"-Y", mapping?: Mapping }
Scalar<I> = { image: I, component: "r"|"g"|"b"|"a", invert: boolean, mapping?: Mapping }
Maps<I>   = { color?: Colour<I>, normal?: Normal<I>, roughness?: Scalar<I>,
              metalness?: Scalar<I>, occlusion?: Scalar<I> }

Recipe = { profile: "pbr-metallic-roughness/v1", color: "#rrggbb",
           roughness: number, metalness: number, occlusionStrength: number,
           normalScale: number, mapping: Mapping, maps: Maps<Hash> }
LocalImage = { textureId: SceneTextureId } | { shipped: FrozenTextureURI }
Finish = { id, name, base: { catalogue: MaterialId } | { material: Hash },
           overrides?: { color?: SceneColor, roughness?, metalness?, occlusionStrength?,
                         normalScale?, mapping?: Mapping, maps?: OverrideMaps<LocalImage> } }
```

`OverrideMaps` uses the same role-specific value types as `Maps`, plus JSON `null` for an explicitly disabled binding. Omission inherits the complete binding, including its mapping and convention. Replacing a binding replaces that whole value. Removing its mapping makes it follow the set. Resetting a map override restores its parent binding. Factor overrides use omission for inheritance and accept zero wherever their range includes it. An explicit override equal to the base remains authored, so an inspected value can report its provenance. Empty override containers are omitted. A catalogue instance with no overrides retains the pristine-instance behavior, including the model exception. A resource-backed Finish always has project identity.

**Canonical values and identity.** A normalized recipe carries all six non-map properties shown after the profile (colour, four scalars and mapping), and an empty or populated maps object. New neutral defaults are white, roughness 0.5, metalness 0, occlusion strength 1, normal scale 1 and target mapping with a 1 m square tile, rotation 0 and offset [0,0]. For roughness, metalness and occlusion strength accept [0,1]. Normal scale is (0,10]. A metric tile edge is [0.01,100] m. For UV repeats choose [1/1024,1024] inclusive on both axes. Rotation is [0,2π), offset components [0,1). The operation builder wraps user angles/offsets modulo a full turn/tile, normalizes −0, and rejects invalid non-finite or out-of-range dimensions without clamping. The strict reader rejects out-of-domain encodings, unknown keys, wrong role/selector pairs, invalid colour or unsupported profile. Material v1 admits opaque RGB colour, tangent-space RGB normal and raw scalar components. Coverage, height and emission are outside this profile.

Use UTF-8 of `canonicalUnitJson(normalizedRecipe)`, with sorted keys and no trailing newline, and the repository's `sha256Bytes`. Only these bytes determine the recipe revision. Display names, palette slot IDs, project IDs, transport paths, thumbnail and locator tables live outside it. Preserve authored ordering where it exists in the surrounding envelope. The neutral recipe above must produce `sha256-ce95db1ce6fb2381d7ff4542e05f83b857599e8dc673ca01d082cfc129c973bc`. The same recipe in two projects with different local texture IDs must yield the same digest. A swapped ORM component or normal convention must change it. ## G · Transfer a Finish between projects

**E6b storage and ownership.** A library item is an owner-private immutable `{kind:"material", formatVersion:1, name, recipe}` plus pinned private image dependencies and an optional fixed thumbnail. Keep the item's content ID (hash of its canonical payload, including name) distinct from its portable recipe revision. A project insertion creates an independent Finish and vendors exact source bytes. Deleting the item or source project preserves every destination. A later library revision is a new item in S8. Automatic update propagation would break locked releases.

Extend the existing library listing and kind dispatch, preserving form format 1, its ETag and clients that list forms. Widen the existing `form_library_items.kind` constraint to admit `material`. Add `material_library_images(item_id, hash, mime, byte_size, source)` with primary key `(item_id,hash)` and one discriminated source (owned immutable object key or frozen shipped URI). Put the optional thumbnail key/hash on the material item. Stream private copies through the existing ObjectStore `get` and `put`, verifying the stream before metadata commit. Keep recipe bytes in the existing bounded canonical payload column. Serve byte streams from private storage. Scope object keys by owner/item/attempt and project/asset/attempt respectively. The destination row must never depend on a source project's object key. Preserve the 256 KiB item payload limit, 1,000 item owner limit and per-image P20 limits. A v1 item has at most five distinct image dependencies. [Library codec precedent](../../../../packages/project-model/src/library/form-library.ts) · [API library operations](../../../../apps/api/src/form-library/index.ts) · [Existing storage shape](../../../../apps/api/migrations/001-baseline.sql)

| Operation | Contract |
| --- | --- |
| Save | Snapshot an accepted Finish and revision. Resolve a palette follower to its current literal, flatten overrides without Treatment and report captured followers. POST to the existing library collection with material kind, name, recipe/hash, source project ID and exact local image bindings plus operation ID. For project bytes the API rechecks signed-in ownership and verifies each ready pin/stream. For shipped inputs use the frozen manifest. Keep immutable shipped inputs as digest + allowlisted shipped reference. Stage verified project-image copies in the library namespace, then atomically insert metadata, image rows and receipt. Until metadata commits, listing cannot see the item. Saving to the private library produces zero project history. |
| List/read/thumbnail/remove | Preserve the form-only list response for existing callers. Add explicit kind filter `material` and optional all-kinds for new consumers. A stale item returns 409, and a failed generation leaves the saved item usable with the swatch fallback. Use private/no-store responses and owner checks. An item removed during transfer completes only if its ownership/revision was valid at metadata commit. Otherwise abort. Reclaim abandoned staging after 24 hours on the next scoped library/transfer access, using the model staging precedent. |
