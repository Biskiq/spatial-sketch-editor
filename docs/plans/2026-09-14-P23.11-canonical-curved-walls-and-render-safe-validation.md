# P23.11 — Canonical Curved Walls and Render-Safe Validation

**Parent:** [P23 — Layout Depth umbrella](2026-09-07-P23-layout-depth-minimum-build.md)

**Status:** implementation-ready candidate; verify exact symbols/call sites against current `main` before implementation.

**Scope authority:** [P23 remaining-roadmap reconciliation](2026-09-14-P23-remaining-roadmap-reconciliation.md); P23.11 scope is frozen.

**Issue:** #6 — Bézier Wall can pass commit validation but fail physical Wall mesh generation.

**Repository baseline:** P23.10 is landed and remains the authority for canonical Layout mutation, Room reconciliation, immutable-baseline gesture preview, selection and Layout history.

**Fresh-authority policy:** update the current canonical schema in place. No migration, backward decoding, compatibility shim or old-document support is required before Compatibility Baseline.

## Outcome

Canonical wall-first Layout supports one bounded curved-Wall workflow:

* convert straight Wall ↔ curved Wall;
* add, move and delete interior curve controls;
* move endpoint Junctions using existing canonical Junction editing;
* rigidly move curved Walls without changing shape;
* keep Wall-hosted Openings positioned by physical distance along the curved centerline;
* support simple curved Room boundaries;
* reject curve candidates before commit when the canonical physical-Wall mesh cannot render them.

No legacy Room-owned curve authoring returns.

## 1. Inherited contracts

P23.11 must reuse these landed contracts without introducing alternatives:

* `LayoutWall` / `LayoutDocumentWallFirst` remain canonical architecture state.
* Junction IDs remain the only connectivity truth.
* Rooms remain persistent semantic faces reconciled separately from geometry.
* Openings remain document-global and Wall-hosted.
* `finalizeWallGeometryCandidate` remains the canonical geometry acceptance path.
* `LayoutSelection` remains the single durable selection authority.
* P23.10 immutable-baseline preview/gesture/history lifecycle remains authoritative.
* `layout-geometry-curve.ts` remains the single curve evaluator/sampler.
* `CompiledPhysicalWall.samples` remains the shared compiled centerline consumed by Plan/3D/visitor.
* Layout editing never mutates `SceneDocument`, Camera state or visitor navigation.

## 2. New P23.11 decisions

### Canonical Wall curve data

Extend the current `LayoutWall` authority with one centerline union:

```ts
type LayoutWallCenterline =
  | { kind: 'line' }
  | {
      kind: 'auto-bezier';
      interiorAnchors: LayoutWallCurveAnchor[];
    };
```

Each anchor has a stable ID and X/Z point.

Rules:

* endpoints remain owned only by `startJunctionId` / `endJunctionId`;
* curve anchors are not Junctions;
* anchor order is persisted and deterministic;
* `auto-bezier` requires at least one anchor;
* deleting the last anchor converts the Wall to `line`;
* `DraftSegment` remains internal geometry machinery and is not persisted.

Update the current schema/codec directly. Do not add version/migration machinery.

### One canonical curve adapter

Add one pure Wall-centerline adapter in `layout-core`:

```ts
wallCenterlineSegment(wall, startPoint, endPoint)
```

It maps the canonical Wall representation into the existing curve kernel.

All compiler/topology/Opening code needing Wall centerline geometry must use this seam or its sampled output.

Do not duplicate curve evaluation.

### Opening semantics

Opening meaning stays:

```text
offset = physical metres from canonical Wall start
width  = physical metres along Wall centerline
```

For curves, physical length, placement and reverse traversal use canonical sampled arc length.

A curve edit does not rewrite Opening offset merely to preserve world position.

If the edited curve can no longer host an Opening, reject the whole edit.

### Unsupported operations

Keep these straight-only in P23.11:

* exact Wall length;
* exact Wall angle;
* Wall subdivision / Add Junction.

Curved Wall subdivision is explicitly deferred. Replacing Euclidean distance with arc length does not guarantee a shape-preserving auto-Bézier split.

Unsupported curve crossings requiring noding also reject.

## 3. Core geometry flow

### Compiler

Replace the wall-first compiler's hard-coded line construction with the canonical Wall-centerline adapter:

```text
LayoutWall + endpoint Junctions
→ canonical centerline adapter
→ existing sampleSegment()
→ CompiledPhysicalWall.samples
→ Opening / bounds / physical Wall compilation
→ Plan + editor 3D + museum
```

Straight Walls must preserve existing compiled behavior.

No curve-specific compiler is introduced.

### Rooms and topology

Graph connectivity remains Wall/Junction based.

For geometric face calculations, expand each oriented Wall boundary into its canonical sampled centerline before polygon area/centroid/containment work.

Do not persist those sample points as Room vertices.

Reject:

* curved Wall self-intersection;
* straight/curve crossing away from an explicit shared Junction;
* curve/curve crossing away from an explicit shared Junction;
* overlap/crossing that would require automatic noding.

### Render-safe validation

Issue #6 must move from render-time discovery to canonical acceptance.

Extract the pure finite-thickness self-clearance / offset-overlap predicate currently duplicated in editor/museum Wall mesh builders into `layout-core`.

The same pure rule must be used by:

1. canonical compile/finalization;
2. editor mesh generation as defense-in-depth;
3. museum mesh generation as defense-in-depth.

Do not import renderer/Three/Threlte code into `layout-core`.

An accepted canonical document must not contain a Wall that the normal physical-Wall mesh path immediately rejects.

## 4. Canonical curve operations

Add canonical planners alongside the existing wall-first precision/edit planners:

```ts
planConvertWallToCurve(...)
planConvertWallToLine(...)
planInsertWallCurveAnchor(...)
planMoveWallCurveAnchor(...)
planDeleteWallCurveAnchor(...)
```

Exact names/signatures may follow local conventions.

Every planner must:

* derive a candidate from immutable input;
* mutate only canonical Layout data;
* use deterministic anchor IDs;
* pass through `finalizeWallGeometryCandidate`;
* return one accepted document or stable rejection;
* leave the baseline untouched on rejection.

### Straight → curve

* preserve Wall/Junction/Openings IDs;
* create one deterministic anchor at the Wall midpoint;
* initially remain visually straight;
* commit one Layout history entry.

### Curve → straight

* preserve Wall/Junction/Openings IDs;
* remove curve controls;
* validate the resulting straight Wall and hosted Openings;
* reject atomically if invalid.

### Add / move / delete anchor

* insert at a projected physical position on the sampled Wall;
* move only the selected anchor;
* preserve other anchor IDs/order;
* deleting the final anchor converts to `line`.

Control insertion may change interpolation. P23.11 does not promise shape-preserving insertion.

### Existing operations

Extend only where curve ownership requires it:

* Junction move: endpoint moves, curve anchors remain in place, curve reshapes.
* Rigid Wall move: both endpoint Junctions and all anchors on that Wall receive the same delta.
* Existing rigid Room translation: any moved curved Wall's anchors receive the same translation.
* Exact length/angle: reject curve.
* Subdivision/Add Junction: reject curve.

## 5. Editor interaction contract

Reuse the P23.10 gesture lifecycle exactly.

The selected entity remains:

```ts
{ kind: 'physicalWall'; wallId }
```

A curve control is transient editing state keyed by `{ wallId, anchorId }`; it is not a new `LayoutSelection` variant or hierarchy row.

Add one transient gesture kind for control movement.

Hit priority stays:

```text
Junction / endpoint
> Opening body/handle
> curve control
> Wall body
```

Control drag uses:

```text
pointer-down baseline
→ optional existing snap resolution
→ restore immutable baseline
→ canonical anchor planner
→ valid preview or invalid intent
→ replan actual release point
→ one commit or full cancel
```

Do not commit a remembered last-valid preview.

Escape, pointer cancel, lost capture, tool/mode/view change and project replacement follow the existing P23.10 cancellation path.

No new curve drawing tool is introduced.

## 6. Implementation slices and commit order

Each slice is independently testable and should land as a separate reviewable commit.

If a slice proves too large, split only at a smaller architectural/test boundary. Do not combine several slices into one implementation commit.

### Slice 1 — Canonical curve schema

**Work**

* Add Wall centerline union + stable anchors.
* Update strict wall-first codec in place (add `centerline` to `WALL_KEYS`; parse and require it in `parseWall`).
* Audit every canonical `LayoutWall` construction, spread and clone site. At minimum verify:
  * `layout-wall-chain.ts` — Wall-chain birth;
  * `layout-wall-noding.ts` — Wall-split fragment and retaining fragment;
  * `layout-wall-first-precision.ts` — `cloneDocument` Wall spread;
  * `layout-duplicate.ts` — Room duplication clone;
  * any other constructor/spread found during implementation.
* `cloneDocument` (and any equivalent Wall cloning) must deep-copy `centerline` and its `interiorAnchors` array with `[...anchor.point]` per anchor. Candidate planners must never share anchor arrays or points with the baseline.
* Straight Wall creation/split/duplication paths must emit/preserve the new canonical `centerline` field (emitting `{ kind: 'line' }`).
* Update current fixtures / Save-Load expectations.
* Keep legacy Room-owned curve data unchanged.
* **Fresh-authority rule is frozen:** do NOT bump the wall-first format version, add migration, add old/new decoder branches, or preserve superseded persisted documents. The `centerline` field is required on every persisted Wall; a missing `centerline` is invalid. Keep the existing current format authority and change its required Wall shape in place.

**Tests**

* straight Wall round-trip;
* curved Wall round-trip;
* deterministic anchor order/IDs;
* malformed/non-finite anchor rejection;
* duplicate anchor-ID rejection;
* invalid empty curved representation rejection;
* `cloneDocument` deep-clones centerline anchors (baseline isolation: mutating the clone's anchors must not affect the original);
* all canonical Wall constructors (`layout-wall-chain`, `layout-wall-noding` fragment, `layout-duplicate` clone) produce/preserve canonical centerline data;
* current Save/Load preserves it exactly.

**Commit 1:** schema/codec + clone/constructor audit only.

### Slice 2 — Canonical curve adapter and compiler

**Work**

* Add the one Wall→curve-kernel adapter (`wallCenterlineSegment`).
* Replace hard-coded wall-first line construction at both sites in `layout-geometry.ts` (Room boundary adapter line ~219 and physical-Wall compilation line ~323) with the adapter output.
* Keep the existing sampling/compiled Wall path.
* Fix remaining chord-length assumptions for curved Walls:
  * reverse Opening offset in `layout-geometry.ts` (Room adapter, line ~234: replace `Math.hypot(...)` with sampled arc length);
  * `wallFirstWallSpan` in `layout-opening-set.ts` (the Opening-set gate's Wall length source, line ~76: for curved Walls derive length from the adapter's sampled output instead of the Euclidean chord).
* Do **not** generalize the Wall-split/noding path to arc-length subdivision. Curved subdivision remains unsupported; `planWallSplit` stays straight-only.

**Tests**

* straight compilation unchanged;
* curved Wall emits non-linear samples;
* sampled physical length differs from chord when curved;
* Opening position/tangent follows arc distance;
* reverse traversal mirrors using sampled arc length (not chord);
* Opening-set validation uses arc length for curved Walls (offset + width compared against sampled length);
* no second sampling path appears.

**Commit 2:** compiler/read path only.

### Slice 3 — Curved Room geometry and topology

**Work**

* Expand each oriented curved Wall boundary into its canonical sampled centerline vertices for the face polygon, in traversal order (sampled points between junction endpoints, excluding the start junction which is the previous edge's end). Do not persist those sample points as Room vertices.
* Keep graph connectivity on Junction/Wall IDs.
* Add a curve-level crossing validation seam using existing `sampledPolylineIntersects` from `layout-geometry-curve.ts`. The current chord-level `classifyWallIntersection` (operating on `TopologySegment` straight endpoints) is insufficient for curved Walls — two curved Walls whose chords don't cross may still intersect along their curves. This seam lives in `validateWallFirstTopology` or a narrowly shared helper called by it (the dependency direction is: `layout-wall-first-precision.ts` → `layout-wall-topology.ts` / `layout-geometry-curve.ts`, both in `layout-core`).
* Reject:
  * curved Wall self-intersection (using `sampledPolylineSelfIntersects`);
  * straight/curve crossing away from an explicit shared Junction;
  * curve/curve crossing away from an explicit shared Junction (using `sampledPolylineIntersects` on sampled centerlines, excluding shared-endpoint tolerance);
  * contact at the explicit shared endpoint Junction remains legal;
  * overlap/crossing that would require automatic noding.

**Tests**

* simple curved closed Room extracts one face (polygon includes sampled vertices);
* curved area/centroid uses sampled geometry;
* valid curve edit preserves Room ID;
* reverse boundary orientation works;
* curve self-intersection rejects;
* straight/curve crossing where the chord also crosses (chord-level check catches it);
* straight/curve crossing where the curve bows across the straight Wall but its endpoint chord does not cross → sampled-level check must reject;
* curve/curve crossing rejects (sampled-level check catches it when chords don't cross);
* explicit shared-Junction endpoint contact remains valid;
* straight Room regressions remain green.

**Commit 3:** Room/topology support only.

### Slice 4 — Curve planners and Opening semantics

**Work**

* Add convert/add/move/delete curve planners.
* Route them through `finalizeWallGeometryCandidate`.
* Add deterministic anchor allocation.
* Extend rigid Wall/Room translation for anchors:
  * `planRigidWallMove`: translate every `wall.centerline.interiorAnchors[i].point` by the same delta as its endpoint Junctions (depends on Slice 1 deep cloning).
  * `planWallFirstRoomMove` in `layout-room-move.ts`: the current authority directly builds `candidateDocument`, translating boundary Junctions and objects while leaving Wall records untouched. For P23.11, extend it so Walls in `movedWallIds` deep-copy their centerlines and translate every curved interior anchor by the Room delta. Do not route Room movement through `planRigidWallMove`.
* Keep Junction endpoint reshaping semantics (endpoint moves, curve anchors remain in place, curve reshapes).
* Make the rejection boundary explicit:
  * `planWallSubdivision` (Add Junction) rejects a curved target early for UX consistency.
  * `planWallSplit` itself fail-fast rejects any non-line Wall before constructing Junction/Wall fragments — this pins the primitive as straight-only and prevents another caller from accidentally flattening a curve.
  * Any crossing operation that would require splitting a curved Wall rejects before noding mutation.
  * The existing straight split fragment still constructs a canonical straight `centerline` (`{ kind: 'line' }`).
* Explicitly reject curved exact-length, exact-angle and subdivision operations.
* Finish arc-length Opening validation/editing seams.

**Tests**

* straight↔curve identity preservation;
* deterministic anchor creation/insertion/deletion;
* endpoint move reshapes without moving anchors;
* rigid Wall move translates endpoints + anchors identically (anchors not left behind);
* rigid Room move does not leave curved-Wall anchors behind;
* Opening offset stays stable during valid curve reshape;
* invalid Opening fit rejects atomically;
* length/angle/subdivision reject curves;
* curved Wall subdivision rejects at `planWallSplit` (verify the primitive fail-fast rejects non-line Walls before fragment construction);
* straight split produces a valid straight centerline;
* rejected planners do not mutate baseline.

**Commit 4:** canonical mutation semantics only.

## 7. Cross-slice acceptance

P23.11 closes only when:

1. curve data is owned only by canonical `LayoutWall`;
2. endpoint connectivity still comes only from Junction IDs;
3. straight ↔ curve conversion preserves canonical identity;
4. control add/move/delete is deterministic and undoable;
5. supported curved Rooms preserve Room identity;
6. Openings remain hosted by physical arc distance;
7. unsupported crossings/noding/subdivision reject atomically;
8. Issue #6 class rejects before document/history commit;
9. Plan, editor 3D and museum consume the same compiled samples;
10. straight-Wall P23.10 behavior remains green;
11. current Save/Load preserves exact curve data;
12. no Layout curve operation mutates Scene or Camera state.

## 8. Manual acceptance

* Convert straight Wall to curve and back.
* Drag interior control and Undo/Redo.
* Move endpoint Junction and confirm curve reshapes.
* Rigidly move curved Wall and confirm shape is preserved.
* Move a shared Junction with curved and straight incident Walls.
* Verify Opening follows physical distance along curve.
* Bend curve until Opening no longer fits; commit must reject.
* Create unsupported crossing; commit must reject.
* Trigger Issue #6-style tight bend; Wall must reject before disappearing in 3D.
* Try Add Junction on curved Wall; unavailable or explicit rejection.
* Cancel curve drag through Escape, pointer cancel and view/mode switch.
* Save/reload current project and compare Plan/3D geometry.
* Open museum visitor and verify same accepted curve geometry.

## 9. Explicit non-goals

* legacy Room-owned curve authoring;
* migration/backward compatibility for superseded development schemas;
* direct curved-Wall drawing;
* curved Wall subdivision or automatic curve noding;
* automatic intersection repair;
* tangent-handle/constraint networks;
* NURBS, trim, fillet, offset or other general CAD curve tools;
* curve exact-length/angle solving;
* multi-select curve editing;
* curve controls in hierarchy;
* consumer-local sampling or flattening;
* second compiler, selection, reconciler, snap or history authority;
* Scene/Camera work;
* P23.15 junction-mesh redesign.

## 10. Stop conditions

Stop and report rather than broadening P23.11 if:

* the existing curve kernel cannot represent the canonical Wall curve without duplicating/replacing its evaluator;
* simple curved Room support requires implicit graph nodes or general curve noding;
* curved subdivision appears necessary to complete the slice;
* renderer validity cannot be expressed as one shared pure geometry predicate;
* editor and museum mesh validity rules materially differ and cannot be reconciled without a wider architecture decision;
* curve interaction would require a second selection/history/gesture authority;
* Layout curve editing appears to require Scene or Camera mutation;
* implementation begins adding migration/backward-compatibility machinery.

P23.11 is complete only when canonical curved Walls use one Wall-owned representation, one evaluator/compiler path, one topology/reconciliation authority, one mutation/history path and one renderability rule.
