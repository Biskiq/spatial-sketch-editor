## Why this slice exists

Wall-first authoring can create Walls (P23.9 segment-first), edit them exactly (P23.1 Length/Angle/Thickness, P23.6H Height, role change), split them and duplicate their Rooms — but there is **no canonical Wall deletion**. `layout-core` has `planDeleteWallFirstOpening` and no `planDeleteWall`; the editor has `deleteWallFirstOpening`, `deleteLayoutObject`, legacy-only `deleteLayoutRoom`, and no `deleteWall`; `Delete`/`Backspace` handles only `wallOpening` (`LayoutPlanViewport.svelte`). P23.6a (Room-unit move) avoids broad topology editing, P23.6b is explicitly projection/selection/Inspector reconciliation with no new mutation authority, and P23.7 mentions Room delete/topology edits only as regression coverage without specifying Wall deletion. So the hole is currently owned by no slice.

## Product outcome

Select one canonical Wall (canvas, hierarchy, or Inspector) and delete it: the Wall and its hosted Openings go away atomically, affected Rooms reconcile through the existing P23.8 machinery, and Undo restores everything exactly. `Delete`/`Backspace` and an Inspector/hierarchy Delete action call the **same operation**.

## Approved semantic decisions

Follow the `planWallRoleChange()` architecture — topology-changing Wall operations go through candidate graph → face extraction → Room reconciliation → canonical validation/compiler, never direct `walls` mutation:

```text
Delete selected Wall
→ remove hosted Openings atomically
→ prune Junctions only when truly unreferenced
→ extract candidate faces
→ reconcile affected Rooms (existing P23.8 machinery)
→ remap/clear portal relations per the existing portal contract
→ canonical validation + compile
→ one history transaction
→ clear the deleted Wall selection
```

- Reject ambiguous/unsupported topology rather than guessing (atomic, zero history).
- One operation = one history entry; Undo/Redo restores exact Wall/Junction/Opening/Room IDs (no correspondence rerun on Redo, per the canonical mutation contract).
- **Post-delete selection is fixed, not heuristic:** after a successful Wall deletion, canonical Layout selection becomes `none`. Do not select a "nearest survivor" by geometry, topology, or document order. Undo restores document state through history; this slice does not add selection snapshots or special selection resurrection.
- **Junction cleanup is reference-based only:** prune a Junction only when no surviving Wall references it as either endpoint. Do not merge nearby Junctions, heal coordinates, or perform spatial cleanup.
- Legacy Room-owned behavior unchanged.

### Required topology outcomes

Wall deletion submits a candidate graph and accepts the deterministic P23.8 reconciliation result. It is not intrinsically a "merge Rooms" command. Pin these distinct cases:

```text
shared boundary Wall between two Rooms
→ if deletion produces one valid enclosed face
→ reconcile 2 Rooms → 1 Room through the normal 2→1 path

outer boundary Wall of an enclosed Room
→ enclosure opens
→ affected Room retires through normal reconciliation

roomless / partition Wall
→ Wall disappears
→ hosted Openings disappear
→ only truly unreferenced endpoint Junctions are pruned
→ existing Room topology / identities remain unchanged
```

Any candidate that falls into unsupported or ambiguous correspondence/topology rejects atomically rather than guessing or repairing.

## Explicit non-goals

Multi-select delete, cascade dialogs, Room deletion redesign, bulk topology cleanup, smart healing, nearest-survivor selection, selection-history persistence, or any second mutation/history authority.

## Acceptance (minimum)

- delete a shared boundary Wall between two Rooms and, when one valid face remains, reconcile deterministically through the normal 2→1 Room path;
- delete an outer boundary Wall that opens an enclosure → affected Room retires deterministically;
- delete an isolated/roomless or partition Wall → clean removal with existing Room topology/identities unchanged;
- hosted Openings on the deleted Wall are removed atomically in every successful case;
- orphan Junctions are pruned only when no surviving Wall references them;
- ambiguous/unsupported topology rejects atomically with zero history;
- one delete = one history entry; Undo/Redo restores exact IDs;
- successful delete clears canonical Wall selection to `none` (never a dangling `wallId`, never an inferred nearest survivor);
- `Delete`/`Backspace` and Inspector/hierarchy Delete share the one planner;
- legacy compile output byte-identical.

## Test plan

New suite (e.g. `p23-6c-wall-delete.test.ts`) for the planner contract above plus editor history/selection integration: shared-boundary 2→1 reconciliation, outer-boundary Room retirement, roomless/partition removal, hosted-Opening cascade, reference-only orphan-Junction pruning, atomic rejection, one history entry, exact Undo/Redo, and post-delete selection cleared to `none`. Existing topology/history suites stay green.

## Implementation record (2026-09-13)

Implemented on branch `p23.6c` (baseline `28de1e6`, the merged P23.6b).

- **Planner** (`packages/layout-core/src/layout-wall-topology-ops.ts`): new
  `planDeleteWall(document, wallId)` over the exact ratified pipeline —
  candidate graph (Wall removed; hosted Openings removed atomically as the
  Wall's single-host records; endpoint Junctions pruned **reference-only**
  when no surviving Wall references them — no coordinate healing, no
  merging) → face extraction → P23.8 correspondence reconciliation
  (predecessor polygons/witnesses from the BASELINE rooms via the shared
  `roomBoundaryPolygon`/`interiorWitness`/`buildCorrespondenceComponents`
  helpers; `reconcileRooms` owns 2→1 merge, retirement, and portal
  remap/clear through the existing contract) → canonical validation +
  compile through the shared `validateAndCompile` gate. The candidate's
  `rooms`/`objects`/`openings` are installed from the reconciliation result
  exactly as `planWallRoleChange` does; a roomless/partition delete runs no
  reconciliation and leaves Room topology untouched. Reuses the existing
  `WallFirstOpPlan`/`WallFirstOpRejection` result shape (`unknown_wall` and
  `room_reconciliation_rejected` carry the existing codes; the final gates
  surface `invalid_candidate_document`/`candidate_does_not_compile`). The
  planner is pure — the baseline document is never mutated.
- **Operation vocabulary** (`packages/layout-core/src/layout-wall-first-precision.ts`):
  `PrecisionOperation` gains `'wall-delete'` (alongside `'wall-role'`), so
  the delete rides the editor's existing operation-typed document-install
  path with no second channel.
- **Editor adapter** (`apps/editor/src/lib/editor/layout/layout-preview-state.svelte.ts`):
  new `deleteWallFirstWall(state, wallId)` — planner → reject (installs
  nothing, sets `lastMutationMessage`) → `applyWallFirstDocumentPlan`
  (`'wall-delete'`, one atomic preview/geometry rebuild). History is owned
  by the callers' guarded runner (`layoutMutationRunnerFor`), same as every
  other wall-first mutation; one delete = exactly one history entry.
- **One operation, four surfaces:**
  - `LayoutPlanViewport.svelte`: `Delete`/`Backspace` now handles the
    canonical `physicalWall` selection slot (after the `wallOpening` case)
    through the new optional `onWallDelete` prop.
  - `EditorViewport.svelte` / `app/PlanWorkspace.svelte`: both mount sites
    wire `onWallDelete` to a `deleteWall(wallId)` handler that runs the
    shared adapter through the guarded runner and applies the **fixed
    post-delete policy** — canonical Layout selection becomes `none` (never
    a nearest-survivor, never a dangling `wallId`).
  - `EditorInspector.svelte`: the canonical Wall panel gains a `Delete wall`
    danger action (`deleteSelectedWallFirstWall`) calling the **same**
    adapter through the same runner, clearing the selection to `none` on
    success.
  - `UnifiedProjectTree.svelte` + `context-menu/plan-menu-items.ts`:
    `PlanLayoutTarget` gains `{ kind: 'wall', wallId }` and
    `PlanLayoutMenuActions` an optional `deleteWall` (omit-don't-dummy
    policy, mirroring `renameRoom`/`deleteRoom`); Architecture wall rows bind
    a context menu exposing exactly the canonical `Delete wall` action.
- **Tests** (`apps/editor/tests/lib/layout/p23-6c-wall-delete.test.ts`, 22):
  planner contract (fixture-validated 2→1 shared-boundary merge with
  survivor boundary/junction pins, outer-boundary retirement, roomless

  document, planner independence from `planWallRoleChange`) + editor history
